The Kerberos authentication process uses various keys to encrypt and decrypt to ensure that no one can alter the transmitted data. The key is the password generated by a cryptographic algorithm. A key can be understood as an encrypted string of strings, and when the verifier finds that the key provided by the user is consistent with the key stored by itself, we can consider the verification to pass. 
User keys are encrypted strings generated by an encryption algorithm using the password of the client user (User Principal Name). 
Service keys are encrypted strings generated by the password of the Service Principal Names (SPN) through an encryption algorithm.

TGS keys are encrypted strings generated by the password of the Krbtgt through an encryption algorithm.
Session keys are used to verify the communication multiple times in a short period of time.
Session key includes TGS session key that are used by client and KDC and Session Key that are used by client and Server.
The members of Kerberos authentication are the Workstation, the Domain Controller, and the Server. The client stores the user key. The DC stores the user key, TGS key, and service key. The server stores the service key. We can use different keys to encrypt and decrypt different communication processes.
Kerberos authentication flow and key details can be referred to the link:
