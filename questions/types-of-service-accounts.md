# Types of Service Accounts in Active Directory

Active Directory provides **four** service-account types, each with a different trade-off between identity scope and automated management:

1. **Standalone Managed Service Account (sMSA)** — a managed domain account for a **single** computer. Windows automatically rotates the password and simplifies SPN management. Cannot be shared across servers or used in failover clusters. Introduced in Windows Server 2008 R2. (`ad-ds-understand-service-accounts.md:28-42`)

2. **Group Managed Service Account (gMSA)** — extends sMSA across **multiple servers** (server farms, load-balanced services). The DC computes the password from the KDS root key (`kdssvc.dll`); member hosts retrieve it over LDAP. Requires 2012+ domain/forest functional level. (`ad-ds-understand-service-accounts.md:49-56`)

3. **Delegated Managed Service Account (dMSA)** — new in Windows Server 2025. A machine account with fully randomized, Credential-Guard-protected keys. Authentication is bound to the device identity, preventing Kerberoasting. Single-server only; cannot migrate from sMSA/gMSA to dMSA. (`ad-ds-delegated-managed-service-accounts-overview.md:17-33`)

4. **Virtual accounts** — managed local accounts (`NT SERVICE\<name>`) with no password management. Access the network as the computer account (`<domain>\<computer>$`). Single-server, no domain identity of their own. (`ad-ds-understand-service-accounts.md:67-75`)

The key dividing line is **password management**: plain user/computer accounts used as service principals require manual password rotation, while all four managed types automate it. For multi-server or load-balanced scenarios, only gMSA works. For highest-security single-server scenarios (Windows Server 2025+), dMSA provides machine-bound credentials that defeat Kerberoasting (inferred from the comparison table at `ad-ds-understand-service-accounts.md:88-96`).
