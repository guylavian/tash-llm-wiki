# What `KC_EVENTS_LOG_VERBOSITY` controls

**`KC_EVENTS_LOG_VERBOSITY` is not a known environment variable in any RHBK 26.x release or Keycloak version covered in this corpus. It is silently ignored if set.**

## Why it doesn't exist

RHBK's Quarkus-based configuration framework (`rhbk-26-4-configuration.md:160-189`) maps `KC_*` env vars to known CLI options. There is no option named `--events-log-verbosity` in the shipped config reference, so no `KC_EVENTS_LOG_VERBOSITY` is recognized.

## The real ways to control events logging

### 1. Category-level log level (what you likely wanted)

Per `rhbk-26-4-logging.md:88-105`, category-specific log levels are set as individual `log-level-<category>` options. The env var convention is `KC_LOG_LEVEL_<UPPERCASED_CATEGORY_WITH_UNDERSCORES>`:

```bash
KC_LOG_LEVEL_ORG_KEYCLOAK_EVENTS=DEBUG
# or equivalently, lowercase: --log-level-org.keycloak.events=DEBUG
```

This controls the **log output** of the `org.keycloak.events` logger category to the configured log handler (console/file/syslog).

### 2. Events storage/export (SPI-level)

Events are stored, listed, and exported via RHBK's Events SPI configuration, not log level. These are `--spi-events-listener-*` options (e.g., `--spi-events-listener-jboss-logging`) and realm-level settings in the Admin Console under "Events" → "Config" — not env vars with "verbosity" in the name.

### 3. Event metrics (Prometheus)

Aggregated event counters (`keycloak_user_events_total`) are exposed on the `/metrics` endpoint (`reference/keycloak/rhbk-26-4-all-config.md`). These are toggled by `metrics-enabled=true`, not by a verbosity setting.

## Result: silent ignore

`KC_EVENTS_LOG_VERBOSITY` → no matching CLI option → the env var is never read by Keycloak's config layer → completely silent. No deprecation warning, no error.
