# What is EtherChannel and how does load balancing work?

**EtherChannel (Gigabit EtherChannel on IOS XE) aggregates several physical Ethernet links into one logical port-channel to provide more aggregate bandwidth and link redundancy.** Traffic is spread across member links by a hash, not round-robin.

## Flow-based load balancing

A hash of packet-header keys maps each flow to one of **16 buckets** per port-channel, and each bucket is bound to one active member link. Multiple flows can map to the same bucket/member link (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:60-64`).

**Default hash:** Layer 3 src/dst IP. With IOS XE 16.4.1+, the **5-tuple hash** (`port-channel load-balance-hash-algo src-dst-mixed-ip-port`) adds source port, destination port, and L4 protocol (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:500-509`).

**Configuration hierarchy:** `load-balancing flow` (or `vlan`) on the port-channel interface overrides the global `port-channel load-balancing vlan-manual`. The global default is **flow-based** (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:88-93`).

**Up to 64 GEC interfaces, 14 members each** (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:34-35`).

### Gotchas

- Changing the load-balancing method — or losing the port-channel or its last member — **deletes the bucket→member mappings** (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:76-78`).
- When a member link fails, its buckets are redistributed **round-robin** to survivors (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:68-71`).
- MPLS traffic balances on src/dst IP only — 5-tuple is unsupported for MPLS (`cisco-lanswitch-flow-based-per-port-channel-load-balancing.md:39-40`).
- **Mixed-speed links are not supported:** bundling a 1G and 10G link in the same port-channel causes out-of-order packets and throughput degradation (`_sources/cisco-ios-xe/lan-switching.md:22`, supported by `_sources/cisco-ios-xe/lan-switching.md` implicit constraint) *(inferred)*.

## LACP 1:1 redundancy

A two-port LACP channel with `lacp max-bundle 1` + `lacp fast-switchover` keeps one link active and one hot-standby. Fast switchover protects upper layers from a single-link failure (`cisco-lanswitch-etherchannel-flow-based-limited-1-1-redundancy.md:22-25`).

- The link with **higher port priority (lower numeric value)** is active; equal priorities mean **no revert** on recovery (`cisco-lanswitch-etherchannel-flow-based-limited-1-1-redundancy.md:78-85`).
- Must be enabled **on both ends** or fast switchover fails (`cisco-lanswitch-etherchannel-flow-based-limited-1-1-redundancy.md:86-88`).
