# What does `KC_CACHE_STACK_MODE` configure?

**This environment variable does not exist in Red Hat build of Keycloak or upstream Keycloak.**

## The real cache-configuration options

### `KC_CACHE` (`--cache`)
The **existing** environment variable controls the cache mechanism:

| Env | CLI | Values | Default |
|---|---|---|---|
| `KC_CACHE` | `--cache` | `ispn`, `local` | `ispn` (production), `local` (development) |

`ispn` enables embedded Infinispan clustering for high-availability; `local` disables clustering (`rhbk-26-4-all-config.md:13`).

### `--cache-stack` (CLI only — no env var)
The **cache transport stack** is a separate, CLI-only option (`rhbk-26-4-caching.md:199`):

- `--cache-stack=<stack>` selects the JGroups transport stack for Infinispan node discovery.
- Default since RHBK 26.x: **`jdbc-ping`** (TCP transport, database-based node discovery).
- Deprecated values: `kubernetes`, `ec2`, `azure`, `google`, `udp` (`rhbk-26-4-caching.md:191-197`).
- Upgrading from RH-SSO/RHBK 25 with `cache-stack=kubernetes` produces a deprecation warning advising `jdbc-ping` instead (`_gated-kb-index.md:3930-3932`).

There is **no `KC_CACHE_STACK` or `KC_CACHE_STACK_MODE` environment variable** — the cache-stack is only configurable via `--cache-stack` on the `kc.sh start` command line, or through `additionalOptions` on the [[keycloak-cr]].
