# What does the FAPI 2.0 Security Profile mandate for high-value APIs?

FAPI 2.0 Security Profile (OIDF final) mandates:

- **Grant type:** `response_type=code` only; implicit, hybrid, ROPC rejected
- **PAR (RFC 9126):** mandatory — all auth params pushed to `/par`; front-channel carries only `client_id` + `request_uri`; `request_uri` expires ≤ 600 s
- **PKCE S256:** required; `plain` is forbidden
- **Auth code:** max lifetime 60 s, single-use; replay → `invalid_grant`
- **Client auth:** only mTLS (RFC 8705) or `private_key_jwt`; `client_secret_*` forbidden; signing algorithms `PS256`/`ES256`/`EdDSA` only (no `RS256`/`HS256`)
- **Sender-constrained tokens:** every access token bound via mTLS cert binding or DPoP; plain bearer tokens not acceptable
- **`iss` parameter (RFC 9207)** in auth responses to prevent mix-up
- **Endpoints:** derived from discovery document only; no hardcoded URLs
- **TLS 1.2+** (BCP 195); `http://` redirect URIs forbidden except loopback
- **Resource server:** verify `cnf` binding on every request; tokens in HTTP headers only, never query params

In Keycloak/RHBK these are enforced via built-in client profiles: `fapi-2-security-profile`, `fapi-2-dpop-security-profile`, `fapi-2-message-signing`, `fapi-2-dpop-message-signing`.
