# Users losing their AD federated link (account-merge prompts)

**Symptom.** Users sporadically lose their federated link to Active Directory and are prompted to "merge accounts" during login.

**Cause.** The Identity Provider's **Username Template Importer** mapper keys the federated link on a mutable AD attribute — typically `${ATTRIBUTE.sAMAccountName}`, `${ATTRIBUTE.userPrincipalName}`, or `${ATTRIBUTE.cn}`. When an AD admin changes that attribute (e.g., a rename or UPN change), the incoming identifier no longer matches the stored federated link, so RHBK treats the user as unlinked and shows the merge prompt (`references/rhbk-troubleshooting-kb.md:89-93`).

**Fix.** Reconfigure the Identity Provider mapper's **Template** to an immutable AD attribute — the standard is `objectGUID`:

1. In the Admin Console, navigate to **Identity Providers** → your AD IdP → **Mappers** tab.
2. Edit the **Username Template Importer** mapper.
3. Change the **Template** from `${ATTRIBUTE.sAMAccountName}` (or whichever mutable attribute is set) to `${ATTRIBUTE.objectGUID}`.
4. Save.

**One-time impact:** Existing users will need to relink (one merge prompt per user). Per-user recovery: click **Link** on the merge screen, or an admin can manually relink.

Applies to RHBK 26.x with an Active Directory identity provider / federated links.

## Contradictions / caveats
This is about **brokering** (IdP mapper), not LDAP **user federation**. Distinguish from the LDAP provider's UUID attribute setting, which addresses a different problem (DN-based links breaking on AD object moves). See [[ad-idp-link-loss-objectguid]].
