# Q: What do LDAP mappers do in RHBK federation?

## Answer

LDAP mappers are components attached to an LDAP user federation provider that map directory data onto RHBK's user model (`ldap-mappers.md:22-23`). They bridge the schema gap between LDAP and RHBK.

### Common mapper types (`ldap-mappers.md:26-32`)

| Mapper | What it does |
|---|---|
| **user-attribute-ldap-mapper** | Maps a single LDAP attribute to an RHBK user attribute (e.g. `mail` → `email`) |
| **role-ldap-mapper** | Maps LDAP role entries (typically groups under a DN branch) to realm or client roles |
| **group-ldap-mapper** | Maps LDAP groups to RHBK group hierarchy |
| **full-name-ldap-mapper** | Composes `firstName`/`lastName` from a single LDAP attribute (e.g. `cn`) |
| **hardcoded-ldap-role-mapper** | Grants a fixed realm/client role to every user imported from that provider |
| **MSAD User Account Control Mapper** | Vendor preset for Active Directory: maps `userAccountControl` flags (account disabled, locked, password expiry) |

### How they are configured

Mappers are Keycloak `components` with `providerType=org.keycloak.storage.ldap.mappers.LDAPStorageMapper`, managed via the Admin Console or `kcadm.sh` (`ldap-mappers.md:34-44`). Multiple mappers can attach to the same LDAP provider, and the MSAD preset adds the account-control mapper automatically when the vendor type is set to Active Directory (`ldap-mappers.md:32`).

### Interaction with storage mode

A role/group mapper's behavior depends on the parent provider's [[ldap-storage-mode]]: in import mode the mapper also runs during periodic sync; in read-only/no-import mode it resolves memberships on the fly from LDAP (`ldap-mappers.md:48-49`).
