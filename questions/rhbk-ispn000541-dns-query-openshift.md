# RHBK logs ISPN000541 with `dns_query` failures on OpenShift

**You see `ISPN000541` / `java.lang.IllegalArgumentException: dns_query can not be null or empty` in RHBK pod logs on OpenShift.**

## Answer

This error comes from Infinispan's **Kubernetes cache stack** (`jgroups.dns.query` property), which requires DNS-based cluster discovery. On OpenShift, this property must be present, but it is **absent** when the server is started transiently by `kc.sh bootstrap-admin` — the bootstrap tool starts a full clustered server to create the admin user, but the DNS query property is not populated in that ephemeral context (`kb:7128352`, extracted).

### Fix

Run the bootstrap with the **local** cache stack:

```bash
KC_CACHE=local kc.sh bootstrap-admin
# or
kc.sh bootstrap-admin --cache=local
```

The user is created **before** the server start attempt, so even if the management interface fails to bind, the admin creation succeeds. Confirm with `KC-SERVICES0077: Created temporary admin user with username admin1` in the logs (`kb:7128352`, extracted). Then revert `KC_CACHE=local` and start the clustered runtime normally (`[[bootstrap-admin-dns-query]]`, inferred — disables distributed caching).

### If this happens during normal runtime (not bootstrap)

If the error appears during `kc.sh start` (not bootstrap-admin), the cause is different: DNS_PING is misconfigured for the JGroups/Infinispan stack. Check:
- The `JGROUPS_DNS_QUERY` environment variable in the pod spec `(inferred)`
- The Keycloak CR for the Operator: does it set `JAVA_OPTS_APPEND` with `-Djgroups.dns.query=<query-name>`?
- Whether the pod's DNS resolution works for the Kubernetes headless service used by JGroups

The runtime case is rare — almost all occurrences of this error on OpenShift are the bootstrap-admin scenario (`[[bootstrap-admin-dns-query]]`, extracted from KB patterns).
