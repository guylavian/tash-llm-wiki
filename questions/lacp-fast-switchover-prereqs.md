# What does `lacp fast-switchover` change, and what must be configured first?

**It enables flow-based limited 1:1 redundancy on a two-port LACP EtherChannel: one active link, one hot standby, and a fast switchover (instead of a full LACP reconvergence) when the active link fails — valid only with `lacp max-bundle 1` and only when enabled on both ends.**

## Question

> What does `lacp fast-switchover` actually change about failover behavior on a 1:1
> port-channel, and what must be configured before it?

## Answer

**What it changes:** with 1:1 redundancy configured, "if the active link goes down, the
EtherChannel stays up and the system performs fast switchover to the hot standby link"
(`reference/cisco-ios-xe/cisco-lanswitch-etherchannel-flow-based-limited-1-1-redundancy.md:78-84`).
Whether the channel later *reverts* to the original link depends on port priorities:
"when the failed link becomes operational again, the EtherChannel performs another fast
switchover to revert to the original active link, or to the link with the higher
priority" (same lines, :82-84). The mechanism keeps the standby hot so failover avoids
renegotiating the bundle from scratch (inferred — the note names the behavior "fast
switchover" but does not spell out the internal mechanism) (inferred).

**Prerequisites, in order:**

1. A **two-port LACP** EtherChannel — one active, one standby
   (`…-1-1-redundancy.md:79-81`).
2. **Enabled at both ends**: "the feature must be enabled at both ends of the link"
   (`…-1-1-redundancy.md:85-86`).
3. **`lacp max-bundle 1`** on the port-channel — for a controlled primary + revert
   behavior, "one link must have a higher port priority than the other and the LACP
   max-bundle must be set to 1" (`…-1-1-redundancy.md:94-96`).
4. **Port-priority decision**: unequal priorities → deterministic primary that the
   channel reverts to; "to prevent the switchover to revert, you can assign both links
   the same priority" (`…-1-1-redundancy.md:97-98`).

**Configuration** (equal-priority, non-revertive example, quoted from
`…-1-1-redundancy.md:470-478`):

```
interface port-channel 2
 lacp max-bundle 1
 lacp fast-switchover
interface Tengigabitethernet0/1/0
 channel-group 2 mode active
interface Tengigabitethernet 2/1/0
 channel-group 2 mode active
```

The `lacp fast-switchover` interface command itself: `…-1-1-redundancy.md:181-183`.

**Verify:** `show etherchannel <n> port-channel` — "Displays the port channel
fast-switchover feature capability" (`…-1-1-redundancy.md:447-449`).

## Contradictions / caveats

- The command-reference table's `lacp max-bundle` example shows `14` with a note that
  ASR 1000 minimum is 1 (`…-1-1-redundancy.md:187-197`) — for 1:1 redundancy
  specifically, the value must be 1 (:94-96). Don't copy the table example.
