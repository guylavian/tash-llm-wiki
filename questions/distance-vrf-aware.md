# 'distance vrf-aware' does not exist

**The Cisco IOS-XE codified corpus contains no `distance vrf-aware` router configuration command.** This is a fabricated/invented command.

## What the real `distance` command looks like

Under a routing process (router ospf, router bgp, router rip, etc.), the per-source administrative distance is set with:

```
distance ip-address wildcard-mask [acl]
```

For example: `distance 192.168.1.0 0.0.0.255 10` under `router ospf 1`.

This sets the administrative distance for routes received from the specified source address range, optionally filtered by an access list. See [[cisco-administrative-distance]].

## VRF-aware commands that do exist

Cisco IOS-XE has features named "VRF-aware" for BGP conditional advertisement and BGP translate-update (`cisco-bgp-bgp-vrf-aware-conditional-advertisement`, `cisco-bgp-vrf-aware-bgp-translate-update`), but **none** of these involve a `distance` command or a `vrf-aware` keyword on the `distance` command.

Per-VRF distance is configured by entering the VRF address-family context and applying `distance` there — not with a `vrf-aware` modifier:

```
router bgp 65000
 address-family ipv4 vrf CUSTOMER-A
  distance bgp 20 200 200
```

## Contradictions / caveats

There is zero evidence for `distance vrf-aware` in the offline Cisco IOS-XE corpus (the harvested _sources and reference tier). The command as phrased should never appear in production Cisco IOS-XE configurations.
