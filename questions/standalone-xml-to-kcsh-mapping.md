# Mapping RH-SSO 7.6 standalone.xml to RHBK kc.sh options

**The EAP `standalone.xml` no longer exists. RHBK uses a unified 4-source config model (CLI → env var → config file → KeyStore) where every option is available in all four sources, differing only in key format.**

## Body

### Config model change

RH-SSO 7.6 used hierarchical XML in `standalone.xml`. RHBK replaces it with flat `--key=value` CLI parameters (or `KC_KEY=value` env vars, or `key=value` in `conf/keycloak.conf`, or `kc.key=value` in a KeyStore). Four sources, first wins (`rhbk-26-6-migrating-server.md:43-47`). `kc.sh --help` lists all options by category (`rhbk-26-6-migrating-server.md:55-56`).

### Subsystem-by-subsystem mapping

| standalone.xml | kc.sh option | Notes |
|---|---|---|
| `<datasource><connection-url>jdbc:postgresql://HOST:PORT/DB` | `--db postgres --db-url-host HOST --db-url-port PORT --db-url-database DB --db-schema SCHEMA` | Bundled drivers for supported DBs; Oracle/MSSQL need manual JAR (`rhbk-26-6-migrating-server.md:58`) |
| `<pool><min-pool-size>` / `<max-pool-size>` | `--db-pool-min-size N --db-pool-max-size N` | (`rhbk-26-6-migrating-server.md:73-80`) |
| `<tls><key-store>` | `--https-key-store-file PATH --https-key-store-password PASSWORD` | Or PEM form: `--https-certificate-file` + `--https-certificate-key-file` (`rhbk-26-6-migrating-server.md:170-177`) |
| `<subsystem infinispan>` | `--cache ispn` (or `local`), `--cache-embedded-realms-max-count N`, separate Infinispan XML config file | Default transport: `--jgroups-stack=jdbc-ping` (DB-based, TCP, auto-TLS). All other stacks deprecated from 26.2. Domain-clustered mode unsupported (`rhbk-26-6-migrating-server.md:179-224`) |
| `<spi name="hostname"><property name="frontendUrl">` | `--hostname URL --hostname-admin URL` | **Mandatory** under `kc.sh start`. Can disable strict with `--hostname-strict=false` (`rhbk-26-6-migrating-server.md:226-248`) |
| Reverse proxy headers | `--proxy-headers xforwarded` (or `forwarded`) | (`rhbk-26-6-migrating-server.md:243-248`) |
| `<spi name="truststore">` | `--truststore-paths PATH --tls-hostname-verifier WILDCARD` | Accepts PEM or unencrypted PKCS12; JKS must be converted (`rhbk-26-6-migrating-server.md:250-274`) |
| `<spi name="vault" provider="elytron-cs-keystore">` | `--vault keystore --vault-file PATH --vault-pass PASSWORD` | No realm config changes needed if new keystore has same secrets (`rhbk-26-6-migrating-server.md:276-293`) |
| JVM / `standalone.conf` | `JAVA_OPTS` (full override) or `JAVA_OPTS_APPEND` (append) | Default JVM args in `kc.sh` script itself (`rhbk-26-6-migrating-server.md:294-307`) |
| `<spi name="X"><provider name="Y"><property name="Z">` | `--spi-X-Y-Z VALUE` | Flat key: `spi-<spi-id>-<provider-id>-<property>=<value>` (`rhbk-26-6-migrating-server.md:309-324`) |
| Operating mode: standalone | `./kc.sh start --cache=local` | (`rhbk-26-6-migrating-server.md:179-197`) |
| Operating mode: standalone-ha | `./kc.sh start` (defaults to `--cache=ispn`) | (`rhbk-26-6-migrating-server.md:179-197`) |
| `/auth` context root | `--http-relative-path=/auth` | RHBK default is server root (`rhbk-26-6-migrating-server.md:142-144`) |
| `KeycloakDS` JNDI datasource | Automated — no JNDI needed | Bundled drivers auto-registered (`rhbk-26-6-migrating-server.md:58`) |

### Troubleshooting

- `kc.sh show-config` — shows which source each property came from and its resolved value (`rhbk-26-6-migrating-server.md:329`)
- `kc.sh --verbose start` — prints full error stack trace (`rhbk-26-6-migrating-server.md:330-331`)
