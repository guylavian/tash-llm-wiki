# What does the ms-DS-Allowed-To-Delegate-From attribute control?

**`ms-DS-Allowed-To-Delegate-From` does not exist in the AD schema.** There is no attribute by that name. This appears to be a confusion (or hallucination) conflating two real delegation attributes.

## Two real attributes, neither named "Allowed-To-Delegate-From"

**`ms-DS-Allowed-To-Delegate-To`** (`msDS-AllowedToDelegateTo`) — multi-valued string on the **front-end service account** listing SPNs it may delegate to in classic constrained delegation. Schema definition: "Allowed-To-Delegate-To contains a list of SPNs that are used for Constrained Delegation" (`reference/active-directory/ad-ds-schema-updates.md:36719-36724`). Set by an account holding `SeEnableDelegationPrivilege` (typically Domain Admins).

**`ms-DS-Allowed-To-Act-On-Behalf-Of-Other-Identity`** (`msDS-AllowedToActOnBehalfOfOtherIdentity`) — single-valued security descriptor on the **target/resource object** controlling which accounts may act on behalf of others to services running as this account. This is the Resource-Based Constrained Delegation (RBCD) attribute added in Windows Server 2012. Schema definition: "This attribute is used for access checks to determine if a requester has permission to act on the behalf of other identities to services running as this account" (`reference/active-directory/ad-ds-schema-updates.md:4767-4772`).

Both attributes coexist on dMSA migration (`reference/active-directory/ad-ds-delegated-managed-service-accounts-overview.md:82-83`).

## False premise correction

The question's "ms-DS-Allowed-To-Delegate-From" attribute name mirrors the structure of "Allowed-To-Delegate-To" but with a reversed direction ("From" vs "To"). The real attribute for expressing "who may delegate from/to a resource" is `ms-DS-Allowed-To-Act-On-Behalf-Of-Other-Identity` on the resource object — the direction metaphor is "act on behalf of," not "delegate from."
