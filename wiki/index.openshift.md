## Entities (28)
- [[buildconfig-s2i]] — A BuildConfig is OpenShift's build definition — a strategy (Source/S2I, Docker, or Custom) plus one or more sources (Git, Dockerfile, or Binary) — that produces an image pushed to an ImageStreamTag; Source-to-Image (S2I) is the default strategy, injecting app source into a builder image via assemble/run scripts without a Dockerfile.
- [[cluster-dns]] — In-cluster DNS is served by CoreDNS, deployed and managed as a daemon set by the OpenShift DNS Operator, resolving *.cluster.local Service/Pod names for every pod via the kubelet-configured resolv.conf.
- [[cluster-operators]] — A ClusterOperator is the status object each OpenShift platform component reports through (Available/Progressing/Degraded); the Cluster Version Operator (CVO) reconciles the whole set during install and upgrade, gating each runlevel on every ClusterOperator reaching Available=True, Degraded=False, and the target version — first stop for any platform-level triage (oc get co).
- [[csi-driver]] — A cluster-scoped (non-namespaced) CSIDriver object that declares a Container Storage Interface volume driver's capabilities to Kubernetes — whether attach is required, whether pod info is passed on mount, fsGroup handling, and storage-capacity tracking.
- [[horizontal-pod-autoscaler]] — The HPA controller periodically adjusts a Deployment's or StatefulSet's replica count to match observed CPU/memory/custom metrics against min/max bounds — horizontal (more Pods), not vertical (bigger Pods); the v2 API adds per-direction scaleUp/scaleDown behavior tuning.
- [[image-streams]] — An ImageStream is a virtual view over related container images — it holds no image data itself — that lets builds, Deployments, and DeploymentConfigs reference a stable ImageStreamTag instead of a mutable registry tag, decoupling app manifests from the concrete registry location and enabling automatic rollout on image change.
- [[kubernetes-daemonset]] — A DaemonSet ensures a copy of a Pod runs on every (or a selected subset of) node — the pattern for node-local agents like log collectors, monitoring daemons, and storage/CNI plugins — and is added to and removed from nodes automatically as the cluster changes.
- [[kubernetes-deployment]] — A Deployment declares desired Pod state and drives ReplicaSets to match it — controlled rollout, rollback, and scaling — via RollingUpdate (default) or Recreate strategy; OpenShift's legacy DeploymentConfig predates it and should not be used for new workloads.
- [[kubernetes-ingress]] — The Kubernetes-native object for exposing HTTP(S) routes from outside the cluster to Services, fulfilled by a separate Ingress controller — on OCP, creating an Ingress auto-generates a managed Route.
- [[kubernetes-networkpolicy]] — A namespaced object that selects pods and declares allowed ingress/egress connections by pod, namespace, or IP block; policies are additive-only (default allow-all until a policy selects a pod), require a CNI plugin that implements NetworkPolicy, and OpenShift's OVN-Kubernetes plugin adds default deny-all policies plus a router-allow label in some system namespaces.
- [[kubernetes-pod]] — The smallest deployable Kubernetes unit — one or more co-scheduled containers sharing a network namespace and volumes — managed in practice through workload controllers, with health driven by probes and placement by resource requests/limits.
- [[kubernetes-rbac]] — Role-based access control decides what an identity (user, group, or ServiceAccount) may do — verbs on resources, granted via Roles/ClusterRoles bound to that identity; OpenShift adds a cluster-wide vs project-scoped two-level hierarchy and default cluster roles on top of upstream Kubernetes RBAC.
- [[kubernetes-service]] — A stable virtual endpoint (ClusterIP + DNS name) that load-balances to a changing set of ready pods selected by label, solving pod-IP churn — with ClusterIP/NodePort/LoadBalancer/ExternalName types and an endpoint set gated by pod readiness.
- [[kubernetes-statefulset]] — A StatefulSet manages Pods that need a stable, unique identity — a fixed ordinal, a stable network name, and per-Pod persistent storage that survives rescheduling — unlike a Deployment's interchangeable replicas.
- [[liveness-readiness-startup-probes]] — The three kubelet health checks — liveness restarts a stuck container, readiness gates Service traffic without restarting, startup delays the other two for slow-booting apps — and the tuning fields (initialDelaySeconds, periodSeconds, timeoutSeconds, failureThreshold) that decide how fast each one reacts.
- [[machine-config]] — MachineConfig objects (rendered per MachineConfigPool) describe the desired on-node OS/systemd/file state for RHCOS nodes; the Machine Config Operator (MCO) applies them via the Machine Config Daemon, detects configuration drift, and marks a node/pool Degraded when on-disk state diverges from the rendered config — an OpenShift-only day-2 layer with no upstream Kubernetes equivalent.
- [[network-policy]] — An application-centric object that restricts which pods/namespaces/IP blocks a selected pod may talk to on ingress and/or egress; without one, all pods in a project are reachable from any other pod by default.
- [[openshift-oauth]] — OpenShift's built-in OAuth server issues API access tokens after delegating identity checks to a configured identity provider (htpasswd, LDAP, GitHub, OIDC, etc.); tokens default to a 24-hour lifetime and the server has no direct Kubernetes upstream equivalent — vanilla Kubernetes leaves authentication to external webhook/OIDC/cert plugins.
- [[openshift-route]] — OpenShift's native object for exposing a Service to external HTTP(S) traffic through the cluster's HAProxy-based Ingress router, with edge / passthrough / re-encrypt TLS termination — the OCP counterpart to a Kubernetes Ingress.
- [[operator-lifecycle-manager]] — OLM installs, upgrades, and manages the lifecycle of user-facing Operators via CatalogSource/Subscription/InstallPlan/ClusterServiceVersion/OperatorGroup CRDs; it is distinct from the Cluster Version Operator, which manages OpenShift's own built-in ClusterOperators and has no Subscription object at all.
- [[ovn-kubernetes]] — The default OpenShift CNI network plugin: an overlay pod/service network built on Open Virtual Network (OVN) over Open vSwitch (OVS), programmed via OpenFlow, providing distributed routing, NetworkPolicy enforcement, egress IPs, IPsec, and IPv6/dual-stack.
- [[persistent-volume-claim]] — A namespaced request for storage (size, access mode, volume mode) that the control plane binds to a matching PersistentVolume — either pre-created or dynamically provisioned by a StorageClass — and mounts into a pod's volumes.
- [[pod-security-admission]] — Pod Security Admission is upstream Kubernetes' namespace-labeled admission controller enforcing the privileged/baseline/restricted Pod Security Standards; OpenShift runs it globally (privileged enforced, restricted warn/audit) alongside — not instead of — SCCs, and auto-syncs each namespace's warn/audit labels from its ServiceAccounts' allowed SCCs.
- [[resource-requests-limits]] — Requests are what the scheduler reserves for a container (driving Pending when unsatisfiable); limits cap what the kernel allows it to use — CPU is throttled at the limit, memory over the limit gets the container OOM-killed.
- [[route-tls-termination]] — The three TLS termination modes an OpenShift Route can use to serve HTTPS — edge (router terminates), passthrough (pod terminates), re-encrypt (router terminates then re-establishes TLS to the pod) — plus insecureEdgeTerminationPolicy and HSTS.
- [[security-context-constraints]] — The OpenShift cluster policy that controls what a pod is allowed to do — run as root, use host networking, mount host paths — with the default restricted-v2 SCC running containers as a random non-root UID, the most common reason a community image that works on plain Kubernetes fails on OpenShift.
- [[service-accounts]] — A ServiceAccount is a namespaced, non-human identity Pods use to talk to the API server or external systems; OpenShift auto-derives its username as system:serviceaccount:<project>:<name> and, before 4.16, auto-generated a long-lived token Secret per account that newer clusters no longer create.
- [[storage-class]] — A cluster-scoped object that lets administrators describe a storage tier (provisioner, parameters, reclaim policy, volume binding mode, expansion) that PVCs reference by name to trigger dynamic provisioning.
