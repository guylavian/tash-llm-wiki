# `unsupported.podTemplate`

**A raw Deployment pod-template override on the [[keycloak-cr]], merged into what
the Operator generates — the escape hatch when no first-class CR field exists.
Tech Preview / unsupported.**

```yaml
spec:
  unsupported:
    podTemplate:
      metadata:
        labels:
          my-label: "keycloak"
      spec:
        containers:
          - volumeMounts:
              - name: test-volume
                mountPath: /mnt/test
        volumes:
          - name: test-volume
            secret:
              secretName: keycloak-additional-secret
```

Use it to inject labels, annotations, volumes, and volume mounts. The Operator
merges your fields with its generated values; there is **no guarantee** the
Deployment works as expected.

## Caveats

- It lives under `spec.unsupported` because it is **highly experimental / Tech
  Preview** and not completely tested.
- Granting podTemplate access is effectively namespace-admin trust — it can deploy
  alternative workloads with the Operator's permissions, including Secret access.
- **Breaks `Auto` rolling-update detection**: the feasibility Job may miss
  podTemplate settings (or Secrets/ConfigMaps/Volumes referenced there) and decide
  wrongly. If you use podTemplate, prefer another update strategy
  ([[operator-rolling-updates]]).

## Contradictions / caveats

- Tech Preview status is consistent across 26.0–26.6.
