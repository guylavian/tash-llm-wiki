# EAP → Quarkus configuration model migration

**RHBK replaces RH-SSO 7.6's JBoss EAP runtime with Quarkus, so `standalone.xml`,
`jboss-cli`, and the operating-mode start scripts no longer apply — everything is
now a flat `kc.sh` configuration option.**

## Body
A single unified config model spans four sources, resolved in this precedence
order (first wins):

1. **CLI parameters** — `--db-url-host cliValue`
2. **Environment variables** — `KC_DB_URL_HOST=envVarValue`
3. **Configuration file** — `db-url-host=confFileValue` (`conf/keycloak.conf`)
4. **Java KeyStore file** — `kc.db-url-host=keystoreValue` (for secrets)

Every option exists in all four sources; only the key format differs. `kc.sh
--help` lists all options grouped by category (cache, database, etc.).

The RH-SSO operating modes (standalone, standalone-clustered, domain-clustered)
collapse into one start script `kc.sh`:

| RHBK | RH-SSO 7.6 |
|---|---|
| `./kc.sh start --cache=local` | `./standalone.sh` |
| `./kc.sh start [--cache=ispn]` | `./standalone.sh --server-config=standalone-ha.xml` |

`--cache` defaults are start-mode aware: `local` under `start-dev`, `ispn` under
`start`. **Domain clustered mode is not supported in RHBK.**

### SPI provider config translation
The old XML `<spi>/<provider>/<property>` block becomes a flat key:
`spi-<spi-id>-<provider-id>-<property>=<value>` (e.g.
`--spi-connections-http-client-default-connection-pool-size 10`).

### Troubleshooting
- `kc.sh show-config` — shows which source each property came from and its value.
- `kc.sh --verbose start` — prints the full error stack trace.

## Contradictions / caveats
- The RPM distribution of the server is no longer available; ZIP (or container)
  only.
- Default JVM args are baked into `kc.sh`; override with `JAVA_OPTS` (full
  replace) or `JAVA_OPTS_APPEND` (append). There is no `standalone.conf`.
