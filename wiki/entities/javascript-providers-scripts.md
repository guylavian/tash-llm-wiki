# JavaScript providers (scripts) & the JAR constraint

**RHBK can run JavaScript at runtime for four customization points — Authenticator, JavaScript Policy, OIDC protocol mapper, SAML protocol mapper — but scripts are Technology Preview, disabled by default, and must be deployed as a JAR with a `keycloak-scripts.json` descriptor; you cannot upload a bare `.js` file.**

## Enabling (preview)

Scripts are **not fully supported** and are off by default. Enable at start:

```
kc.sh start --features=preview     # or --features=scripts
```

## What scripts can customize

- **Authenticator** — must provide `authenticate(context)` and/or `action(context)`. Bindings available in the script: `script`, `realm`, `user`, `session`, `authenticationSession`, `httpRequest`, and `LOG`. Use `AuthenticationFlowError = Java.type("org.keycloak.authentication.AuthenticationFlowError")` then `context.failure(...)` / `context.success()`.
- **OIDC protocol mapper** — bindings `user`, `realm`, `token` (ID token, if configured for ID token), `tokenResponse` (access token response, if configured for access token), `userSession`, `keycloakSession`. The script's `exports` value becomes the claim value mapped into the `Token Claim Name`.
- **SAML protocol mapper** — analogous, declared under `saml-mappers`.
- **JavaScript Policy** — for Authorization Services, declared under `policies`.

## The "scripts must be a JAR" constraint

To deploy scripts you build a JAR (a ZIP with `.jar` extension) containing your `.js` files plus a descriptor `META-INF/keycloak-scripts.json`:

```json
{
  "authenticators": [ { "name": "My Authenticator", "fileName": "my-script-authenticator.js", "description": "..." } ],
  "policies":       [ { "name": "My Policy",        "fileName": "my-script-policy.js" } ],
  "mappers":        [ { "name": "My Mapper",        "fileName": "my-script-mapper.js" } ],
  "saml-mappers":   [ { "name": "My Mapper",        "fileName": "my-script-mapper.js" } ]
}
```

Each script needs a matching descriptor entry under the right type array. `fileName` is mandatory and must map to a file in the JAR; `name` (admin-console label, defaults to the file name) and `description` are optional. One JAR may carry many scripts of each type.

Deploy like any other provider: copy the JAR to `providers/` then run `kc.sh build`. See [[spi-provider-model]].

## Contradictions / caveats

- **Technology Preview across RHBK 26.0–26.6** — disabled by default, not fully supported for production. Confirm support status for your exact RHBK release before relying on it.
- This is the only constraint that forbids loose `.js` deployment: even a one-line mapper must ship inside a JAR with `keycloak-scripts.json`. (Earlier WildFly-era RH-SSO allowed uploading scripts via the admin console; that path is gone in RHBK.)
- For non-preview customization of the same four points, write a compiled Java provider against the corresponding SPI instead — see [[spi-provider-model]].
