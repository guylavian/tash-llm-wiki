# External Data Grid (Cross-DC) with the Data Grid Operator

**The multi-cluster building block that holds RHBK session caches in a separate
Red Hat Data Grid cluster per site and replicates them synchronously between
sites using Data Grid Cross-DC. RHBK connects to it as a remote store.**

## What it is
For multi-site/multi-cluster HA, sessions do not live in embedded Infinispan;
they live in an **external Data Grid** cluster deployed by the **Data Grid
Operator** in each site (`Site-A`, `Site-B`). The two clusters form a Cross-DC
("cross-site") connection so cached data survives a whole-site failure.

- **Minimum supported version: Data Grid 8.5.2** (or newer patch) for external
  deployments.
- Cross-site transport uses **JGroups over TLS**; 26.4/26.6 connect the two sites
  via Data Grid's **Gossip Router**.

## Deployment essentials (blueprint)
1. Install the Data Grid Operator in **both** clusters.
2. **Credentials** — an `identities.yaml` (username/password with `admin` role)
   stored in a `connect-secret`; RHBK authenticates to Data Grid with these.
3. **Cross-site service account** — create `xsite-sa`, grant it `view`, mint a
   `service-account-token` secret in each cluster, then exchange the tokens
   (`Site-A` token → `Site-B` as `xsite-token-secret`, and vice versa). The
   operator uses it to inspect the remote site's network config.
4. **TLS** — upload a keystore (`xsite-keystore-secret`) and truststore for the
   JGroups TLS sockets; Data Grid uses an OpenShift Route with TLS SNI to route
   cross-site traffic.

## How RHBK connects to it
On the `Keycloak` CR, the remote store is configured via `additionalOptions`:
```yaml
- name: cache-remote-host         # e.g. "infinispan.keycloak.svc"
- name: cache-remote-port         # "11222"
- name: cache-remote-username     # from remote-store-secret
- name: cache-remote-password     # from remote-store-secret
- name: spi-connections-infinispan-quarkus-site-name  # e.g. "keycloak"
```
The `multi-site` feature must also be enabled ([[multi-site-feature-flag]]).

## Operating it
- **CLI automation** via a `Batch` CR runs Data Grid CLI commands declaratively
  with `oc`.
- **Health** of the cache manager:
  `GET /rest/v2/cache-managers/default/health/status` (no credentials), or the
  full per-cache health with Data Grid credentials — see
  [[ha-load-balancer-failover]] and the health-check chapter.
- Re-sync after split-brain: [[site-synchronization]].

## Contradictions / caveats
- This is **external** Infinispan — distinct from the **embedded** caches a
  single-cluster deployment uses ([[distributed-caches]]). Embedded cannot span
  sites.
- The blueprint is a **minimal functional example**, not a hardened config — add
  your own security and performance tuning.
- Naming: 26.0/26.2 docs call the parent setup "multi-site"; 26.4/26.6 call it
  "multi-cluster". The Data Grid Cross-DC building block is the same.
