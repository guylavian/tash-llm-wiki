# Metrics exemplars (linking metrics to traces)

**Exemplars attach the last recorded trace ID to a metric data point, so a Grafana metrics panel can jump straight to the trace behind an outlier latency or error.**

## Which metrics support exemplars

- `http_server_requests_seconds_count` (including histograms) — see [[server-metrics-endpoint]].
- `keycloak_credentials_password_hashing_validations_total`.
- `keycloak_user_events_total` — see [[event-metrics]].

## Setup

1. Enable metrics ([[server-metrics-endpoint]]) and tracing ([[tracing-otlp]]).
2. Enable **exemplar storage** in Prometheus (a **preview** feature you must turn on).
3. Scrape using the `OpenMetricsText1.0.0` protocol (not on by default). With the Prometheus Operator, set it on the `ServiceMonitor`:
   ```yaml
   spec:
     scrapeProtocols:
       - OpenMetricsText1.0.0
   ```
4. In Grafana, configure `exemplarTraceIdDestinations` on the Prometheus datasource pointing at your tracing datasource (Jaeger/Tempo).
5. Toggle **Exemplars** on each dashboard query — dots/stars appear that link to traces.

## Verifying

Record all traces for the test (tracing ratio `1.0`, see [[tracing-otlp]]), log in to generate traces, then scrape with the OpenMetrics content type and look for the `# {span_id=...,trace_id=...}` suffix:

```
curl -s http://localhost:9000/metrics \
  -H 'Accept: application/openmetrics-text; version=1.0.0; charset=utf-8' \
  | grep "#.*trace_id"
```

## Contradictions / caveats

- If the scrape protocol is **not** negotiated as OpenMetrics 1.0.0, Prometheus (and a browser hitting `/metrics`) falls back to PrometheusText and **no exemplars** appear.
- An exemplar only exists if the request was actually **sampled** into a trace — with low sampling ratios many points have none.
- Prometheus exemplar storage is a **preview** feature — confirm your (mirrored) Prometheus build supports it for air-gapped setups.
