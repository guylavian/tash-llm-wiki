# Client Registration CLI (kcreg)

**`kcreg.sh` / `kcreg.bat` — the command-line front end to the RHBK
[[client-registration-service]] REST endpoints, for self-service client config in
scripts.**

## Where it lives
Packaged inside the RHBK server distribution under `bin/` (`kcreg.sh` on Linux,
`kcreg.bat` on Windows). Add `$KEYCLOAK_HOME/bin` to `PATH` to run from anywhere.

## Authenticating
By default the server recognizes the CLI as the `admin-cli` client (auto-created
per realm), so logging in by username needs no extra client config. You can also
configure a dedicated client (e.g. `reg-cli`) with **Client authentication On**
and either a service account or Direct Access Grants, then:
`kcreg config credentials --client reg-cli --secret <secret>`.

## Typical workflow
- `kcreg config initial-token $TOKEN` then `kcreg create -s clientId=myclient`
  (or `kcreg create -s clientId=myclient -t $TOKEN`) — uses an Initial Access
  Token when the user lacks `manage-clients`.
- Edit round-trip: `kcreg get myclient > myclient.json`, edit, then
  `kcreg update myclient -f myclient.json`.

## Permissions
A user needs a realm-management role (`manage-clients` for full control,
`view-clients` read-only, or `create-client`) **or** an Initial Access Token.
With neither, operations fail with `403 Forbidden`.

## Contradictions / caveats
- Stable across RHBK 26.0–26.6. This is the developer self-service tool; for
  general admin automation use `kcadm.sh` instead (inferred — `kcadm.sh` is not
  mentioned in this chapter; the comparison is general RHBK tooling knowledge).
