# Management interface (port 9000)

**RHBK serves observability endpoints — `/health/*` and `/metrics` — on a dedicated management interface, port `9000` by default, separate from the application HTTP(S) ports.**

## Why a separate port

Keeping health and metrics off the main ports lets you firewall the management interface independently and avoid exposing operational data to application clients. By default:

- [[health-endpoints]] (`/health/started`, `/health/live`, `/health/ready`, `/health`) — present when `health-enabled=true`.
- [[server-metrics-endpoint]] (`/metrics`, OpenMetrics text) — present when `metrics-enabled=true`.

## Relocation toggles

- `http-management-health-enabled=false` moves the **health** endpoints back to the main HTTP(S) ports; then block `/health` at the proxy.
- mTLS settings propagate to the management interface: with `https-client-auth=required`, set `https-management-client-auth` to `request` or `none` so probes don't need a client certificate.

## Contradictions / caveats

- Across 26.x the default management port is `9000`; it is configurable via the management-interface options (see "Configuring the Management Interface" in the server config guide).
- The container image strips `curl`, complicating in-container probing of this port — see [[health-endpoints]].
