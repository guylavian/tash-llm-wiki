# OpenTelemetry centralization (telemetry-* options)

**Global `telemetry-*` server options point all RHBK observability signals (Logs, Metrics, Traces) at a single OpenTelemetry collector, so you get one OTLP endpoint for the whole stack.**

## How it works

The `opentelemetry` feature is **enabled by default**; OTel only exports once at least one component is turned on (for example Traces). The global settings are shared across all components:

- `telemetry-endpoint` — OTLP collector endpoint. Default `http://localhost:4317`.
- `telemetry-service-name` — service identifier of the exporter. Default `keycloak`. Takes precedence over `service.name` set in `telemetry-resource-attributes`.
- `telemetry-protocol` — transport. `grpc` (default) or `http/protobuf`.
- `telemetry-resource-attributes` — list of resource attributes (e.g. `service.namespace`).
- `telemetry-header-<header>` — custom request headers sent with all telemetry exports (auth tokens etc.), e.g. `--telemetry-header-Authorization='Bearer my-token'`.

Component-specific headers (`telemetry-logs-header-*`, `telemetry-metrics-header-*`, and the [[tracing-otlp]] options) take precedence over the general `telemetry-*` settings for their component.

```
bin/kc.[sh|bat] start \
  --telemetry-endpoint=http://my-otel-endpoint:4317 \
  --telemetry-service-name=my-keycloak-iam \
  --telemetry-protocol=http/protobuf
```

## Components

- **Traces** — the supported path; can override global telemetry settings via the `tracing-*` options to ship traces to a different collector. See [[tracing-otlp]].
- **OTel Logs** (`telemetry-logs-enabled`, feature `opentelemetry-logs`) — **Technology Preview**, disabled by default. `telemetry-logs-level` filters which already-generated logs are exported (it does not raise `log-level`).
- **OTel Metrics** (`telemetry-metrics-enabled`, feature `opentelemetry-metrics`) — **experimental**, not for production; also requires `metrics-enabled=true`. Uses the Micrometer-to-OpenTelemetry bridge, so semantic conventions differ from the native [[server-metrics-endpoint]].

## Operator (Keycloak CR)

In **RHBK 26.6** the Keycloak CR has a first-class `spec.telemetry` stanza mapping 1:1 to the `telemetry-*` options:

```yaml
spec:
  telemetry:
    endpoint: http://my-telemetry:4317
    serviceName: my-best-keycloak-telemetry
    protocol: http/protobuf
    resourceAttributes:
      service.namespace: keycloak-namespace-telemetry
```

OTel Logs/Metrics are enabled by listing `opentelemetry-logs` / `opentelemetry-metrics` under `spec.features.enabled`. See [[rhbk-operator]].

## Contradictions / caveats

- The `spec.telemetry` CR stanza is a 26.6 addition; on earlier versions use `additionalOptions` to pass the `telemetry-*`/`tracing-*` keys.
- OTel **Logs** and **Metrics** remain Tech Preview/experimental across 26.x — prefer the native `/metrics` scrape and your normal log pipeline in production.
- `telemetry-logs-level` filters already-generated logs: `telemetry-logs-level=DEBUG` exports nothing extra if `log-level=WARN`.
