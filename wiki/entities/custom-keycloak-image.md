# Custom / pre-optimized RHBK images

**Pointing the [[keycloak-cr]] at a custom container image (`spec.image`) so the
server runs a pre-augmented, build-time-optimized build instead of re-augmenting
on every Pod start.**

## Why pre-optimize

With the default image the server performs a **costly re-augmentation every time a
Pod starts**. A custom image with augmentation (and any build-time config /
extensions) baked in at build time avoids that delay — important for fast scaling
and for air-gapped registries ([[operator-olm-install]]).

## Providing the image

```yaml
spec:
  instances: 1
  image: quay.io/my-company/my-keycloak:latest
  http:
    tlsSecret: example-tls-secret
  hostname:
    hostname: test.keycloak.org
```

- **Version alignment**: the RHBK release inside the custom image must match the
  Operator version for full Operator/Operand compatibility.
- For an **optimized** image, `health-enabled` and `metrics-enabled` must be set
  explicitly in the Containerfile.
- **Build-time options are ignored at runtime**: with a custom image, every
  build-time option passed via a dedicated CR field or [[additional-options]] is
  ignored — bake them into the image.
- The Operator is unaware of config inside the image. Use the CR for anything the
  Operator must reflect in Services/probes — namely TLS/HTTP(S) settings and
  [[keycloak-truststores]] (so the Operator probes the right scheme).

## Non-optimized custom image

If you must use a non-optimized image (or build-time properties on an augmented
image), set `startOptimized: false` — this re-incurs the re-augmentation cost on
every start:

```yaml
spec:
  image: quay.io/my-company/my-keycloak:latest
  startOptimized: false
```

## Contradictions / caveats

- Behavior is consistent across 26.0–26.6. The chapter is numbered Ch. 5 in 26.0
  and Ch. 6 in 26.6 (a rolling-updates chapter was inserted) — same content.
- Changing the image tag triggers a **recreate** update by default; use
  [[operator-rolling-updates]] (`Auto`, or experimental `rolling-updates:v2`) to
  avoid downtime when only the theme/provider/build-time config changed.
