# The `multi-site` Feature Flag

**An RHBK feature that must be enabled on the `Keycloak` CR for a
multi-cluster/cross-site deployment; among other things it exposes the
load-balancer probe `/lb-check`.**

## What it does
Enabling `multi-site` switches RHBK into the multi-cluster operating mode used
with an [[external-data-grid-operator]] and a failover
[[ha-load-balancer-failover]]. The guide specifically calls out that it enables
**additional features for multi-site support like the loadbalancer probe
`/lb-check`**, which the AWS Global Accelerator NLB health-checks.

On the `Keycloak` Custom Resource:
```yaml
spec:
  features:
    enabled:
      - multi-site
```

## Companion CR settings (multi-cluster blueprint)
The same CR that enables `multi-site` typically also sets:
- `cache-remote-host` / `cache-remote-port` / `cache-remote-username` /
  `cache-remote-password` — connect to the external Data Grid as a remote store.
- `spi-connections-infinispan-quarkus-site-name` — the local Data Grid site name.
- `transaction.xaEnabled: false` — XA is **not** supported by the AWS Aurora JDBC
  wrapper driver (`software.amazon.jdbc.Driver`).
- `http-max-queued-requests` — load shedding ([[session-persistence-volatile]]
  is unrelated; this caps the request queue, returning HTTP 503 past the limit).
- `metrics-enabled: true` — needed for sizing/monitoring (filter the endpoint
  behind a reverse proxy so it is not externally reachable).

## Contradictions / caveats
- Used only for **multi-cluster**; a single-cluster deployment does not enable it.
- Enabling the flag alone is insufficient — the external Data Grid connection, the
  synchronously replicated database, and the failover LB must all be in place.
- It is a product feature flag, not a preview gate in the HA blueprints, but
  confirm its support state for your target version (26.0/26.2 vs 26.4/26.6) since
  the surrounding chapter was renamed "multi-site" → "multi-cluster".
