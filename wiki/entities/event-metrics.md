# User event metrics (keycloak_user_events_total)

**Event metrics expose aggregated counters of user activities (logins, login failures, token refreshes) as `keycloak_user_events_total`, per RHBK instance, on the standard `/metrics` endpoint.**

## Enabling

Needs both `metrics-enabled` and the user-event-metrics toggle:

```
bin/kc.[sh|bat] start --metrics-enabled=true --event-metrics-user-enabled=true
```

The feature is `user-event-metrics`. Counters are **per instance** and **reset on restart**; in a cluster you must collect from all instances and aggregate for a cluster-wide view.

## Dimensions and filtering

- By default there is a separate metric **per realm**.
- `event-metrics-user-tags` adds dimensions — `realm`, `idp`, `clientId`. Breaking down by client/IdP is fine for small installs but raises memory and monitoring load with many clients/IdPs.
  `--event-metrics-user-tags=realm,idp,clientId`
- `event-metrics-user-events` limits which event types are counted, e.g. `--event-metrics-user-events=login,logout`. (See the Server Administration Guide for the list of event types.)

The emitted series looks like:
`keycloak_user_events_total{client_id="...",error="",event="login",idp="",realm="master"} 1.0` — with `error` populated for failures (e.g. `invalid_user_credentials`).

This counter powers the **capacity planning** Grafana dashboard (see [[grafana-dashboards]]) and supports [[metrics-exemplars]].

## Contradictions / caveats

- Currently **only user events** are captured as metrics ("for now") across 26.x.
- Both `event-metrics-user-enabled` and the `metrics-enabled` build option are required; the feature `user-event-metrics` must be enabled.
- Restart resets counters — alert/aggregate accordingly.
