# FIPS startup failures — Bouncy Castle libs and Argon2 admin login

**Two distinct FIPS-mode failures: a native BC link error at startup, and an "Invalid credentials" admin login due to an Argon2 hash.**

## Body
### 1. Startup fails with UnsatisfiedLinkError (kb:7135122)
**Symptom.** Server will not start in FIPS mode:
`Fips1402StrictCryptoProvider` config error and
`java.lang.UnsatisfiedLinkError: /tmp/bc-fips-jni.../libbc-probe.so: failed to map segment from shared object`.

**Cause.** The bundled Bouncy Castle FIPS libraries were replaced with
external/newer versions (e.g. `bc-fips` 2.1.x from Maven Central / the BC
website) that are not certified with the product runtime.

**Fix.** Use only the **bundled** BC FIPS jars; remove any externally placed
versions from the library path/classpath. For RHBK 26.2.10 the bundled versions
are `bc-fips: 2.0.0`, `bctls-fips: 2.0.19`, `bcpkix-fips: 2.0.7`,
`bcutil-fips: 2.0.3`. Air-gap: never substitute jars from a public mirror.

### 2. Admin "Invalid credentials" after switching to FIPS (kb:7135124)
**Symptom.** Correct admin password is rejected with "Invalid credentials";
TRACE shows `PasswordHashProvider argon2 not found for user admin`.

**Cause.** The existing admin password was hashed with **Argon2** (the non-FIPS
default), which is disabled in FIPS mode, so the hash cannot be verified.

**Fix.** Restart out of FIPS, log in, create a new admin (e.g. `admin_fips`)
whose password uses a FIPS-compliant algorithm (PBKDF2; strict FIPS typically
needs ≥14 chars), restart with `--features=fips --fips-mode=strict`, verify the
new user, then delete the old Argon2-hashed admin.

Applies to RHBK 26.x in FIPS mode.

## Contradictions / caveats
These two are independent — a clean BC-jar install can still hit the Argon2
login failure, and vice versa. Fix both when standing up FIPS on an existing
realm.
