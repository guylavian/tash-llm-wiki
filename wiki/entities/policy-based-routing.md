# Policy-Based Routing (PBR)

**Forwarding packets according to a route map applied to an interface rather than by destination-based longest-prefix lookup — enabling source-, application-, or link-sensitive routing.**

## How it works
`ip policy route-map tag` on an interface policy-routes transit traffic; `ip local policy route-map tag` does the same for router-originated traffic. Packets are matched (`match ip address` ACL/prefix or `match length`) and forwarded via the map's `set` clauses (`set ip next-hop`, `set interface`, `set ip precedence`).

## Caveats
- **Enabling `ip policy route-map` disables fast switching** for all packets on that interface.
- **Local PBR + TCP:** router-sourced TCP fails unless the device has a RIB/FIB entry for the remote host (the path itself need not match the PBR path); UDP/ICMP still follow the local policy.
- **`set ip next-hop verify-availability`** checks the next hop is a CDP neighbor before policy-routing, preventing a blackhole/ARP loop when the next hop is down; it requires CDP, a directly-connected Cisco next hop, and does not work with distributed CEF.

## Variants
**SGT-based PBR** matches Cisco TrustSec Security Group Tags instead of IP/ACL (number-based tags only, not IPv6 on IOS XE); a dynamic SGT route-map overrides a static route-map on the same interface — always disassociate a route-map from the interface before deleting it (inferred: otherwise static PBR can't be reconfigured).
