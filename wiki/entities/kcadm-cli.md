# kcadm.sh — Admin CLI

**The command-line client (`kcadm.sh` on Linux, `kcadm.bat` on Windows) that performs Admin REST API CRUD operations against realms, clients, users, roles, groups, keys, and events.**

Ships in the server `bin/` directory; add `$KEYCLOAK_HOME/bin` to `PATH`.

## Authenticating
```
kcadm.sh config credentials --server http://localhost:8080 --realm master --user admin
```
This saves the access + refresh token to `$HOME/.keycloak/kcadm.config` (Windows:
`%HOMEPATH%\.keycloak\kcadm.config`) and reuses them across invocations. Alternatives:
- Authenticate per-command with `--no-config` (nothing written to disk; more token
  round-trips).
- Log in with a `clientId` + client secret (or **Signed JWT**) instead of a user
  password — creates a service-account session.
- Omit `--password` to be prompted, or supply it via env `KC_CLI_PASSWORD`.
- Point at an alternate config file with `--config` for parallel sessions.
- For TLS to a private CA: `kcadm.sh config truststore --trustpass <pw> <truststore.jks>`.

The session account needs Admin REST permissions (e.g. the `realm-admin` role of the
`realm-management` client). See [[realm-resource-access]].

## CRUD model
```
kcadm.sh create|get|update|delete ENDPOINT [ARGS]
```
maps to POST/GET/PUT/DELETE against `SERVER_URI/admin/realms/REALM/ENDPOINT`. Use `-r`
to target a different realm than the login realm; `-s name=value` to set attributes
(values are parsed as JSON; quote arrays like `'redirectUris=["http://app/*"]'`);
`-f FILE` (or `-f -` for stdin) to send a JSON body; `-i` to print the created id;
`-o` to print the result. `update` does get-then-merge by default — `-n` does a
no-merge PUT. List trimming: `--fields realm,enabled`, `--format csv --noquotes`.

## Common operations
- **Realms:** `create realms -s realm=demorealm -s enabled=true` (realms are disabled by
  default), `get realms`, `update realms/demorealm -s enabled=false`,
  `delete realms/demorealm`.
- **Keys:** `get keys -r demorealm`; rotate via `create components ...` — see
  [[realm-keys-and-rotation]].
- **Roles:** `create roles`, `get-roles` (with `--cclientid`, `--rolename`,
  `--effective`, `--available`, `--all`), `add-roles` / `remove-roles` for composite
  roles and for assigning to groups (`--gname`). See [[roles-and-groups]].
- **Users:** `create users -s username=testuser -s enabled=true -r demorealm`.
- **Events:** `update events/config -r demorealm -s 'eventsListeners=["jboss-logging"]'`,
  toggle `eventsEnabled` / `adminEventsEnabled`, set `eventsExpiration` (seconds).
- **Caches:** `create clear-realm-cache` / `clear-user-cache` / `clear-keys-cache`
  (each with `-s realm=<realm>`).
- **Import:** `create partialImport -r <realm> -s ifResourceExists=FAIL|SKIP|OVERWRITE -f
  exported.json`. See [[realm-import-export]].

## Contradictions / caveats
- Bodies sourced are RHBK **26.0**; the Admin CLI chapter appears in 26.2/26.4 primary
  results with the same command surface.
- Passing secrets as command options is discouraged — prefer prompting or env vars.
- Quoting non-JSON values in `-s` and having the quotes stripped is **deprecated**
  behavior; supply unquoted text or valid JSON string literals.
