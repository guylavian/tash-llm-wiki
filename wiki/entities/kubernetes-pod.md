# Kubernetes Pod

**A pod is the smallest deployable unit: one or more containers that share one IP/port space and storage volumes and are always co-scheduled on the same node.** Pods are ephemeral — you manage them through controllers, not by hand.

## Lifecycle + identity
- A pod's name and IP do **not** survive rescheduling; treat pods as cattle. Create them through a controller: **Deployment** (stateless), **StatefulSet** (stable identity/storage), **DaemonSet** (one per node), **Job/CronJob** (batch).

## Health — probes
- **liveness** — failing restarts the container.
- **readiness** — failing removes the pod from [[kubernetes-service]] endpoints (no restart) — the lever behind router 503s.
- **startup** — gates the other two for slow-starting apps.

## Placement — requests + limits
- **requests** are what the scheduler reserves; a pod whose request fits no node stays **Pending**.
- **limits** cap usage: CPU is throttled, memory over-limit is **OOMKilled** (→ CrashLoopBackOff).

## On OpenShift
- Runs under an SCC: by default a **random non-root UID** (`restricted-v2`) — see [[security-context-constraints]]. Make images UID-agnostic.
