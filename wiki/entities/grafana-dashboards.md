# Grafana dashboards for RHBK

**RHBK provides official Grafana dashboard JSON (troubleshooting and capacity planning) in the `keycloak/keycloak-grafana-dashboard` GitHub repo, imported into Grafana against a Prometheus datasource.**

## Dashboards

- **Troubleshooting dashboard** (`keycloak-troubleshooting-dashboard.json`) — shows the [[service-level-indicators]] graphs on top, and supports drilling down when SLI graphs look wrong (per the troubleshooting-with-metrics chapter).
- **Capacity planning dashboard** (`keycloak-capacity-planning-dashboard.json`) — load estimation: password validations, login flows, etc. Requires [[event-metrics]] to be enabled to populate correctly.

## Prerequisites

- Metrics enabled and collected into Prometheus (see [[server-metrics-endpoint]]).
- For HTTP request latency **heatmaps**, set `http-metrics-histograms-enabled=true`.

## Version-to-branch mapping (air-gap)

The JSON lives outside the product, so mirror/clone the matching branch before going disconnected:

| RHBK version | `keycloak-grafana-dashboards` branch/tag |
|---|---|
| 26.1 – 26.2 | `26.2.0` |
| >= 26.3 | `main` |

`git clone -b <branch> https://github.com/keycloak/keycloak-grafana-dashboard.git` then import the files from `dashboards/`.

## Import / bare-metal

Import via Grafana **New → Import → Upload dashboard JSON**, then pick the Prometheus datasource. The dashboards expect Kubernetes-inserted labels (`namespace`, `container`, `pod`); for bare-metal, add them in the Prometheus scrape config with static labels and a `relabel_configs` rule mapping `__address__` to `pod`.

## Contradictions / caveats

- Dashboards are sourced from an **external GitHub repo**, not bundled in the product image — plan for this in disconnected installs.
- Branch selection is version-sensitive; using `main` against an older RHBK may reference metrics/labels that differ.
