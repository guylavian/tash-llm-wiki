# Kubernetes DaemonSet

**A DaemonSet ensures all (or a selected subset of) nodes run a copy of a Pod — Pods are added as nodes join the cluster and garbage-collected as nodes leave; deleting the DaemonSet cleans up the Pods it created.**

## Typical uses
- A cluster storage daemon on every node.
- A log-collection daemon on every node (e.g. fluentd).
- A node-monitoring daemon on every node.

A more complex setup can run multiple DaemonSets for the same type of daemon, with different flags or resource requests per hardware type.

## Shape
- `.spec.template` is a Pod template (same schema as a Pod, minus `apiVersion`/`kind`), and its `RestartPolicy` must be `Always` (or unspecified, which defaults to `Always`).
- `.spec.selector` is a Pod selector, same mechanics as a Job's — it must match the Pod template's labels and, once set, is immutable.

## DaemonSet vs Deployment vs autoscaling
A DaemonSet's replica count is implicitly "one per matching node," not a number you set — it does not have a `.spec.replicas` field, and **horizontal pod autoscaling does not apply to DaemonSets** (there's nothing to scale independent of node count) (inferred: contrast drawn against [[horizontal-pod-autoscaler]], which targets Deployments/StatefulSets only).
