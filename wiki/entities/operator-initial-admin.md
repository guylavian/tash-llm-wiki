# `bootstrapAdmin` & the `-initial-admin` Secret

**How the Operator provisions the first admin: the `spec.bootstrapAdmin` stanza on
the [[keycloak-cr]], or an auto-generated `<cr-name>-initial-admin` Secret.**

## Auto-generated (default)

If `spec.bootstrapAdmin` is omitted, the Operator creates a basic-auth Secret named
`<metadata.name>-initial-admin` in the CR's namespace, with username **`temp-admin`**
and a generated password. Fetch it:

```bash
oc get secret example-kc-initial-admin -o jsonpath='{.data.username}' | base64 --decode
oc get secret example-kc-initial-admin -o jsonpath='{.data.password}' | base64 --decode
```

Use these for the Admin Console or Admin REST API. **Change the default credentials
and enable MFA before production.**

## Explicit `bootstrapAdmin`

`spec.bootstrapAdmin` can name a Secret for a bootstrap **user** (must contain
`username` + `password`) and/or a bootstrap **service account** (must contain
`client-id` + `client-secret`).

## Caveats

- If a **master realm already exists** for the cluster, `spec.bootstrapAdmin` is
  effectively **ignored**. To create a recovery admin then, run the CLI command
  directly against a Pod — see [[kc-bootstrap-admin]] and the Admin bootstrap and
  recovery guide.

## Contradictions / caveats

- Behavior is consistent across 26.0–26.6.
