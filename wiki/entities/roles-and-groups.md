# Roles and groups

**Roles (realm roles and client roles, optionally composite) grant permissions; groups bundle role assignments and attributes for sets of users — both are managed in the Admin Console or via `kcadm.sh`.**

## Realm vs client roles
- **Realm role** — scoped to the realm. Create:
  `kcadm.sh create roles -r demorealm -s name=user -s 'description=...'`.
- **Client role** — scoped to a specific client. Create under the client's id:
  `kcadm.sh create clients/<clientId>/roles -r demorealm -s name=editor`.

List with the dedicated `get-roles` command: realm roles `get-roles -r demorealm`,
client roles `get-roles -r demorealm --cclientid realm-management`. Identify a role by
name (`--rolename` / `--rname` for a composite target) or id (`--roleid` / `--rid`).

## Composite roles
A composite role aggregates other realm and/or client roles, so assigning it grants all
its constituents. Manage with `add-roles` / `remove-roles`:
```
kcadm.sh add-roles -r demorealm --rname testrole --rolename user
kcadm.sh add-roles -r demorealm --rname testrole --cclientid realm-management --rolename create-client --rolename view-users
```
Inspect with `get-roles --rname testrole [--effective|--available|--all]`:
- `--effective` — roles the composite ultimately grants.
- `--available` — roles that could still be added.
- `--all` — full expansion.

## Groups
Groups can be granted roles in bulk. Assign client roles to a group with `add-roles`
using `--gname Group` (or `--gid`):
```
kcadm.sh add-roles -r demorealm --gname Group --cclientid realm-management --rolename create-client --rolename view-users
```
Users inherit the group's role assignments. Admin permissions over realm resources are
themselves expressed as client roles of the `realm-management` client — see
[[realm-resource-access]].
