# Intermittent AD identity-provider link loss (account-merge prompts)

**Symptom → cause → fix for users sporadically losing their AD federated link and being asked to merge accounts.**

## Body
**Symptom.** Users sporadically lose their IdP link to Active Directory and are
prompted to "merge accounts" on login.

**Cause.** The IdP **Username Template Importer** mapper keys the federated link
on a *mutable* AD attribute (e.g. `${ATTRIBUTE.sAMAccountName}`,
`${ATTRIBUTE.userPrincipalName}`, `${ATTRIBUTE.cn}`). When AD admins change that
attribute, the new identifier no longer matches the stored link.

**Fix.** Reconfigure the Identity Provider mapper's **Template** to an immutable
AD attribute — the standard is `objectGUID`. This causes a one-time
merge/relink for existing users (their old links were keyed on the previous
attribute). Per-user recovery: click **Link** on the merge screen, or an admin
manually relinks.

Applies to RHBK 26.x with an Active Directory identity provider / federated links.

## Contradictions / caveats
Distinguish from LDAP *user federation* UUID config: this is about the
**brokering** (IdP) mapper's username template, not the LDAP provider's UUID
attribute. See [[ldap-user-federation]] for the federation side. (inferred —
this distinction is not made in the cited kb:7128299 source; it is added here
to prevent confusion with the separate LDAP federation UUID setting.)
