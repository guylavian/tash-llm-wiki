# Server metrics endpoint (/metrics) and histograms

**With `metrics-enabled=true`, RHBK exposes a Prometheus/OpenMetrics `/metrics` endpoint on the management port serving System, JVM, Database, HTTP, and Infinispan Cache metric families.**

## Enabling and querying

Build-time/start option:

```
bin/kc.[sh|bat] start --metrics-enabled=true
```

The endpoint is `/metrics` on the [[management-port]], content type `application/openmetrics-text` (Prometheus/OpenMetrics text format).

## Metric families

| Family | Examples / scope |
|---|---|
| System | CPU and memory, e.g. `system_load_average_1m` |
| JVM | GC and heap, e.g. `base_gc_total`, `jvm_memory_usage_after_gc_percent`, `jvm_threads_peak_threads` |
| Database | Agroal connection pool, e.g. `agroal_active_count` |
| HTTP | Global and per-endpoint, e.g. `http_server_requests_seconds_count` / `_bucket` |
| Cache | Infinispan caches — see [[distributed-caches]] |

### Self-provided (Keycloak-specific) metrics

- `keycloak_user_events_total` — user event counter (tagged `realm`, `client_id`, `idp`, `event`, `error`). Requires [[event-metrics]].
- `keycloak_credentials_password_hashing_validations_total` — password validations, tagged `algorithm`, `hashing_strength`, `outcome`, `realm`. Useful for capacity planning.

## Histograms and SLO buckets

- `http-metrics-histograms-enabled=true` adds percentile buckets to `http_server_requests_seconds` for heatmaps and latency analysis — at extra cost to your monitoring system.
- `http-metrics-slos` adds explicit buckets for specific latency thresholds (e.g. `250` ms) used by [[service-level-indicators]].

`http_server_requests_seconds_count`, `keycloak_user_events_total`, and `keycloak_credentials_password_hashing_validations_total` can carry [[metrics-exemplars]] linking to a trace.

## Contradictions / caveats

- This native endpoint is the **supported** metrics path. The OpenTelemetry Metrics export (`telemetry-metrics-enabled`, Micrometer-to-OTel bridge) is **experimental** with differing semantic conventions (inferred — not in the two metrics chapters cited here; see [[opentelemetry-centralization]] for its own sourcing).
- Histograms/percentile buckets increase scrape and storage load; enable only where you need heatmaps or fine SLO buckets.
