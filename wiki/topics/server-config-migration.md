# Migrating the RH-SSO 7.6 server configuration to RHBK

**Mapping each RH-SSO 7.6 `standalone.xml` subsystem (datasource, TLS, cache,
hostname, truststore, vault, JVM) to the equivalent RHBK `kc.sh` options.**

## Body
Prerequisites: shut down the old RH-SSO instance so two server versions never
share the database at once, back up the database, install **OpenJDK 21**, and
review the target version release notes. The general config-model change is
described in [[quarkus-config-migration]].

### Database
RHBK bundles drivers for the supported databases (exception: **Oracle and
Microsoft SQL Server** still need manual driver installation). Map the
`KeycloakDS` datasource to options:

```
kc.sh start --db postgres --db-url-host mypostgres --db-url-port 5432 \
  --db-url-database mydb --db-schema myschema \
  --db-pool-min-size 5 --db-pool-max-size 50 \
  --db-username myuser --db-password myuser
```

Store credentials in the KeyStore config source where possible. The schema is
auto-migrated on first connect — see [[database-auto-migration]].

### HTTP / TLS
HTTP is **disabled** and TLS is **required** by default in production (`start`)
mode. RHBK serves from the server root, not `/auth`; restore the old path with
`--http-relative-path=/auth`. TLS via keystore
(`--https-key-store-file/--https-key-store-password`) or PEM
(`--https-certificate-file/--https-certificate-key-file`).

### Clustering / cache
The Infinispan subsystem moves to a separate Infinispan config file; the most
common knobs are exposed as options (e.g.
`cache-embedded-realms-max-count`). Default JGroups transport is now
**`jdbc-ping`** (DB-based discovery, TCP, auto-TLS). All stacks except
`kubernetes` deprecated in **26.2**; `kubernetes` also deprecated in **26.4** —
migrate to `jdbc-ping`. Set `jgroups.bind.address` (and
`jgroups.external_port`/`jgroups.external_addr` in non-transparent networks).
See [[distributed-caches]] and [[ha-cross-site]].

### Hostname / proxy
The Hostname SPI is now **mandatory** under `start` (RH-SSO merely recommended
it). Translate `frontendUrl` → `--hostname`, set `--hostname-admin` for the admin
URL, and choose proxy header handling with `--proxy-headers xforwarded` (or
`forwarded`). Disable enforcement with `--hostname-strict=false`. Hostname/proxy
options affect generated resource URLs only — never the bind address/port.

### Truststore
File truststore SPI → system truststore. RHBK accepts **PEM** or **unencrypted
PKCS12** (`.p12`/`.pfx`); **JKS must be converted** (keytool to PKCS12, then
`openssl` to strip the password). Example:
`--truststore-paths path/to/store.p12 --tls-hostname-verifier WILDCARD`.

### Vault
The Elytron Credential Store becomes the **Keystore Vault**
(`--vault keystore --vault-file ... --vault-pass ...`). No realm changes needed
if the new keystore holds the same secrets; `${vault.realm-name_alias}` resolves
as before under the default `REALM_UNDERSCORE_KEY` resolver. See [[vault-spi]].

### JVM
Same approach as RH-SSO but no `standalone.conf`; use `JAVA_OPTS` /
`JAVA_OPTS_APPEND`.

## Contradictions / caveats
- 26.2 vs 26.4 transport-stack deprecation differs (see above) — pin your
  decision to the exact target version.
- Manual schema migration changes the start behavior: the server writes the SQL
  file and then **exits** instead of running. See [[database-auto-migration]].
