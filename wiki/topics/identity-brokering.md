# Identity brokering

**RHBK acts as an identity broker — an intermediary that delegates authentication to external identity providers (social, OIDC, SAML) and then issues its own token to the client, so applications only ever integrate with RHBK.**

## Broker flow
An unauthenticated user hits a protected resource → client redirects to RHBK → RHBK
shows configured IdPs → user picks one → RHBK redirects to the external IdP → IdP
authenticates → user returns with a security token → RHBK validates it and **imports/
creates the user** (identity federation) or, if the user exists, prompts **account
linking** (governed by the First Login Flow) → RHBK issues its own token to the client.
The client never sees the external protocol — only RHBK does. A **default IdP** (set on
the Identity Provider Redirector in the Browser flow) can skip the IdP-selection page;
the `kc_idp_hint` query parameter lets a client request a specific provider.

## Provider types
- **Social** — Google, Facebook, GitHub, GitLab, Bitbucket, LinkedIn, Instagram,
  Microsoft, PayPal, OpenShift, Stack Overflow, Twitter. Each takes a client ID/secret
  obtained from the provider and a generated **Redirect URI**.
- **Protocol-based** — **OIDC v1.0 / OAuth v2.0** and **SAML v2.0**; broker any compliant
  IdP. An OIDC realm-as-client can authenticate to the external IdP with a client secret,
  the realm private key, or a Signed JWT. SAML v2.0 IdPs configure Entity IDs, SSO/SLO/
  Artifact service URLs, bindings (Redirect vs HTTP-POST vs Artifact), Principal Type
  (Subject NameID or SAML attribute), and signing/encryption (the realm keypair signs
  AuthnRequests when *Want AuthnRequests Signed* is on; decryption keys come from
  [[realm-keys-and-rotation]] with `enc` use).

## Common IdP settings
`Alias` (unique id, used to build redirect URIs), `Enabled`, `Hide on Login Page`,
`Account Linking Only`, `Store Tokens` / `Stored Tokens Readable`, `Trust Email`
(skips email verification), `GUI Order`, `Verify essential claim` (+ claim name/value,
value supports regex), **First Login Flow**, **Post Login Flow**, **Sync Mode**
(`legacy` / `import` / `force`), and `Case-sensitive username`.

For LDAP/AD *user storage federation* (a different mechanism from brokering) see the
existing [[ldap-user-federation]], [[ldap-storage-mode]], and [[ldap-mappers]] pages.

## Contradictions / caveats
- Bodies sourced are RHBK **26.0**; the Integrating identity providers chapter is present
  in 26.2/26.4 primary results. The exact social-provider list and SAML option set can
  shift between 26.0/26.2/26.4/26.6.
- Brokering (external IdP) is distinct from LDAP **user federation**; do not conflate the
  First Login Flow (brokering) with LDAP import modes.
