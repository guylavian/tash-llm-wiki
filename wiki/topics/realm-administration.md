# Realm administration

**A realm is the isolated security domain in which Keycloak/RHBK manages users, applications, roles, and groups; one deployment hosts many realms, all isolated from one another.**

## The master realm vs. other realms
Two kinds of realm exist. The **master realm** is created at first start and holds
the bootstrap administrator account (see [[kc-bootstrap-admin]]); use it only to
create and manage other realms. **Other realms** are where you place your users
and applications — avoid creating end users in master. Realms are isolated and
can only authenticate the users they own. You can disable master and use
**Dedicated Realm Admin Consoles** so each realm has its own console with local
admin accounts.

> Export files produced from the Admin Console are *not* suitable for backups or
> server-to-server transfer — only boot-time exports are. See [[realm-import-export]].

## Per-realm settings (Realm settings → tabs)
- **SSL mode** (General tab, "Require SSL"): `External requests` (HTTP allowed only
  from private/loopback IPs), `None` (dev only), or `All requests` (SSL mandatory).
  Production should use `All requests`. See [[security-hardening-checklist]].
- **Email** (Email tab): SMTP host/port, encryption (port 465 for SSL/TLS), and
  optional authentication. The SMTP password can reference an **external vault**.
  Email must be configured for Forgot Password, email verification, and the
  Update Email workflow.
- **Themes** (Themes tab): Login, Account, Admin console, and Email themes per realm.
- **Localization** (Localization tab): enable internationalization, choose supported
  locales and a default. Locale is resolved in order: user-selected → user profile →
  client `ui_locales` → cookie → `Accept-Language` → realm default → English.

## Login options (Login tab)
- **Forgot password** — adds a reset link; the reset flow can be customized (e.g.
  the `Reset - Conditional OTP` sub-flow, and `Force login after reset` =
  `true`/`false`/`only-federated`). See [[authentication-flows]].
- **Remember Me** — turns the login cookie from session-only into a persistent cookie.
- **ACR → LoA mapping** — maps Authentication Context Class Reference values to numeric
  Levels of Authentication, used by step-up flow conditions and the `acr` claim. See
  [[step-up-authentication]].
- **Update Email workflow (UpdateEmail)** — `UPDATE_EMAIL` required action; **Technology
  Preview, disabled by default**, enabled with `--features=preview` or
  `--features=update-email`.

Cryptographic signing/encryption for a realm is handled by its key providers — see
[[realm-keys-and-rotation]].

## Contradictions / caveats
- Sourced bodies are RHBK 26.0; chapter structure for "Configuring realms" is stable
  across **26.0 / 26.2 / 26.4 / 26.6** (same chapter appears in 26.2/26.4 primary hits).
- The **Update Email** workflow is a preview feature and not fully supported; migrating
  realms must explicitly enable the `Update Email` required action or users cannot
  change their email.
- The **Maximum Authentication Age** password policy may be deprecated in favor of the
  Update Password required action configuration (see [[password-policies]]).
