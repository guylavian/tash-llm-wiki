# Does it possible to configure realm specific Client Initiated Backchannel Authentication (CIBA)  URI ? 

Does it possible to configure realm specific Client Initiated Backchannel Authentication (CIBA) URI ?
Environment
- Red Hat Build of Keycloak(RHBK)
- 24.x
- Red Hat Single Sign On(RHSSO)
- 7.x
Issue
- How to configure realm specific CIBA setting i.e. channel uri ?
For realm A, i want to set channel uri as: https://ciba.aaa.com
For realm B, i want to set channel uri as: https://ciba.bbb.com
- In a single RHBK instance, can i supply multiple CIBA URLs at the same time ?
spi-ciba-auth-channel-ciba-http-auth-channel-http-authentication-channel-uri=https://ciba.aaa.com
spi-ciba-auth-channel-ciba-http-auth-channel-http-authentication-channel-uri=https://ciba.bbb.com
Resolution
- Unfortunately, the system property is global to the RHBK instance and does not support realm-specific values.
This means that only one CIBA authentication channel URI can be set per instance using this configuration
option.
spi-ciba-auth-channel-ciba-http-auth-channel-http-authentication-channel-uri
For different CIBA channel URIs example like:
https://ciba.aaa.com for Realm A
https://ciba.bbb.com for Realm B
Run separate RHBK instances, each configured with its own CIBA channel URI and dedicated to a specific realm.
This is currently the only supported way to assign different CIBA channel URIs per realm.
Root Cause
-
The CIBA HTTP Authentication Channel URI (httpAuthenticationChannelUri) is implemented as a system-wide
configuration in Red Hat Build of Keycloak. This setting is defined via a global system property (--spi-ciba-
auth-channel-ciba-http-auth-channel-http-authentication-channel-uri) and does not support realm-specific values.As a result, when multiple realms within the same RHBK instance require different CIBA channel URIs, only one can
be configured at a time. This architectural limitation prevents setting a distinct httpAuthenticationChannelUri
for each realm, which led to the issue observed.
