# Configuring Keycloak with Separate Hostname URLs for SSO and Admin Console

Configuring Keycloak with Separate Hostname URLs for SSO and Admin Console
Environment
- Red Hat Build of Keycloak (RHBK)
- 26.x
Issue
- Does Keycloak support separate hostname and hostname-admin urls without forced redirections ?
- There is a requirement to separate the
Red Hat build of Keycloak
hostname url (sso.com) and hostname-admin url
(ssoadmin.com) to achieve. Is it possible ?
Resolution
To achieve clean separation of user and admin hostnames without redirection, follow these steps:
- Disable strict hostname validation by setting the following:
hostname-strict=false
This allows Keycloak to accept requests to multiple hostnames without enforcing redirection to a single canonical hostname.
- Update the Keycloak configuration by commenting out the following lines in keycloak.conf:
#hostname=
#hostname-admin=
- Configure the external proxy (e.g., a reverse proxy or load balancer) to handle the URL rewriting and SSL termination for both sso.com and ssoadmin.com appropriately.
With this setup, both hostnames function independently:
Admin console is accessible via https://ssoadmin.com/admin
User login and application endpoints are served via https://sso.com
Root Cause
Keycloak's hostname settings, by default, enforce a single trusted hostname or a strict redirect to the defined hostname and hostname-admin. When both are defined and strict validation is enabled, the application will redirect requests to the canonical hostname, causing unintended behavior when separate admin and user URLs are required.
This behavior is by design to ensure consistency in production environments, unless overridden intentionally.
Diagnostic Steps
Verify the absence of unwanted redirections:
Access https://sso.com -> Should load login page without redirection.
Access https://ssoadmin.com/admin -> Should load admin console without redirecting to sso.com.
Check the effective runtime options:
- Run kc.sh show-config or inspect the running pod/container logs to confirm hostname-strict=false is
applied.
Ensure no hostname parameters are active in keycloak.conf:
# These should be commented or removed
#hostname=sso.com
#hostname-admin=ssoadmin.com
Ensure your reverse proxy is correctly routing:
sso.com -> Keycloak port for user endpoints
ssoadmin.com -> Keycloak port for admin console
