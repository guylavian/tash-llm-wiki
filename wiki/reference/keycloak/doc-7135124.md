# Admin login fails with "Invalid credentials" after enabling FIPS mode due to Argon2 password hashing

Admin login fails with "Invalid credentials" after enabling FIPS mode due to Argon2 password hashing
Environment
- Red Hat build of Keycloak (RHBK)
- 26.x
Issue
After successfully enabling FIPS mode on Red Hat build of Keycloak, users are unable to log in to the Admin Console using their existing administrator credentials. The UI displays "Invalid credentials," even though the correct password is provided.
Enabling TRACE logging reveals that the system is unable to find the Argon2 provider:
Plaintext
DEBUG [org.keycloak.credential.PasswordCredentialProvider] ... PasswordHashProvider argon2 not found for user admin
This occurs because the existing admin password was hashed using Argon2 (the default in non-FIPS mode). Argon2 is not FIPS-compliant and is strictly disabled when the server is running in FIPS mode. Consequently, the server cannot verify the password hash.
Resolution
To resolve this, the admin user's password must be updated to use a FIPS-compliant hashing algorithm, such as PBKDF2.
Perform the following steps:
- Revert to Non-FIPS Mode: Stop the server and restart it without FIPS flags enabled (i.e., run in standard mode).
- Create a New FIPS-Compliant Admin User:
- Log in to the Admin Console with the existing admin credentials.
- Create a new administrator user (e.g., admin_fips).
- Set a password for this new user. Ensure the realm's password policy uses PBKDF2 (or manually verify the hash algorithm if possible).
Note: If using strict FIPS mode, the password must typically be at least 14 characters long.
- Enable FIPS Mode: Stop the server and restart it with FIPS mode enabled (--features=fips --fips-mode=strict).
- Verify Access and Cleanup:
- Log in using the new admin_fips user.
- Delete the old admin user account that used the Argon2 hash to ensure no non-compliant credentials remain in the system.
