# LLM-Wiki Review — 2026-07-02

Rigorous review of the LLM-Wiki ("SRE brain") across structure, retrieval fitness, the temporal
knowledge graph, per-domain accuracy, consistency, maintainability, and coverage. Grounded in
file:line evidence; four parallel reviewers (structure/consistency, retrieval fitness, Keycloak+AD
accuracy, Cisco accuracy + coverage gaps) plus a direct code review of `_meta/wikikb/tkg/`.

## Verdict

The architecture is genuinely good: the schema contract, confidence gate, and temporal-honesty
rules are better-designed than most production RAG systems. But **two of the four domains are
disconnected from their own corpora, the eval scoreboard measures only half the vault, and filed
answers contain fabricated facts that the amortization model will now serve forever**. The pattern
held for keycloak; it was *ported* to AD/cisco/openshift as a shape without the load-bearing wiring.

## Blockers

### B1 — Fabricated facts filed as answers (cisco-ios-xe)

CLAUDE.md's own rule: amortization makes whatever was filed the cheap cache hit *forever*. These
are cached now:

- `questions/c9500-issu-svl-blackhole-nsf-gr.md:45` — "90 s = default BGP hold timer (3 × 30 s
  keepalive)". IOS-XE defaults are **60 s keepalive / 180 s hold**. This wrong number *anchors the
  diagnosis* of the post-mortem.
- Same page, :109/:117-118 — `show platform software ISSU` is not a real command (it's
  `show issu state detail`), and "C9500-SV-LIC" is not a real SKU (SVL needs Network Advantage).
- `questions/redistribute-ospf-into-ebgp.md:40` — "Without a route map, **all** OSPF routes are
  redistributed." Wrong: `redistribute ospf` into BGP takes internal routes only by default;
  externals need `match external 1 external 2`. The source (iri-xe-3s-book) only shows
  `match internal` ("Sets the device to redistribute OSPF internal routes") — the "all" is an
  unsupported inversion. (Line 83's "must supply a metric" is DOWNGRADED to a caveat: the book
  itself states verbatim "any protocol can redistribute routes … as long as a default metric is
  configured" — legitimately extracted, but the book's blanket rule binds for RIP/EIGRP targets,
  not BGP, where MED defaults to the IGP metric. Add a Contradictions/caveats note.)

Verified 2026-07-02 against the original harvest PDFs (irg/iro/iri/lanswitch xe books): the BGP
book states 60 s keepalive / 180 s hold in ≥4 places; none of the five PDFs contain any ISSU
content (`config_system_management_chapter_011001.pdf` is a wireless-controller chapter) — the
wrong claims are exactly the ones absent from the sources, filled in at the edge of
`tiers-covered: [conceptual]` without `(inferred)` tags.

The H1 banner fired on two of these pages — and didn't stop a single wrong number. Root cause:
`lint.py`'s citation-grounding check **excludes CLI flags/commands as too noisy** (CLAUDE.md, LINT
section), which is exactly the identifier class that leaked.

**Fix:** correct the three pages, and narrow the CLI exclusion — a `show ...` command or SKU-shaped
token absent from the domain's entire reference tier should at minimum warn on `questions/` pages.

### B2 — AD and cisco-ios-xe cite nothing their tooling can resolve

Both are declared `shape: corpus-backed` (`_meta/taxonomy.md:106,:115`) with real reference tiers
(236 and 173 notes), yet **0/69 AD pages and 0/17 cisco pages carry a `## Sources` block** — AD
cites only `web:`/`ref:`, cisco only `note:`. Consequences cascade: `crosslink` resolves nothing →
the tkg has zero CITES edges for these domains → `expand` (the multi-hop recall fix) rescues
nothing → the eval confirms it (AD graph-assist: 3/7 → 3/7, zero lift, vs keycloak 6/12 → 10/12).

**Fix:** re-cite AD/cisco claims against `reference/<domain>/` notes with `kb:` tokens and run
`crosslink --apply` — or honestly flip the taxonomy to notes-first and accept the reference tiers
are dead weight.

## Major

### M1 — The tkg is not in the answer path

Only `wikikb/__main__.py` imports `wikikb.tkg`; `route`/`expand`/`kb`/the LangGraph query nodes
never consult it. The "version-aware citation filtering" that actually protects answers is one
line: `crosslink.resolve()` newest-primary-wins (`wikikb/build/crosslink.py:117`). The tkg itself
is a well-built reporting layer.

**Fix:** either wire `temporal-query` into QUERY step 2/3 (e.g. `expand --as-of`) or stop
describing the system as having version-aware answer filtering.

### M2 — No supersession; cumulative-only temporal queries

`temporal-query --as-of 26.2` filters `valid_from <= asof` (`tkg/tkg.py:206`) with `valid_until`
hardcoded None. A 26.6-era query happily returns 26.0-cited edges with no signal that a 26.4/26.6
note supersedes them. The "never infer supersession" rule (`tkg/model.py:28`) is honest but
over-cautious for the one case that *is* deterministic: the corpus holds the same guide at
26.2/26.4/26.6, so same-guide version succession is derivable without inference.

**Fix:** add a derived `superseded_by` edge attribute for same-family/same-guide successors —
that's fact, not fabrication.

### M3 — Temporal layer is single-domain

All 192 version-temporal edges are keycloak; `versions.py` knows only rhbk/rhsso. AD (Windows
Server FLs are dateable to the day from public Microsoft lifecycle data) and IOS-XE (release
trains) get nothing. Combined with B2, the "temporal + cross-domain knowledge graph" is in
practice a keycloak citation graph with 11 cross-domain links.

### M4 — Eval blind spots + red selftest

`_meta/eval/cases.jsonl`: 12 keycloak, 7 AD, **0 cisco, 0 openshift**. The scoreboard
(r@10 47% → 74% with graph+closure) says nothing about half the domains. Selftest is 43/48:
`index.cisco-ios-xe.md` and the global router are stale (missing
`questions/redistribute-ospf-into-ebgp.md`), and all four eval goldens have drifted (token-count
only; recall lines intact).

**Fix:** ≥5 cases per missing domain, `python3 -m wikikb index`, regenerate goldens.

### M5 — `dpop.md` vs `dpop-sender-constraining.md` duplication

Same RFC 9449 concept split across two entities; 19 vs 20 inbound links, 8 pages link *both*, and
the two MOCs disagree on which is canonical (`sso-implementation-review.md:51` vs
`oidc-client-best-practices.md`). One of the 6 eval misses (the DPoP token-binding case) is
plausibly this split diluting the anchor.

**Fix:** `dpop.md` (the corpus-backed slug) absorbs the spec detail; `dpop-sender-constraining`
becomes an alias; repoint links.

### M6 — `entities/ad-functional-levels.md` contradicts itself

Line 40: "No new FLs have been added since WS 2016 (as of 2026)" — directly contradicted by the
page's own WS-2025 FL column (:32) and "raise FFL to 2025" (:28). WS 2025 *did* introduce the
first new FL since 2016. An SRE reading line 40 concludes a 2025 DFL doesn't exist.

**Fix:** "No new FLs were added by WS 2019 or 2022 (both cap at the WS 2016 level); WS 2025
introduces the next new functional level."

### M7 — 124/269 pages carry `provenance: needs-review`

The largest lint class (46% of the wiki). The confidence gate's H2/H3 arms and the Provisional arm
are numerically meaningless on these pages because the counts were never assigned.

**Fix:** run the per-claim provenance pass (INGEST step 6) at scale.

### M8 — `symptoms:` frontmatter unbuilt where it matters most

27 AD pages have it; keycloak has 3 (questions only), cisco 0, openshift 1. CLAUDE.md calls this
"the SRE agent's lookup surface + the future embedding target." The MOC tables already contain the
symptom strings (`sso-implementation-review.md` has 53 rows).

**Fix:** lift the MOC-table symptom strings into per-page `symptoms:` frontmatter.

## What's genuinely strong (don't fix what isn't broken)

- Keycloak and AD content quality is high — 16/18 spot-checked pages clean, and every checked
  `kb:` citation actually contains its claim (no fabricated citations in the corpus-backed domain).
- Router precision is 100% with zero confident-wrong routes (15/19 confident, 4 graceful abstains
  on genuinely cross-domain cases).
- Chunk granularity is healthy: no page >282 lines, no wall-of-text pages, one 12-line fragment
  (`questions/phantom-incident-from-double-encoded-alertmanager-webhook-ob.md`).
- Zero lint hard errors, zero orphans, zero broken links, zero stale stubs.
- The `bgp` / `bgp-path-attributes` / `bgp-route-reflector` decomposition is correct, not
  duplication.
- All four domains have a review MOC with a machine-readable symptom→cause table (53/84/56/35 rows).
- The tkg's honesty engineering (R1–R4, precision-tagged errata dates, the `reference/`-only
  assertion) is real in the code, not just the docs. The build is deterministic: 390 nodes,
  2,423 edges, 192 version-temporal.

## The 3 highest-leverage changes

1. **Re-cite AD + cisco against their reference tiers and run `crosslink --apply` (B2).** One
   mechanical pass unlocks four things at once: graph-expand recall for 86 pages (the eval shows
   exactly this lift for keycloak), CITES edges for the tkg, provenance-trace, and the
   citation-grounding backstop — which is currently blind in the two domains where fabrication
   actually occurred. Everything downstream of the graph is starved until this lands.
2. **Fix the filed fabrications and close the CLI-token lint hole (B1 + M6).** Four pages, then
   one lint change. The wiki's core promise is that cached answers are grounded; three cisco
   questions and one AD entity currently violate it, and the exclusion that let them through will
   let the next one through too.
3. **Make the eval cover what the wiki claims to cover (M4).** Add cisco + openshift cases,
   regenerate the stale indexes and goldens, get selftest to 48/48. Until then every quality
   number is a keycloak number wearing a four-domain badge.

Deliberately *not* in the top 3: wiring the tkg into QUERY (M1). It's the most interesting gap,
but with only 11 cross-domain links and single-family temporal coverage, the graph doesn't yet
contain enough signal to change answers — fix the inputs (change 1) before plumbing the output.

## Coverage gaps by domain (ranked by SRE value)

### Keycloak/RHBK (175 pages) — deep, but skewed to config/security concepts over day-2 ops
1. Backup & restore / DR runbook (PostgreSQL strategy, realm-export-at-scale, PITR) — absent.
2. Database-side HA (Aurora/Patroni failover vs the JDBC layer, read replicas) — the
   `keycloakhighservererrorrate` post-mortem was a slow-DB incident with no cause page to link.
3. Zero-downtime RHBK minor-upgrade runbook (only the operator angle exists).
4. Alert thresholds / PrometheusRule page (what to page on: JGroups split, cache-owner loss, DB
   pool exhaustion, token-endpoint p99).
5. Infinispan/session-store sizing and JGroups troubleshooting as an entity.
6. CVE/RHSA patch process.
7. Large-realm bulk operations topic.

### Active Directory (69 pages) — excellent design/security coverage; thin on live troubleshooting
1. Replication *troubleshooting* (repadmin/dcdiag runbook, lingering objects, tombstone lifetime,
   events 1388/1988/2042).
2. DFSR SYSVOL health, JRNL_WRAP, D2/D4 authoritative restore.
3. Kerberos ticket-error triage (KRB_AP_ERR_MODIFIED, duplicate SPNs).
4. Trusts (types, SID filtering, secure-channel resets, nltest) — absent entirely.
5. Routine single-DC system-state restore (short of full forest recovery).
6. w32tm time-sync diagnostics.
7. Entra Connect / hybrid sync (possibly deliberate scope).

### Cisco IOS-XE (17 pages) — coherent but tiny; a "CCNP routing chapter," not an SRE domain
1. HA/redundancy: StackWise Virtual, SSO/NSF, ISSU, GR — the deep question page itself says the
   entries don't exist (`c9500-issu-svl-blackhole-nsf-gr.md:125`).
2. First-hop redundancy (HSRP/VRRP) — absent.
3. Platform triage (show tech, crash cause, CoPP, interface errors/optics, syslog signatures).
4. EIGRP — referenced repeatedly, no page.
5. Modern STP (RSTP/MST, PortFast/BPDU Guard) and switchport-style trunking.
6. Upgrade/install runbooks (install vs bundle mode, rollback) — what the ISSU question needed.

### OpenShift (8 pages) — a seed skeleton, not yet a usable SRE domain
1. ClusterOperator / cluster-upgrade triage (Degraded, upgrade stuck, MCP rollouts).
2. Node lifecycle (NotReady, drain/cordon, kubelet pressure evictions).
3. Storage (PVC Pending, StorageClass, ODF) — the MOC names the symptom, no entity exists.
4. etcd health & backup/restore — the single most SRE-critical OCP topic; absent.
5. Ingress/router beyond Route basics (sharding, cert rotation, 503 classes).
6. Workload controllers & probes (Deployment/StatefulSet, HPA, quotas).
7. Image/registry (ImagePullBackOff, disconnected mirroring ICSP/IDMS). Note: the repo's own
   `openshift-gitops` skill covers much of this and the wiki hasn't absorbed any of it.

  `reference/cisco-ios-xe/` notes — verify against the corpus before editing, per the wiki's own
  rules.

  on whether the reference tiers are meant to be the citation authority — owner's call; both fixes
  are legitimate.

  is above but it was not accuracy-reviewed.
