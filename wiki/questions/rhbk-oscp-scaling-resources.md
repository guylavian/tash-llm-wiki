# How to scale RHBK on OpenShift — StatefulSet resources and PostgreSQL database resources

**Question:** I have an RHBK deployment on OpenShift. How do I scale the StatefulSet resources (CPU/memory for the RHBK pods) and the PostgreSQL database resources, and what are the best practices?

**Answer:** You have three resource domains to size: (1) RHBK pod CPU/memory via `spec.resources`, (2) replica count via `spec.instances` (optionally with HPA), and (3) the PostgreSQL database instance and connection pool. The detailed answer is above in this conversation body — see [[questions/rhbk-oscp-scaling-resources|the full answer]].

## Key takeaways

1. **Pod resources** — Default memory limit is 2 GiB (≈70% heap + 300 MB non-heap). The HA Guide blueprint uses requests 2 vCPU/1250M, limits 6 vCPU/2250M, tested at ~410 req/s across 3 pods.
2. **CPU sizing model** — ~1 vCPU per 15 password logins/s, per 120 client credentials/s, per 120 refresh tokens/s, plus 150% headroom.
3. **Replicas** — Set `spec.instances: 3` (tested baseline). Minimum 2 for HA. HPA against CPU at 80% target works. Vertical autoscaling is NOT recommended.
4. **DB connection pool** — Set `poolInitialSize=poolMinSize=poolMaxSize=30` (equal sizing preserves statement caching).
5. **DB instance sizing** — Per 100 req/s: budget ~1400 write IOPS and 0.35–0.7 vCPU. E.g., `db.t4g.large` (2 vCPU) for cost-efficiency, `db.t4g.xlarge` (4 vCPU) for fast peak response.
6. **The Operator does NOT manage the DB** — you must provision PostgreSQL separately (managed service or self-managed StatefulSet with synchronous replication for HA).
