# What are security principals in Active Directory?

**A security principal is any entity the operating system can authenticate — a user account, a computer account, or a security group — each assigned a unique [[security-identifiers-sid]] at creation that it keeps for its entire lifetime and is never reused.**

The authorization flow turns SIDs into access decisions: at sign-in, the Local Security Authority (LSA) builds an **access token** containing the user's SID, the SIDs of their groups, and their user rights. When a thread accesses a securable object, the OS compares the token's SIDs against the access control entries (ACEs) in the object's security descriptor.

Two storage scopes exist:
- **Domain principals** — Active Directory objects replicated among DCs.
- **Local principals** — stored in the SAM database on a single computer.

Three kinds of principal:
- **User accounts** — a person or dedicated service account (see [[default-user-accounts]]).
- **Computer accounts** — lets a domain-joined machine authenticate on the network.
- **Security groups** — collect principals for unified permission assignment (see [[security-groups]]).

A related concept is **special identity groups** (Everyone, Authenticated Users, etc.) — dynamic groups whose membership the OS controls (see [[special-identity-groups]]).
