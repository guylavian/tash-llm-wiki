# What does the `KC_HOSTNAME_ADMIN_STRICT` environment variable do?

**`KC_HOSTNAME_ADMIN_STRICT` does not exist.** It is a fabrication — no such environment variable is defined in any RHBK 26.x or upstream Keycloak release.

The two real options whose names may have been conflated:

- **`KC_HOSTNAME_ADMIN`** (`--hostname-admin`) — sets a separate hostname for the Admin Console and Admin REST API, e.g. `--hostname-admin https://admin.my.keycloak.org:8443`. Does not restrict access to admin endpoints on the frontend URL (ref: [[hostname-v2]]).
- **`KC_HOSTNAME_STRICT`** (`--hostname-strict`) — when `false`, allows fully dynamic URL resolution from request headers. Default is `true` in production (`kc.sh start`), and either `--hostname` or `--hostname-strict false` must be set explicitly (ref: [[hostname-v2]]).

There is no combined `admin-strict` variant. To run separate SSO and admin hostnames behind a reverse proxy, see [[separate-sso-admin-hostnames]]: the documented pattern is to disable `hostname-strict` and omit the explicit `hostname`/`hostname-admin` config, letting the reverse proxy handle routing.
