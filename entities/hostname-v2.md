# Hostname v2 configuration

**RHBK requires an explicit `hostname` (or `hostname-strict false`) in production so it never derives its public URLs dynamically from a `Host` header — a security measure against issuer/redirect spoofing.**

Hostname v2 is gated by the `hostname:v2` feature (enabled by default in RHBK 26.x). It controls how the **frontend**, **backend (backchannel)**, and **administration** base URLs are formed — which drives token issuer values, OIDC Discovery (`/.well-known/openid-configuration`), redirect URIs, and email action links.

## Key options

- `--hostname my.keycloak.org` — sets the frontend hostname. Scheme/port are filled in (e.g. `https://my.keycloak.org:8443`).
- `--hostname https://my.keycloak.org[:123][/auth]` — a **full URL** fixes scheme, port, and context path (needed when behind a proxy on `443`/a sub-path).
- `--hostname-admin https://admin.my.keycloak.org:8443` — exposes the Admin Console/REST on a separate host. (Note: this does **not** block the Admin REST API on the frontend URL — restrict it at the reverse proxy — *inferred* hardening guidance, not a built-in guarantee.)
- `--hostname-backchannel-dynamic true` — lets backend/backchannel URLs resolve dynamically from request headers while the frontend stays the fixed public URL. Requires `hostname` to be a full URL. Default `false` (backchannel == frontchannel).
- `--hostname-strict false` — allow fully dynamic URL resolution (default in `start-dev`; must be explicit in production if `--hostname` is not set).
- `--hostname-debug true` — enables a troubleshooting endpoint.

`hostname`/`proxy` options only change the URLs RHBK advertises (static resources, OIDC endpoints, redirect URIs); they do **not** change the ports the server listens on — use the `http-*`/`https-*` options for that.

## Resolution sources

URLs come from: dynamic request data (`Host`, scheme, port, context path), proxy headers (`Forwarded` / `X-Forwarded-*`), or hardcoded config (`hostname`, `hostname-admin`, realm frontend URL). See [[reverse-proxy-configuration]] for how `proxy-headers` interacts with this.

## Validations

- `hostname` and `hostname-admin` must be full URLs (scheme + host); port validated only if present.
- In the production profile (`kc.sh start`), either `--hostname` or `--hostname-strict false` must be set explicitly (not required in `start-dev`).
- If `--hostname` is not configured: `hostname-backchannel-dynamic` must be `false` and `hostname-strict` must be `false`.

## Contradictions / caveats
- This is the **v2** model used throughout RHBK 26.0–26.6 (quoted from 26.4). The older v1 options (`hostname-url`, `hostname-path`, `hostname-strict-backchannel`, `frontend-url`, etc.) belong to removed v1 and should not be mixed in.
- In v1, `hostname-strict-backchannel=true` (env `KC_HOSTNAME_STRICT_BACKCHANNEL`) forced backchannel URLs to match the frontend hostname; in v2, this is the default (`hostname-backchannel-dynamic=false`).
- Edge TLS termination: combine `--hostname https://...` with `--http-enabled true` so the proxy can talk HTTP on `8080` while clients see HTTPS.
