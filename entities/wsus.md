# Windows Server Update Services (WSUS)

**WSUS lets administrators fully manage the distribution of Microsoft Update
content to computers on their network from an internal server, instead of every
client reaching out to Microsoft Update directly.**

## Body

WSUS is **deprecated — it's no longer adding new features** — but Microsoft
continues to support it in production and ships security/quality updates for it
per the product lifecycle.

At least one WSUS server (the **upstream server**) must reach Microsoft Update;
other WSUS servers can synchronize from it. A **hierarchy** links upstream and
downstream servers in one of two modes:
- **Autonomous mode** (default, distributed administration) — downstream servers
  share updates from the upstream server but manage their own approvals and
  computer groups independently.
- **Replica mode** (centralized administration) — downstream servers inherit
  update approvals and computer groups from the upstream server; not administered
  separately.

**Storage:** WSUS needs a database — either **Windows Internal Database (WID)**
(the default; Windows-authentication only, no admin UI) or **SQL Server**
(Standard/Enterprise/Express). SQL Server is required for a **Network Load
Balancing (NLB)** WSUS deployment. Update files themselves can be stored locally
on the WSUS server (default; saves internet bandwidth) or fetched by clients
directly from Microsoft Update servers.

**Sizing (minimum):** 1.4 GHz x64 CPU (2 GHz+ recommended), an extra 2 GB RAM
beyond other server needs, 40 GB+ disk (plus 10 GB per Windows version/architecture
for **Unified Update Platform (UUP)** content), 100 Mbps+ NIC — sized for clients
synchronizing every 8 hours.

**Computer groups** target updates to subsets of clients via **server-side
targeting** (manual assignment) or **client-side targeting** (Group Policy/registry
self-assignment); nested group priority is depth-based, and Install actions/earlier
deadlines override Uninstall/no-deadline/later-deadline actions.

Since **March 28, 2023**, WSUS supports **UUP** updates for Windows 11 21H2+
clients — this requires either a listed cumulative update on the WSUS server or
manually registering the `.wim`/`.msu` MIME types in IIS, or Windows 11 22H2+
clients can fail to install updates.

## Contradictions / caveats

Microsoft recommends **not deeply nesting** a WSUS hierarchy (untested beyond
five levels; each level adds propagation delay), and recommends a **hub-and-spoke**
network topology over a deep hierarchical one for performance.
