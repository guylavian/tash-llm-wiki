# Service Level Indicators and SLOs (PromQL)

**RHBK ships example availability, latency, and error SLIs/SLOs computed from `up` and `http_server_requests_seconds_*` with PromQL, to track the login/refresh/logout user journey against targets.**

## Service definition

The reference service is: *as a user I want to log in, refresh my token, and log out.* The example SLOs (tailor to your case):

| Characteristic | Example SLO | Source |
|---|---|---|
| Availability | up 99.9% / month (~44 min downtime) | Prometheus `up` |
| Latency | 95% of auth requests < 250 ms over 30d | `http_server_requests_seconds_bucket` (`le="0.25"`) |
| Errors | server-error rate < 0.1% over 30d | `http_server_requests_seconds_count{outcome="SERVER_ERROR"}` |

## Prerequisites

- Metrics enabled (see [[server-metrics-endpoint]]).
- `http-metrics-slos` set to the latency threshold(s) to bucket (e.g. `250`); optionally `http-metrics-histograms-enabled=true` for extra buckets.
- A PromQL-capable monitoring system (Prometheus).

## Example PromQL

**Availability** (uses subqueries; in Grafana swap `30d:15s` for `$range:$interval`):
```
count_over_time(sum(up{container="keycloak",namespace="$namespace"} > 0)[30d:15s])
/ count_over_time(vector(1)[30d:15s])
```

**Latency** — fraction of auth requests faster than 250 ms (requires `http-metrics-slos` to contain `250`):
```
sum(rate(http_server_requests_seconds_bucket{uri=~"/realms/{realm}/protocol/{protocol}.*|/realms/{realm}/login-actions.*", le="0.25", container="keycloak", namespace="$namespace"}[30d])) without (le,uri,status,outcome,method,pod,instance)
/ sum(rate(http_server_requests_seconds_count{uri=~"...login-actions.*", container="keycloak", namespace="$namespace"}[30d])) without (le,uri,status,outcome,method,pod,instance)
```

**Errors** — filter `outcome="SERVER_ERROR"` over the same auth URIs.

These SLI graphs sit on top of the troubleshooting [[grafana-dashboards]].

## Contradictions / caveats

- The SLO target values are **examples only** — agree real targets with stakeholders.
- Queries are Kubernetes/Prometheus blueprints; adapt label selectors (`container`, `namespace`, `pod`) for bare-metal — see [[grafana-dashboards]] for relabel config.
- For alerting/live dashboards, convert heavy subquery expressions into recording rules to limit resource use (inferred — general PromQL practice, not stated in the cited chapter).
