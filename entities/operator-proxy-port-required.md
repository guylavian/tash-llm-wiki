# RHBK Operator fails "Proxy port is required!"

**Symptom → cause → fix for the operator pod refusing to start behind a cluster-wide proxy that omits the port.**

## Body
**Symptom.** The RHBK Operator pod fails to start with
`java.lang.IllegalArgumentException: Failure in creating proxy URL. Proxy port is required!`
from `HttpClientUtils.getProxyUri`.

**Cause.** The OpenShift cluster-wide `Proxy` CR has `httpProxy` / `httpsProxy`
values with **no port number**. The fabric8 Kubernetes client used by the
operator requires an explicit proxy port (upstream keycloak/keycloak#30165).

**Fix.** Add an explicit port to the cluster `Proxy`:
```yaml
httpProxy:  http://myproxy:port
httpsProxy: https://myproxy:port
```
Keep `noProxy` and `trustedCA` as configured, then let the operator reconcile.

Applies to the RHBK Operator on OpenShift with a cluster-wide `Proxy`
(HTTP_PROXY/HTTPS_PROXY).

## Contradictions / caveats
This is the *cluster* `Proxy` CR, not the Keycloak CR — fixing proxy headers on
the Keycloak side (gated kb:7104900) is a separate concern.
