# ConfigMgr PowerShell Module (ConfigurationManager)

**Windows PowerShell manages a Configuration Manager hierarchy through the `ConfigurationManager`
module, whose cmdlets operate against a site-scoped `CMSite` PSDrive rather than the filesystem.**

## Body

### Launching

The easiest path is **Connect via Windows PowerShell** from the ConfigMgr console (blue-rectangle
arrow, top-left) — this auto-connects a PSDrive for the current site and starts the session under
the **AllSigned** execution policy for the Process scope (change with `Set-ExecutionPolicy
-ExecutionPolicy RemoteSigned -Scope Process` if that's too strict for the environment).

Alternatively, import the module manually into an existing PowerShell session:

- Default module path: `C:\Program Files (x86)\Microsoft Endpoint
  Manager\AdminConsole\bin\ConfigurationManager.psd1`.
- Starting in version 2111, console install adds this path to the `PSModulePath` environment
  variable, so `Import-Module ConfigurationManager` (by name alone) works without a full path.
- The `SMS_ADMIN_UI_PATH` environment variable is also usable: `Set-Location
  "$env:SMS_ADMIN_UI_PATH\..\"`.
- Verify which module/version actually loaded with `(Get-Module -Name
  ConfigurationManager).Version` and `.Path` — importing a stale copy from another folder on the
  same machine is the documented pitfall.

### Connecting to a site

If it's the first time importing the module on a machine, create the site PSDrive manually, e.g.
`New-PSDrive -Name "ABC" -PSProvider "CMSite" -Root "siteserver.contoso.com" -Description
"Primary site"`, then `Set-Location ABC:` to run cmdlets against that site. `Get-CMSite` confirms
the module loaded and is connected correctly, returning site server name, install directory, site
name, and version.

### Version and update-help notes

Starting in version 2103, the module requires **.NET 4.7.2+**. All currently supported
Configuration Manager current-branch versions support PowerShell 5.1, and the module also
supports PowerShell 7 (side-by-side with 5.1). `Update-Help` refreshes cmdlet help from
`pshelpprod.blob.core.windows.net` (requires internet access) — but because of a change in how
updateable content is published starting with version 2103, **don't run `Update-Help` against a
version 2010 site**; update the site to 2103+ first.
