# Using a vault

**RHBK ships two Vault SPI implementations — a plaintext file-based vault (ideal for Kubernetes/OpenShift mounted secrets) and a Java KeyStore-based vault — referenced from realm config via `${vault.<name>}` placeholders.**

## What can use a vault

From the Admin Console: the SMTP mail server password, the LDAP bind credential ([[ldap-user-federation]]), and the OIDC identity provider client secret.

## Enabling (build option)

```
bin/kc.sh build --vault=file        # file-based
bin/kc.sh build --vault=keystore    # Java KeyStore-based
```

## File-based vault

- `--vault-dir=/my/path` — directory where secret files (e.g. mounted K8s secrets) live.
- Per-realm naming convention: file `${vault.<realmname>_<secretname>}`. With the default `REALM_UNDERSCORE_KEY` resolver, underscores within `<realmname>` and `<secretname>` are **doubled**, separated by a single underscore. Example: realm `sso_realm` + name `ldap_credential` → file `sso__realm_ldap__credential`.

## Java KeyStore vault

- Create entries with `keytool -importpass -alias <realm>_<alias> -keystore keystore.p12 -storepass <pw>` (stored as a PBE `SecretKeyEntry`).
- Start with `--vault-file=/path/keystore.p12 --vault-pass=<pw> [--vault-type=<type>]` (`vault-type` defaults to `PKCS12`).
- Reference with `${vault.realm-name_alias}`.

## Why use it

Avoids plaintext secrets in `keycloak.conf`/CLI. Recommended for the HTTPS keystore password ([[tls-configuration]]) and the DB password ([[database-configuration]]). Distinct from — but complementary to — the KeyStore **config source** that holds sensitive runtime *options* (`kc.<key>`); see [[config-sources-precedence]] (inferred cross-reference distinguishing two similarly-named mechanisms, not a single-source claim).

## Contradictions / caveats
- Behavior stable across RHBK 26.0–26.6 (quoted from 26.4). The file-based vault is plaintext-on-disk by design — protect the mount.
- Only the two built-in SPI implementations are documented here; the default key resolver is `REALM_UNDERSCORE_KEY` (others exist — see the Server Administration guide).
