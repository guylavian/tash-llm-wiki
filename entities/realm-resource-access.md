# Managing access to realm resources

**Each realm has a dedicated Admin Console; administrative authority is granted through client roles of the `realm-management` client (per-realm) and `admin`/`master` roles in the master realm (cross-realm).**

## How admin access works
Every realm gets its own Admin Console from which that realm is managed. The **master
realm** is special: accounts there can administer **multiple** realms. Within a realm,
administrative powers are expressed as **client roles of the `realm-management` client**
— for example `realm-admin` (full admin of that realm), `manage-clients`, `view-users`,
`create-client`. Assigning these roles (directly, via composite roles, or via groups —
see [[roles-and-groups]]) delegates fine-grained admin capability without granting
master-realm power.

The account a `kcadm.sh` session uses must hold the appropriate role (e.g. the
`realm-admin` role of `realm-management`) to invoke Admin REST operations — see
[[kcadm-cli]].

## Contradictions / caveats
- Bodies sourced are RHBK **26.0/26.4** ("Managing access to realm resources",
  Ch. 11 in 26.4). Fine-grained admin permissions have evolved across versions
  (26.0/26.2/26.4/26.6) — a newer Admin Permissions / Admin Fine-Grained Permissions
  model may apply; verify against your exact version.
- Prefer per-realm `realm-management` roles over master-realm accounts to follow least
  privilege (inferred recommendation; see [[security-hardening-checklist]]).
