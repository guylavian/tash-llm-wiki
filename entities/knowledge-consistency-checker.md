# Knowledge Consistency Checker (KCC)

**The KCC is a built-in process running on every domain controller that automatically generates and dynamically adjusts the Active Directory replication topology.**

## Body

The KCC builds replication routes by creating one-way **inbound** connection objects
on each DC (see [[site-links-and-replication-schedule]] for the objects' schedules).
It produces two *separate* topologies:

- **Intra-site (within a site):** connections between writable DCs form a
  **bidirectional ring**, with extra shortcut connections added in large sites to keep
  replication latency under three hops.
- **Inter-site (between sites):** a **layering of spanning trees** — one inter-site
  connection between any two sites per directory partition, generally with no shortcut
  connections. A single KCC instance per site creates the cross-site connections over
  the configured site links.

**Connection objects** it generates appear in AD Sites and Services as
`<automatically generated>`. An administrator can also create connections manually, or
modify an auto-generated one (which converts it to an administratively modified object
shown as a GUID); the KCC never touches manual or modified connection objects.

**Failover:** the KCC runs at intervals, reviews connection health, and if a partner
DC has failed it builds temporary connections to other available replication partners.
If *all* DCs in a site are unavailable, it creates connections to DCs in another site —
so sites route replication around network failures and offline DCs.

For Windows Server 2008 RODC hub-and-spoke deployments, the KCC adds rebalancing
("Random BH Loadbalancing Allowed", on by default) so adding a hub bridgehead can
redistribute branch connections (it does not for writable-DC topologies by default —
bridgehead selection is randomized only once when connections are first added)
(inferred — combining the connection-object and site-link notes).

## Contradictions / caveats

- The **intersite topology generator (ISTG)** — one role-holder DC per site — owns the
  inter-site topology specifically; the per-DC KCC owns intra-site. Site link bridges
  are evaluated for the ISTG's least-cost path computation (see
  [[site-links-and-replication-schedule]]).
- The KCC adapts to added/removed DCs, site moves, and changing costs/schedules
  automatically; manual connection objects opt out of that adaptation.
