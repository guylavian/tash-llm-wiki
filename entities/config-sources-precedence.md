# Configuration sources and precedence

**RHBK reads options from four sources; when the same option is set in more than one, the highest-priority source wins.**

Order of application (first = highest priority):

| Priority | Source | Format |
|---|---|---|
| 1 | Command-line parameter | `--<key-with-dashes>=<value>` (some have `-<abbr>`) |
| 2 | Environment variable | `KC_<KEY_WITH_UNDERSCORES>=<value>` |
| 3 | `conf/keycloak.conf` (or `--config-file=` file) | `<key-with-dashes>=<value>` |
| 4 | Java KeyStore config source | `kc.<key-with-dashes>` (value = password in KeyStore) |

Worked example for `db-url`: with `--db-url=cliValue` set, `cliValue` is used regardless of `KC_DB_URL`, `db-url=` in the file, or `kc.db-url` in the KeyStore. Remove the CLI flag and the env var wins, and so on down the list.

Related formatting facts:
- `keycloak.conf` can reference env vars: `db-url-host=${MY_DB_HOST:fallback}` (colon gives a fallback).
- Quarkus properties (`conf/quarkus.properties`) are a separate, mostly-unsupported escape hatch; where RHBK already maps a Quarkus property (e.g. `quarkus.http.port`), the RHBK value takes precedence.
- The KeyStore source is the recommended place for **sensitive** runtime options (e.g. `db-password`). Type defaults to `PKCS12`; secrets use the `PBE` algorithm.

## Contradictions / caveats
- This 4-source model and ordering is consistent across RHBK 26.0–26.6 (quoted here from
  26.4; only the 26.4 note was checked directly, so 26.0/26.2/26.6 consistency is
  inferred).
- Build options must **not** be stored in the KeyStore — they are persisted in plain text into the image. See [[build-vs-runtime-options]].
