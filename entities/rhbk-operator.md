# RHBK Operator (Keycloak CR)

**The OpenShift/Kubernetes operator that deploys and manages RHBK declaratively
via the `Keycloak` custom resource, installed through OLM.**

## How
- **Install:** via OLM from a catalog (a disconnected/air-gapped mirror is
  supported — see `ref:rhbk-operator.md` for the ImageContentSourcePolicy /
  catalog-mirror note).
- **Deploy:** apply a `Keycloak` CR specifying hostname, DB connection
  (`usernameSecret` / `passwordSecret` referencing a Kubernetes Secret), TLS,
  ingress, and `image` / `startOptimized` for pre-built images.
- **Realm bootstrap:** a `KeycloakRealmImport` CR imports a realm at deploy time.
- **Admin bootstrap:** the temporary admin is wired through a Secret, not raw CLI
  flags — see [[kc-bootstrap-admin]].
- **Advanced tuning:** `additionalOptions`, truststores, `podTemplate`,
  scheduling, and secret references on the CR (`ref:rhbk-operator.md`).

## Caveats
- DB Secret pattern (`oc create secret generic keycloak-db-secret ...`) is the
  documented approach in the HA guide's single- and multi-cluster chapters.
- For multi-site, the operator is paired with an external Infinispan/Data Grid —
  see [[ha-cross-site]].
- Use a **custom pre-optimized image** for air-gapped registries so the server
  doesn't try to re-build/augment at start.
