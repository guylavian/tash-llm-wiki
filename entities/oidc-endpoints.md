# OIDC Endpoints (well-known discovery)

**The standard set of OpenID Connect / OAuth2 endpoints RHBK exposes per realm,
all discoverable from the `.well-known/openid-configuration` document.**

## Discovery
`/realms/{realm}/.well-known/openid-configuration` — lists every endpoint and
config option. RP libraries can bootstrap entirely from this; otherwise list
endpoints individually.

## The endpoints (relative to `/realms/{realm}`)

| Endpoint | Path | Notes |
|---|---|---|
| Authorization | `/protocol/openid-connect/auth` | Authenticates the end-user via browser redirect |
| Token | `/protocol/openid-connect/token` | Exchange code or credentials for tokens; refresh; also the token-exchange grant target |
| Userinfo | `/protocol/openid-connect/userinfo` | Standard claims; bearer-token protected |
| Logout | `/protocol/openid-connect/logout` | See [[oidc-logout]] |
| Certificate (JWKS) | `/protocol/openid-connect/certs` | Realm public keys as JWK; used for offline [[oidc-token-validation]] |
| Introspection | `/protocol/openid-connect/token/introspect` | Active state of a token; **confidential clients only** |
| Dynamic Client Registration | `/clients-registrations/openid-connect` | See [[client-registration-service]] |
| Token Revocation | `/protocol/openid-connect/revoke` | Revokes access *and* refresh tokens; revoking a refresh token also revokes user consent |
| Device Authorization | `/protocol/openid-connect/auth/device` | Device + user codes; public or confidential |
| Backchannel (CIBA) | `/protocol/openid-connect/ext/ciba/auth` | Returns `auth_req_id`; **confidential clients only** |

## Introspection as JWT
Calling introspection with header `Accept: application/jwt` (instead of
`application/json`) can return an extra `jwt` claim carrying the full JWT access
token — useful when the original token was a lightweight access token. Requires
enabling **Support JWT claim in Introspection Response** on the client's advanced
settings.

## Contradictions / caveats
- Endpoint paths are stable across RHBK 26.0–26.6. The set of endpoints
  advertised in discovery can grow with new features (e.g. PAR, MCP scopes).
- Introspection and CIBA are restricted to confidential clients — see
  [[client-authentication-methods]].
