# Migrating RH-SSO 7.6 client adapters & OIDC/SAML apps

**Several RH-SSO 7.6 Java client adapters are no longer released with RHBK;
re-platform applications onto the standards-based OIDC/SAML support in their own
stack, and account for protocol/client-setting changes.**

## Body

### Dropped adapters
No longer released starting with RHBK:
- JBoss EAP 6.x OIDC adapter
- JBoss EAP 7.x OIDC adapter
- Spring Boot adapter
- Red Hat Fuse adapter

Recommended replacements:
- **JBoss EAP 8.x** — use the EAP-native OpenID Connect client (no extra
  dependency). Remove `EAP_HOME/modules/system/add-ons/keycloak/` and configure
  the native OIDC client; its config schema mirrors the old `keycloak.json`.
- **JBoss EAP 7.x** — no RHBK support; existing apps keep using RH-SSO 7.6
  adapters under maintenance support.
- **JBoss EAP 6.x** — end of maintenance; unsupported by both products.
- **Spring Boot** — use Spring Security's OAuth2/OIDC support.

**Bridge guarantee:** RH-SSO 7.6 adapters are **supported in combination with an
RHBK 26.x server**, so you can migrate the server first and re-platform apps
later.

### Protocol / client-setting changes
- **Access Type removed** from OIDC clients in Admin Console v2. Reproduce:
  *Bearer-only* = client with no flow enabled; *Public* = client auth disabled +
  ≥1 flow; *Confidential* = client auth enabled + ≥1 flow. `bearerOnly`/
  `publicClient` JSON flags still work via REST/import.
- **Custom-scheme redirect URIs** must now be explicitly matched (e.g.
  `custom:/test*`); a bare `*` no longer covers non-`http(s)` schemes.
- **`client_id` param** supported on the OIDC RP-Initiated Logout endpoint.
- **Valid Post Logout Redirect URIs** added; `+` reuses the Valid Redirect URIs
  set (default on migration for backwards compatibility).
- **UserInfo endpoint:** errors now RFC 6750-compliant (`WWW-Authenticate`
  challenge instead of JSON fields); access token must carry `openid` scope (else
  `403`); disabled users yield `invalid_token`.
- **Service Account Client ID mapper:** claim renamed `clientId` → `client_id`
  (OAuth2-compliant); the `clientId` userSession note still exists.
- **`iss` auth-response param** (RFC 9207) now added by default. Older adapters
  may choke on it — disable per client via *OpenID Connect Compatibility Modes →
  Exclude Issuer From Authentication Response*.

## Upstream / OSS best practice (upstream)
Confirms and extends the RHBK guidance — the same adapter removal happened
upstream at **Keycloak / RHBK 22.0**, and the upstream rationale is the direction
to follow:
- The Java OIDC client adapters were dropped because **OIDC is now natively
  available across the Java ecosystem** — use the platform's own support rather
  than a Keycloak-specific adapter. Recommended replacements by stack: **EAP 8.x
  native OIDC**, **Spring Security** (`spring-boot-starter-oauth2-client` /
  `-resource-server`), **Quarkus OIDC** (`quarkus-oidc`). See
  [[client-libraries-by-stack]].
- **Adapters and server are now decoupled** (separate release cadences): upgrade
  the **server first**, then adapters. Adapter 6.x/7.x is *not* supported by RHBK.
  (inferred)
- The **keycloak-js** JavaScript adapter is **not** among the dropped adapters and
  remains the supported browser option. (inferred)
