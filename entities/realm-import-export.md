# Realm import / export

**Mechanisms for moving realm configuration into RHBK — partial import of an exported realm JSON via the Admin Console / `partialImport` endpoint, versus boot-time export/import for full backups.**

## Two kinds of export — they are not interchangeable
- **Admin Console export files are NOT suitable for backups or transfer between
  servers.** Only **boot-time exports** are suitable for backups or server-to-server
  data transfer (per the Configuring realms chapter).

## Partial import via kcadm.sh
Import an exported `realm.json` into an existing realm:
```
kcadm.sh create partialImport -r demorealm2 -s ifResourceExists=FAIL -o -f demorealm.json
```
`ifResourceExists` controls collisions: `FAIL`, `SKIP`, or `OVERWRITE`. If the target
realm does not exist yet, create it first:
```
kcadm.sh create realms -s realm=demorealm2 -s enabled=true
```
You can also create a whole realm from a JSON document with
`kcadm.sh create realms -f demorealm.json` (or via stdin `-f -`). See [[kcadm-cli]].

## Contradictions / caveats
- Bodies sourced are RHBK **26.0**; the `partialImport` flow and the
  "Admin Console exports are not for backups" caveat appear consistently in 26.2/26.4
  primary results.
- The CLI `partialImport` covers the resources serialized in the export; for a complete
  realm backup use the server's boot-time export/import (covered in the server
  configuration material, outside this guide's scope).
