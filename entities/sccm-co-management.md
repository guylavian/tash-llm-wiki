# SCCM Co-management

**Co-management is one of the primary ways to cloud-attach an existing Configuration Manager
deployment: it lets a Windows device be managed concurrently by Configuration Manager and
Microsoft Intune, with authority for individual workloads switched to Intune at your own pace.**

## Body

### What it enables

A Windows device that has the Configuration Manager client *and* is Intune-enrolled gets the
benefits of both services. You choose which workloads (if any) to switch from Configuration
Manager to Intune authority; ConfigMgr keeps managing every workload you don't switch, plus every
ConfigMgr feature co-management doesn't cover. You can also **pilot** a workload on a separate
collection of devices before switching a larger group. (Co-management is distinct from
**coexistence** — managing with ConfigMgr plus a third-party MDM — which lacks the
conflict-avoidance orchestration co-management provides between ConfigMgr and Intune.)

### Paths to co-management

Two main paths: **existing Configuration Manager clients** — set up hybrid Microsoft Entra ID and
enroll already-managed Windows devices into Intune; or **new internet-based devices** — devices
that join Microsoft Entra ID and auto-enroll into Intune, then install the ConfigMgr client to
reach co-management.

### Workloads and enabling

Workloads you can individually switch include compliance policies, Windows Update policies,
resource access policies, and Endpoint Protection — switching is not all-or-nothing, and a
workload can be switched back to Configuration Manager later, though switching back can leave
side effects behind (e.g. Windows/Office versions installed by Intune remain at that version).
Since Configuration Manager version 2111, the **Cloud Attach Configuration Wizard** streamlines
enabling co-management with recommended defaults or customizable cloud-attach features, and
includes a built-in **Co-management Eligible Devices** collection. The **pilot group** referenced
throughout the co-management UI is just a collection containing a subset of devices, used for
initial testing with no time limit before (optionally) rolling a workload out to all
Configuration Manager devices.
