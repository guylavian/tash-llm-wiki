# `scheduling`

**The `spec.scheduling` stanza on the [[keycloak-cr]] — standard Kubernetes
placement controls for the server Pods.**

Exposes `affinity`, `tolerations`, `topologySpreadConstraints`, and
`priorityClassName`:

```yaml
spec:
  scheduling:
    priorityClassName: custom-high
    affinity:
      podAffinity:
        preferredDuringSchedulingIgnoredDuringExecution: [...]
    tolerations:
      - key: "some-taint"
        operator: "Exists"
        effect: "NoSchedule"
    topologySpreadConstraints:
      - maxSkew: 1
        topologyKey: kubernetes.io/hostname
        whenUnsatisfiable: DoNotSchedule
```

## Defaults

If you specify **no** custom affinity, Pods get **same-zone affinity** and
**same-node anti-affinity** — improving availability while avoiding high-latency
cross-zone cache-cluster traffic ([[distributed-caches]]). A custom affinity or
topology spread constraint replaces these defaults.

## Contradictions / caveats

- Defaults apply to **server Pods only**. From **26.6**, realm-import and update
  Jobs inherit `scheduling` from the CR; that Job inheritance is not documented in
  the earliest streams.
