# Themes & theme SPI

**RHBK themes customize the look of user-facing and admin pages via Freemarker templates, message bundles, stylesheets and `theme.properties`; theme behavior itself is pluggable through the Theme Selector and Theme Resource SPIs.**

## Theme types

Account, Admin, Email, Login, Welcome. All except Welcome are selected per realm in **Realm Settings → Themes** in the admin console. The Welcome theme is server-wide and set with `kc.sh start --spi-theme-welcome-theme=custom-theme`. To theme the master admin console, set the Admin Console theme on the `master` realm.

## Creating a theme

A theme is a directory under the server's `themes/` dir; the directory name is the theme name. Inside it, create a subdirectory per type (e.g. `themes/mytheme/login`), each with a `theme.properties`. A theme consists of HTML Freemarker templates, images, message bundles, stylesheets, scripts, and properties.

Almost always **extend** an existing theme rather than replacing every page. `theme.properties` keys:
- `parent` — theme to extend (e.g. `base` or `keycloak`)
- `import` — pull resources from another theme (e.g. `common/keycloak`)
- `common` — override the common resource path (default `common/keycloak`)
- `styles` — space-separated stylesheets to include
- `locales` — comma-separated supported locales

Properties can substitute `${some.system.property}`, `${env.ENV_VAR}`, with optional defaults `${foo:defaultValue}`. The `base` theme is message-bundle-only — extend it only if writing a console/account implementation from scratch.

Default themes ship inside the distribution JAR (e.g. `keycloak-themes-26.2.15.redhat-00001.jar`); the `themes/` dir is empty except a README. Do not edit bundled themes — extend them so upgrades are clean.

## Theme caching during development

Disable caching to edit live without restart:

```
kc.sh start --spi-theme-static-max-age=-1 --spi-theme-cache-themes=false --spi-theme-cache-templates=false
```

Re-enable in production (caching significantly affects performance). To purge the cache manually, delete `data/tmp/kc-gzip-cache` — useful after redeploying custom providers/themes without having disabled caching.

## Theme SPIs

- **Theme Selector SPI** (`ThemeSelectorProviderFactory` / `ThemeSelectorProvider`) — programmatically choose the theme name per request; the canonical SPI example in the dev guide (`getThemeName(Theme.Type)`). See [[spi-provider-model]].
- **Theme Resource SPI** (`ThemeResourceProviderFactory` / `ThemeResourceProvider`) — control how templates and resources are loaded; relevant when shipping extra templates/messages with a custom provider. The simplest packaging is a JAR with templates under `theme-resources/templates`.
- **Locale selector** — default `DefaultLocaleSelectorProvider`, overridable.

## Contradictions / caveats

- The React-based Admin/Account console theming (Theme Resource SPI for React templates) is documented in the **Themes based on React** chapter and evolves between releases; the classic Freemarker theming model above is stable across RHBK 26.0–26.6.
- The bundled-themes JAR version string tracks the RHBK release (e.g. `26.2.15.redhat-00001`).
- Overriding HTML templates can break on upgrade — re-check overridden templates after each RHBK upgrade (inferred general upgrade-hygiene advice, not a specific doc claim).
