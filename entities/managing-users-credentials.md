# Managing users and credentials

**Creating and administering users, their profile attributes, and their credentials within a realm (Admin Console "Users", or `kcadm.sh`); avoid creating end users in the master realm.**

## Creating users
Create users in the realm that owns the applications they need, **not** in master
(master is only for managing other realms). Via CLI:
`kcadm.sh create users -s username=testuser -s enabled=true -r demorealm`.

## User profile (attributes)
A realm's **user profile** defines a schema for user attributes: which attributes exist,
their validation, and per-context permissions (admin vs end-user) for viewing/editing.
A default profile covers common attributes. Attributes are **managed** (declared in the
schema) or **unmanaged**; being strict about allowed attributes is an extra defense
barrier. Built-in validators enforce values; the `VerifyProfile` required action can
force users to complete their profile (progressive profiling). Profile is configurable
via the UI or a JSON configuration.

## Credentials
Manage a user's credentials in the **Credentials** tab — set/reset passwords, require
credential resets, and view configured credential types (password, OTP, WebAuthn).
Password rules come from [[password-policies]] and OTP from [[otp-policies]]. Lockout
behavior is governed by [[brute-force-detection]]. **Required actions** (e.g. Update
Password, Update Email, Verify Profile, WebAuthn registration) are toggled per realm and
assigned per user; they feed into the [[authentication-flows]].
