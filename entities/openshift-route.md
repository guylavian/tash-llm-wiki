# OpenShift Route

**A Route exposes a [[kubernetes-service]] at a host name to traffic from outside the cluster, served by OpenShift's built-in HAProxy Ingress router.** It is OpenShift's native, older sibling to the Kubernetes [[kubernetes-ingress]] object.

## What it does
- Maps an external host (e.g. `app.apps.<cluster-domain>`) — and optional path — to a Service + target port. The Ingress Operator programs the HAProxy router pods that actually terminate and forward the traffic.
- On OCP, creating a Kubernetes **Ingress** auto-generates a managed Route under the hood, so the two coexist.

## TLS termination modes
- **edge** — TLS terminates at the router; router→pod is plaintext inside the cluster.
- **passthrough** — encrypted bytes go straight to the pod, which terminates TLS itself (required for mTLS or non-HTTP TLS).
- **re-encrypt** — TLS terminates at the router, which opens a **new** TLS connection to the pod (router holds a separate destination CA).

## Common gotchas
- Only pods passing their **readiness probe** are in the Service's endpoints, so a Route to a not-ready app returns 503 from the router even though the Route exists (inferred from the Service endpoint model — see [[kubernetes-service]]).
- A Route needs a Service with matching selector/endpoints; a typo'd selector yields a Route that resolves but 503s.
