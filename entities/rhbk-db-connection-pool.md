# RHBK Database Connection Pool Sizing for HA

**For HA deployments the guide recommends setting the initial, minimum and maximum
JDBC pool sizes equal so connections are pre-created and kept open, preserving
server-side statement caching.**

## The recommendation
Creating a DB connection is expensive (latency, and a connection stampede can
worsen load); closing one invalidates that connection's server-side statement
cache. So:

- Set **`poolInitialSize` = `poolMinSize` = `poolMaxSize`** (the blueprint uses
  `30/30/30`). Equal sizes avoid creating new connections on each incoming request.
- Keeping connections open lets PostgreSQL use **server-side prepared statements**
  (PostgreSQL promotes a statement after ~5 executions by default).
- Because most RHBK requests are served from the **embedded cache** and never
  touch the DB, even a modest pool can serve several hundred requests/s (inferred
  — a conclusion drawn from the sizing numbers above, not itself stated in the guide).

On the `Keycloak` CR:
```yaml
spec:
  db:
    vendor: postgres
    url: jdbc:aws-wrapper:postgresql://<AURORA_URL>:5432/keycloak
    poolMinSize: 30
    poolInitialSize: 30
    poolMaxSize: 30
    usernameSecret: { name: keycloak-db-secret, key: username }
    passwordSecret: { name: keycloak-db-secret, key: password }
  additionalOptions:
    - name: db-driver
      value: software.amazon.jdbc.Driver
```

## Related pitfalls
- **XA off with Aurora:** set `transaction.xaEnabled: false` — the AWS Aurora JDBC
  wrapper driver does not support XA transactions (inferred — not found in the
  cited HA-guide chapters; this is general AWS JDBC wrapper driver knowledge, verify
  against the exact HA guide chapter or the driver's own docs before relying on it).
- Pool size interacts with thread-pool size (`http-pool-max-threads`) and Aurora
  IOPS budget when sessions are DB-backed ([[session-persistence-volatile]]).

## Contradictions / caveats
- The `30/30/30` figure is a **starting point** from the blueprint; adjust to your
  request rate, then load-test.
- Aurora-specific driver settings (`aws-wrapper`, `software.amazon.jdbc.Driver`)
  apply to the documented Aurora setup; other databases use their own driver and
  may support XA.
