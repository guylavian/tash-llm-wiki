# OIDC / OAuth2 Grant Types (flows)

**The flows RHBK supports for obtaining tokens, and which are recommended vs.
discouraged under current OAuth security best practice.**

## Recommended
- **Authorization Code** — redirects the user agent to RHBK; on success an
  authorization code returns, which the app exchanges (with its credentials) for
  access + refresh + ID tokens. Targeted at web apps; **also recommended for
  native/mobile** apps that can embed a user agent. Harden with PKCE.
- **Client Credentials** — client obtains tokens on its own behalf (no user),
  for background/machine-to-machine services. Authenticates with a secret or
  public/private keys. OAuth2-only (not part of OIDC).
- **Device Authorization Grant** — for internet-connected devices with limited
  input or no browser. App gets a device code + user code; user authenticates on
  another device at the verification URI; app polls the token endpoint. Public or
  confidential clients.
- **CIBA (Client Initiated Backchannel Authentication)** — client starts auth by
  talking to RHBK directly (no browser redirect); gets an `auth_req_id` then
  polls (or uses `ping` mode with a Client Notification Endpoint). Confidential
  clients only.

## Discouraged / removed
- **Implicit** — returns access + ID tokens directly from the authorization
  endpoint (no code exchange, no refresh token). Security risk (token leak via
  logs/history); **should not be used** per OAuth 2.0 BCP and **removed in OAuth
  2.1**.
- **Resource Owner Password Credentials (Direct Grant)** — exchanges raw user
  credentials for tokens. Requires the client's **Direct Access Grants Enabled**
  option. Many limitations (no brokering/social login, no required actions,
  credentials exposed to the app); **should not be used**; OAuth2-only and
  **removed in OAuth 2.1**.
- **Hybrid** — returns both a code and tokens; shares Implicit's leak risks.

## Contradictions / caveats
- Implicit and Direct Grant are still *available* in RHBK 26.x for compatibility
  but flagged against best practice; enforce their absence via the OAuth 2.1
  client profiles ([[fapi-oauth21-profiles]]).
- Direct Grant and Client Credentials are OAuth 2.0 grants, not part of the OIDC
  spec proper.
