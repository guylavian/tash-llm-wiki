# `additionalOptions`

**The `spec.additionalOptions` field on the [[keycloak-cr]] — a key/value escape
hatch for any server option that has no first-class field on the CR.**

## Why it exists

Many server options are first-class CR fields, but some are deliberately omitted:
options needing deep internals knowledge, options irrelevant to OpenShift, and
dynamic per-provider (SPI) options. `additionalOptions` accepts any of them.

## Shape

```yaml
spec:
  additionalOptions:
    - name: spi-connections-http-client-default-connection-pool-size
      secret:                       # value from a Secret
        name: http-client-secret
        key: poolSize
    - name: spi-email-template-mycustomprovider-enabled
      value: "true"                 # plain-text value
```

- `name` uses the **same key format as the config file** (e.g. the `spi-...`
  dotted/dashed form), not an env-var form.
- Each entry is either a plain `value` or a `secret` reference.
- Also used to configure the management interface (e.g.
  `http-management-relative-path`) alongside `httpManagement.port`.

## Caveats

- **Ignored with optimized custom images**: when `spec.image` is set, every
  build-time option passed via a dedicated field **or** `additionalOptions` is
  ignored — bake build-time config into the image instead ([[custom-keycloak-image]]).
  (inferred — grounded in `reference/keycloak/rhbk-26-6-customizing-keycloak.md`,
  not in this page's cited advanced-configuration source.)
- Secret-referenced options live in the **same namespace** as the CR; the Operator
  polls ~every minute and does a **rolling restart** when a referenced Secret/
  ConfigMap changes ([[operator-secret-references]]).
