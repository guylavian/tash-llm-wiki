# StorageClass

**A StorageClass describes a storage type/tier for administrators — quality of service, backup policy, or any other policy an admin wants — and is what a [[persistent-volume-claim]] references by name to get a volume dynamically provisioned.**

## Key fields
- **`provisioner`** — determines which volume plugin/[[csi-driver]] actually creates the volume. In-tree ("internal") provisioners exist for some backends; others (e.g. NFS) have **no internal provisioner** and require an external one. Users are not restricted to bundled provisioners — external/3rd-party provisioners are common and full-discretion in packaging.
- **`reclaimPolicy`** — `Delete` (default if unset) or `Retain`; sets the reclaim policy on PVs the class dynamically provisions.
- **`allowVolumeExpansion: true`** — required for a PVC bound to that class to later request a larger size.
- **`mountOptions`** — applied to PVs the class creates; an unsupported mount option is **not validated at creation** and only fails at actual mount time.
- **`volumeBindingMode`** — `Immediate` (default: bind/provision as soon as the PVC is created, ignoring the consuming pod's scheduling constraints — can produce unschedulable pods on topology-constrained backends) or `WaitForFirstConsumer` (delays binding/provisioning until a pod actually uses the PVC, so the volume is provisioned honoring that pod's node selectors/affinity/taints). **Do not combine `WaitForFirstConsumer` with a pod's `nodeName`** — that bypasses the scheduler entirely and the PVC stays `Pending`.

## Default StorageClass
Exactly one StorageClass in a cluster is normally marked default (via annotation); a PVC that specifies no `storageClassName` uses it. Changing the cluster default is a supported `oc`/kubectl admin task (`tasks-change-default-storage-class`).
