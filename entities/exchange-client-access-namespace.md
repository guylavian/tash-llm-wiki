# Exchange Client Access & Namespace

**Since Exchange 2016/2019/SE, Client Access services live inside the Mailbox
server role, all native clients speak HTTP/HTTPS only, and session affinity at the
load balancer is no longer required.**

## Body

Exchange 2013 introduced a dedicated Client Access server role that proxied client
requests back to whichever Mailbox server held the active copy of the target
mailbox; 2016/2019/SE keep that proxying behavior but fold Client Access services
back into the Mailbox role itself — if two Mailbox servers host different
mailboxes, they proxy for each other as needed
(`exchange-exchange-servertoc-p0241-0280.md:327-378`).

Because every native client (Outlook via MAPI over HTTP, Outlook on the web,
ActiveSync, IMAP/POP over HTTP-fronted protocols) now uses HTTP with an
HTTPS-encrypted cookie issued at login, **session affinity is not required**: a
logged-in user resuming on a different Mailbox server running Client Access
services doesn't need to reauthenticate, as long as that server can decrypt the
cookie — i.e., shares the same SSL certificate
(`exchange-exchange-servertoc-p0241-0280.md:342-345, 408-413`). This also lets a
load balancer implement simple HTTP health probes per client-facing service
instead of maintaining sticky sessions.

**Load-balancing options** range from simple DNS round-robin (give the client every
Mailbox server's IP and let the HTTP client retry a different one on failure — has
drawbacks) to dedicated hardware/virtual load balancers, including Layer 4 (fast,
but blind to traffic contents/can't route per-service) and Layer 7 options
(`exchange-exchange-servertoc-p0241-0280.md:419-472`). One hard constraint: DAGs
use Microsoft (Windows) Clustering Services, which **cannot coexist on the same
server with Windows Network Load Balancing (NLB)** — so NLB is not an option on a
Mailbox server that's also a DAG member; third-party load balancers are required
instead (`exchange-exchange-servertoc-p0241-0280.md:436-439`).

**Autodiscover** publishes an SCP (Service Connection Point) object per Mailbox
server's frontend Client Access services, carrying a `ServiceBindingInfo` FQDN of
the form `https://<server>/autodiscover/autodiscover.xml`; the Microsoft Remote
Connectivity Analyzer's ActiveSync/Outlook Autodiscover tests validate this path
end to end (`exchange-exchange-servertoc-p0241-0280.md:300-313`).
