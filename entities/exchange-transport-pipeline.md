# Exchange Transport Pipeline & Connectors

**The transport pipeline is the collection of services, connectors, and queues on
Mailbox and Edge Transport servers that route every message to the categorizer
before delivery.**

## Body

Four services make up the pipeline
(`exchange-exchange-servertoc-p1521-1560.md:667-717`):

- **Front End Transport service** (Mailbox servers) — a stateless proxy for
  inbound/outbound external SMTP; it never inspects content, never talks to the
  Mailbox Transport service, and queues nothing locally.
- **Transport service** (Mailbox servers) — the functional successor to the
  Exchange 2010 Hub Transport role. Performs categorization and content
  inspection; never talks directly to mailbox databases.
- **Mailbox Transport service** (Mailbox servers) — split into **Mailbox
  Transport Submission** (pulls outbound messages from the local mailbox
  database over RPC, submits over SMTP to Transport) and **Mailbox Transport
  Delivery** (receives from Transport, delivers to the local mailbox database
  over RPC). Only this service ever talks to a mailbox database, and only the
  local one.
- **Transport service on Edge Transport servers** — near-identical to the
  Mailbox-server Transport service; if an Edge Transport server is deployed in
  the perimeter, all Internet-facing mail flows through it.

Inbound mail without an Edge Transport server enters via the default **Receive
connector** `Default Frontend <server>` on Front End Transport, is handed to
Transport's `Default <server>` receive connector, then to Mailbox Transport
Delivery, then RPC-delivered to the mailbox database
(`exchange-exchange-servertoc-p1521-1560.md:740-757`). With a subscribed Edge
Transport server, inbound mail instead enters the Edge server's Transport service,
crosses to a Mailbox server via the auto-created **`EdgeSync - Inbound to <AD
site>`** Send connector, then follows the same Front End → Transport → Mailbox
Transport Delivery chain (`exchange-exchange-servertoc-p1521-1560.md:759-785`).
Outbound mail requires an admin-created Send connector — none exists by default in
a new organization (`exchange-exchange-servertoc-p1521-1560.md:799-803`).

**Server roles are down to two** as of 2013+: Mailbox (bundles the old Mailbox +
Client Access roles) and Edge Transport, which manages EdgeSync-based relay/smart
hosting outside the AD forest and is not itself an AD forest member
(`exchange-exchange-servertoc-p0241-0280.md:356-403`).

## Contradictions / caveats

None observed across the notes read; both sources describe the same 2016/2019/SE
architecture consistently.
