# KeycloakRealmImport CR

**A `KeycloakRealmImport` custom resource that drives the Operator to import a
realm into a managed Keycloak deployment via a one-shot Kubernetes Job.**

## Shape

```yaml
apiVersion: k8s.keycloak.org/v2alpha1
kind: KeycloakRealmImport
metadata:
  name: my-realm-kc
spec:
  keycloakCRName: <name of the Keycloak CR>   # same namespace
  realm:
    id: example-realm
    realm: example-realm
    enabled: true
    ...                                        # a full RealmRepresentation
```

- `spec.keycloakCRName` ties the import to a [[keycloak-cr]] in the **same namespace**.
- `spec.realm` accepts a full `RealmRepresentation`. Recommended source: export a
  realm to a single file, convert JSON → YAML, paste under `realm:`.
- Status conditions (`Done`, `Started`, `HasErrors`) via
  `oc get keycloakrealmimports/<name> -o go-template='{{range .status.conditions}}...'`.

## Placeholders (env-var substitution)

`spec.placeholders` enables import placeholder replacement from environment
variables sourced from Secrets in the same namespace:

```yaml
spec:
  placeholders:
    ENV_KEY:
      secret:
        name: SECRET_NAME
        key: SECRET_KEY
```

Only Secrets are supported. Placeholder replacement exposes **all** env vars
(including sensitive ones) to the import — treat it as privileged.

## Behavior & lifecycle

- **Create-only**: if a realm with the same name already exists it is **not
  overwritten**; the CR never updates or deletes realms, and changes made directly
  in Keycloak are not synced back into the CR.
- After a successful import you should **delete the Realm Import CR** to clean up
  the associated Job and Pod resources (documented from 26.6).
- The import Job can inherit `resources` and `scheduling` from the Keycloak CR; the
  Realm Import CR can override `resources` independently ([[operator-resources]]).

## Contradictions / caveats

- The "delete the CR after import to clean up the Job/Pod" guidance is called out
  explicitly from **26.6**; behavior (create-only) is consistent across 26.0–26.6.
- Anyone able to create/edit `KeycloakRealmImport` CRs should be a namespace admin (inferred — follows from the placeholder-privilege note above, not stated directly).
