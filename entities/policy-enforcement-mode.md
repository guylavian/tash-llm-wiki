# Policy enforcement mode

**A resource-server setting that decides the outcome when a requested resource has no associated [[authorization-permissions|permission/policy]] — the default-deny vs default-allow knob.**

Configured on the Resource Server Settings page (a client's Authorization tab):
- **Enforcing** — *default*. Access is denied when there is no policy associated with the resource.
- **Permissive** — access is allowed when there is no policy associated with the resource.
- **Disabled** — disables evaluation of all policies and allows access to all resources.

This is orthogonal to [[decision-strategies|Decision Strategy]] (which combines outcomes when policies *do* exist).

## Contradictions / caveats
- Stable across RHBK **26.0–26.6**.
- `Permissive` and `Disabled` weaken protection — combined with the always-grant **Default Resource** (`/*`) seeded at resource-server creation, they can silently expose everything (inferred — a risk synthesis combining this chapter with the default-resource behavior documented elsewhere). Narrow or remove the default resource first (see [[fine-grained-authorization]]).
