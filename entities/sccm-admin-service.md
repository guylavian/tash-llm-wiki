# SCCM Admin Service (REST API)

**The administration service is a REST API — built on the Open Data Protocol (OData) v4 — that
the SMS Provider exposes over HTTPS for programmatic access to Configuration Manager.**

## Body

It has two routes:

- **WMI route**: `https://<SMSProviderFQDN>/AdminService/wmi/<ClassName>` — supports GET and POST
  over more than 700 WMI classes.
- **OData/SQL route**: `https://<SMSProviderFQDN>/AdminService/v1.0/<ClassName>` — the versioned
  route that carries newer Configuration Manager functionality.

`<ClassName>` must be a valid, **case-sensitive** Configuration Manager class name (e.g.
`SMS_Site`).

### Where ConfigMgr itself uses it

Configuration Manager natively uses the administration service for: email approval of apps,
viewing recently connected consoles, the console's Security node, Microsoft Intune tenant attach,
Community hub, and managing console extensions.

### Custom integration scenarios

Beyond built-in usage, the admin service is the supported surface for: replacing a custom web
service that reads site data, PowerShell scripts run from the ConfigMgr console or as a task
sequence step (accessing site data without a custom WMI-facing web service), and pulling site
data into Power BI via its OData connector.

### Prerequisites

To access the administration service, the account needs to be an administrative user in
Configuration Manager (or, via a cloud management gateway, an account in Microsoft Entra ID). On
the SMS Provider server: version 2006 and earlier required the Web Server (IIS) role (not
required starting 2010); starting version 2107 the SMS Provider requires .NET 4.6.2 (4.8
recommended; 2103 and earlier required .NET 4.5+); and enabling secure HTTPS with a trusted
certificate may be needed.
