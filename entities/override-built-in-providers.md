# Overriding built-in providers (order & provider id)

**To replace a built-in RHBK provider whose id must stay fixed, implement a factory with the same provider id and a higher `order()` — the highest-order implementation for a given id wins at runtime.**

## Two ways to override

1. **Preferred — unique id + set as default.** Give your factory a unique `getId()` and select it as the default provider via configuration (for single-implementation types: `kc.sh build --spi-<spi>--provider=<id>`). This avoids id collisions.
2. **Same id + `order()`.** Sometimes the provider id is load-bearing and cannot change. Example: customizing OIDC behavior by extending `OIDCLoginProtocolFactory` requires keeping id `openid-connect`, because the admin console, the OIDC well-known endpoint, and other components key off it. In that case keep the id and override `order()` to return a value higher than the built-in:

```java
public class CustomOIDCLoginProtocolFactory extends OIDCLoginProtocolFactory {
    @Override public int order() { return 1; }
}
```

When multiple factories share a provider id, only the highest-`order()` one is used.

## Disabling a provider

Set `enabled=false` for a specific provider. Example — disable the Infinispan user cache:

```
kc.sh build --spi-user-cache--infinispan--enabled=false
```

## Contradictions / caveats

- Behavior is consistent across RHBK 26.0–26.6. The `--spi-<spi>--provider=` default-selection syntax applies to single-implementation provider types only; multiple-implementation types (e.g. `EventListener`) are selected by id at lookup time instead (inferred — general SPI-model knowledge, not stated verbatim in this chapter). See [[spi-provider-model]].
