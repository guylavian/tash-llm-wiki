# PowerShell Classes

**`class` and `using` are PowerShell keywords reserved since version 5.0 for defining custom
.NET types directly in script — see `about_Classes` and `about_Using`.**

## Body

### Language status

The PowerShell language grammar lists `class` among its reserved keywords, alongside `define`,
`from`, `using`, and `var` — all reserved for (then) future use. An editor's note in the grammar
reference confirms `class` and `using` were introduced in PowerShell 5.0
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p1121-1160.md:1505-1533`).

### Static methods and delegate conversion

Classes support `static` methods with typed parameters and return values. A PowerShell 7.0
change let you convert a `PSMethod` into a .NET delegate, so a class's static method can be
passed as a callback into another method:

```powershell
class M {
    static [int] DoubleStrLen([string] $value) { return 2 * $value.Length }

    static [long] AggregateString([string[]] $values, [Func[string, int]] $selector) {
        [long] $res = 0
        foreach ($s in $values) { $res += $selector.Invoke($s) }
        return $res
    }
}

[M]::AggregateString((gci).Name, [M]::DoubleStrLen)
```

(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0681-0720.md:388-411`).

### Relationship to custom object types

Before classes existed, ad hoc typed objects were built with `[pscustomobject]` and a
`PSTypeName` property inserted via `$obj.psobject.TypeNames.Insert(0, "My.Object")` or inline
as a `PSTypeName` key in the hashtable literal. The source notes that PowerShell classes are the
alternative, more structured way to create custom PowerShell types
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0321-0360.md:503-528`).
