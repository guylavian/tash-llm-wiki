# Bootstrapping / Recovering an Admin Account

**Creating a temporary admin user (or admin service account) to gain access to a
realm when no usable admin credential exists — e.g. first start, or recovery.**

## How
RHBK provides `bootstrap-admin` start parameters that create a *temporary* admin:

```sh
# temporary admin user
bin/kc.sh start --bootstrap-admin-username tmpadm --bootstrap-admin-password pass

# temporary admin service account (client credentials)
bin/kc.sh start-dev --bootstrap-admin-client-id tmpadm --bootstrap-admin-client-secret <secret>
```

Equivalent environment variables exist for containers/operator deployments
(`KC_BOOTSTRAP_ADMIN_USERNAME` / `KC_BOOTSTRAP_ADMIN_PASSWORD` and the client-id
/ client-secret pair).

## Caveats
- The bootstrapped account is **temporary** — intended to log in, create a
  permanent admin, then be removed. Do not leave it in place.
- Documented in `Chapter 3. Bootstrapping and recovering an admin account`
  (Server Configuration Guide), present in RHBK 26.2 / 26.4 / 26.6.
- On OpenShift this is wired through the [[rhbk-operator]] / a Secret, not the
  raw CLI flags (inferred — bridges the Operator's `bootstrapAdmin` mechanism to
  the bare-CLI flags; see [[operator-initial-admin]]).
