# Password policies and hashing

**Realm-level rules (Authentication → Policies) constraining password strength, age, reuse, and the hashing algorithm; new realms have no policy, so set one before creating users.**

A policy applies only to **new** users / new password sets — to enforce on existing
users add the `Update Password` required action or use `Expire password`.

## Hashing
Passwords are never stored in cleartext; they are hashed with a standard algorithm:

| Algorithm | Notes | Default iterations |
|---|---|---|
| `argon2` | Default (non-FIPS); much lower CPU than PBKDF2, more secure | 5 |
| `pbkdf2-sha512` | Default for FIPS | 210,000 |
| `pbkdf2-sha256` | | 600,000 |
| `pbkdf2-sha1` | Deprecated | 1,300,000 |

Default hashing algorithm is set server-wide with
`--spi-password-hashing-provider-default=<algorithm>`. Argon2 parallel hashing is
capped to JVM-available cores by default. **Hashing iterations** default `-1` (use the
algorithm default) — rarely change. Changing the algorithm only re-hashes a user's
password the next time they log in.

## Policy types (selected)
- **Digits / Lowercase / Uppercase / Special characters** — minimum counts.
- **Not username / Not email** — password must differ from those.
- **Regular expression** — must match Java regex pattern(s).
- **Expire password** — valid for N days.
- **Not recently used** — history-based; configurable count of stored old passwords.
- **Not recently used (In Days)** — cannot reuse a password set within N days.
- **Password blacklist** — UTF-8 file under `${kc.home.dir}/data/password-blacklists/`
  by default; case-insensitive; uses a BloomFilter (configurable false-positive
  probability, default 0.01%, via
  `--spi-password-policy-password-blacklist-false-positive-probability`). Path is
  overridable with `keycloak.password.blacklists.path` or
  `--spi-password-policy-password-blacklist-blacklists-path`.
- **Maximum Authentication Age** — seconds within which a user may change password
  without re-auth (`0` = always re-auth). **May be deprecated** in favor of configuring
  the Update Password required action.

Pairing a strong password policy with OTP is the practical mitigation for the
guessing attacks the brute-force chapter describes (inferred — a synthesis
connecting the two chapters, not a single stated recommendation); see
[[brute-force-detection]] and [[security-hardening-checklist]].

## Contradictions / caveats
- Bodies sourced are RHBK **26.0**. Argon2 is the default only for **non-FIPS**;
  FIPS deployments default to `pbkdf2-sha512`.
- `pbkdf2-sha1` is deprecated — do not select it for new realms.
