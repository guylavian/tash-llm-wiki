# Liveness, Readiness, and Startup Probes

**The kubelet uses three independent probes to judge container health, and mixing up their purposes is the most common cause of both false-restart loops and silent traffic black-holes.**

## The three probes
- **liveness** — "is this container still alive?" On failure the kubelet **kills and restarts** the container. Point it at something that can genuinely never recover without a restart; pointing it at a deep, slow dependency (a downstream DB, an external API) causes healthy containers to be killed in a restart loop under load.
- **readiness** — "is this container ready to receive traffic right now?" On failure the kubelet does **not** restart the container — it removes the Pod from the owning [[kubernetes-service]]'s endpoints, so no traffic (and no router traffic on OpenShift) is sent to it until it passes again. This is the lever behind a Route/Service returning 503 with an otherwise-Running Pod.
- **startup** — gates the liveness/readiness checks until a slow-starting container has finished booting, so a legitimately slow startup isn't mistaken for a liveness failure and killed mid-boot. Once the startup probe succeeds, liveness/readiness take over.

## Tuning fields
Each probe (exec command, HTTP GET, or TCP socket check) is tuned with:
- `initialDelaySeconds` — how long the kubelet waits after container start before the first probe.
- `periodSeconds` — how often the probe runs.
- `timeoutSeconds` (default 1s) — how long a single probe attempt may take before it counts as a failure.
- `failureThreshold` — consecutive failures before the probe is considered failed (liveness → restart; readiness → remove from Service endpoints). The effective grace window before a symptom fires is roughly `failureThreshold * periodSeconds`.

## Diagnostic note
Observed events (`kubectl describe pod`, e.g. `Liveness probe failed: ...`) name **which** probe fired and why — read that line first before assuming which of the two failure classes (restart vs traffic removal) is in play, per the wiki's break-fix discipline: lead with the observed signal, not the first plausible hypothesis.
