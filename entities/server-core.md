# Server Core

**Server Core is a minimal Windows Server installation option (Standard or
Datacenter edition) with no desktop shell — a smaller disk footprint and, because
of the smaller code base, a smaller attack surface.**

## Body

Server Core omits the GUI shell packages (`Microsoft-Windows-Server-Shell-Package`,
`-Gui-Mgmt-Package`, `-Gui-RSAT-Package`, `-Cortana-PAL-Desktop-Package`) along
with accessibility tools, OOBE, audio support, and UWP push notifications. Locally
available tools include the command prompt, PowerShell, Regedit, Diskpart, and
Task Manager; **not** locally available: Server Manager, Event Viewer, `services.msc`,
Control Panel, Windows Explorer/Taskbar, Hyper-V Manager GUI, or a browser — these
are managed **remotely** via RSAT, [[windows-admin-center]], or PowerShell/WinRM.

**Included roles** (subset): AD DS, AD CS, AD FS, AD LDS, AD RMS, DHCP, **DNS
Server**, File and Storage Services, Host Guardian Service, **Hyper-V**, Print and
Document Services, Remote Access, **Remote Desktop Services** (see caveat below),
Volume Activation Services, Web Server (IIS), and **WSUS**.

**Local management tool:** the **Server Configuration tool (SConfig)** — a
menu-driven (PowerShell-based from Windows Server 2022 onward) tool for network
config, domain join, Windows Update, and activation; it auto-launches on sign-in
by default from Windows Server 2022. SConfig only works in a local or Remote
Desktop session — **not** over a remote PowerShell session — and Microsoft
recommends more scalable tools (answer files, MDT, Configuration Manager, Group
Policy, Windows Admin Center) once you're managing more than a handful of servers.

## Contradictions / caveats

Server Core's Remote Desktop Services role **does** include the Connection
Broker, Licensing, and Virtualization Host role services, but **not the Session
Host** — so [[remote-desktop-services]] session hosting requires Desktop
Experience, even though other RDS roles run fine on Server Core (extracted: the
Session Host role service is absent from the Server Core role-service table, and
the parent article explicitly gives "a Hyper-V server doesn't need a GUI" as the
canonical Server Core use case, implying session-hosting GUI apps are the
exception, not the rule — inferred connective reasoning).
