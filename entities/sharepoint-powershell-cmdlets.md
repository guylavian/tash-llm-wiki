# SharePoint Online / Server PowerShell Cmdlet Surface

**`Connect-SPOService` connects a SharePoint (or SharePoint Embedded) Administrator to the
SharePoint admin center and must run before any other SharePoint Online cmdlet; site-collection
cmdlets like `Get-SPOSite`/`New-SPOSite` only work once that connection exists.**

## Body

### Connecting

`Connect-SPOService -Url https://contoso-admin.sharepoint.com -Credential admin@contoso.com`
is the baseline form; only **one SharePoint Online service connection is supported per
PowerShell session and per geo** — running `Connect-SPOService` again automatically
disconnects and replaces the existing connection, so delegated partner administrators managing
multiple tenants in one session must explicitly switch connections. The caller must hold the
SharePoint Administrator or SharePoint Embedded Administrator role
(`reference/powershell/spps-connect-sposervice.md:17-19,47-53`). Besides username/password,
the cmdlet supports certificate-based auth (`-ClientId`/`-TenantId` + `-Certificate`/
`-CertificateThumbprint`/`-CertificatePath`) and managed identity (`-ManagedIdentity`,
optionally `-ManagedIdentityType`/`-ManagedIdentityClientId` for a user-assigned identity)
(`reference/powershell/spps-connect-sposervice.md:309-361`). `-Region` selects the auth
region for sovereign clouds: `Default`, `ITAR` (GCC High/DoD only), `Delos` (German sovereign
cloud), `France`, `Germany`, `China`
(`reference/powershell/spps-connect-sposervice.md:382-402`).

### MFA and modern authentication

Connecting with just `-Credential` against an account that requires **multi-factor
authentication fails** with `Could not connect to SharePoint Online`; the documented fix is to add
`-ModernAuth $true -AuthenticationUrl https://login.microsoftonline.com/organizations` (or omit
`-Credential` entirely to be interactively prompted, which also satisfies MFA)
(`reference/powershell/spps-connect-sharepoint-online.md:55-72,74-84`). `-UseSystemBrowser
$true` authenticates via MSAL and the system browser instead; a `UseSystemBrowser` registry
DWORD under `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\SPO\CMDLETS\` makes that the default
without repeating the switch every time
(`reference/powershell/spps-connect-sposervice.md:440-452`).

### Known module conflict

The SharePoint Online Management Shell module fails to load if the **SharePoint Client
Components SDK** is also installed on the same computer — the documented fix is uninstalling
the SDK
(`reference/powershell/spps-connect-sharepoint-online.md:88-89`).

### The cmdlet surface beyond Connect

Once connected, administrative cmdlets like `Get-SPOSite` ("Returns one or more site
collections") and `New-SPOSite` ("Creates a new SharePoint Online site collection for the
current company") operate against the connected tenant
(`reference/powershell/spps-get-sposite.md:17`, `reference/powershell/spps-new-sposite.md:17`).
