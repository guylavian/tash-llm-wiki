# Operator advanced configuration

**The advanced knobs on the [[keycloak-cr]] beyond DB/hostname/TLS: trusted
certificates, Pod customization, scheduling, secret references, resources, ingress,
and admin bootstrapping.**

This page collects the smaller `Keycloak` CR features. Each anchors an entity or
section below; all live under `spec` of the same CR.

## Truststores

`spec.truststores` configures the server's truststore from Secrets holding PEM
files or PKCS12 (`.p12`/`.pfx`):

```yaml
spec:
  truststores:
    my-truststore:
      secret:
        name: my-secret
```

Well-known cluster CAs are added automatically when present
(`/var/run/secrets/kubernetes.io/serviceaccount/ca.crt` and `service-ca.crt`). See
[[keycloak-truststores]]. With a custom image, setting `tlsSecret` + `truststores`
lets the Operator reflect the right scheme for the management interface
([[custom-keycloak-image]]).

## Secret & ConfigMap references

Several fields take Secret references (`tlsSecret`, values in
[[additional-options]]) or ConfigMap references (`configMapFile`). The referenced
object must be in the **same namespace** as the CR. The Operator **polls ~every
minute** and performs a **rolling restart** when a meaningful change is detected.
See [[operator-secret-references]].

## Pod Template (`unsupported.podTemplate`, Tech Preview)

A raw Deployment pod-template override merged into what the Operator generates —
for injecting labels, annotations, volumes, and volume mounts when no first-class
field exists:

```yaml
spec:
  unsupported:
    podTemplate:
      metadata:
        labels:
          my-label: "keycloak"
      spec:
        containers:
          - volumeMounts:
              - name: test-volume
                mountPath: /mnt/test
        volumes:
          - name: test-volume
            secret:
              secretName: keycloak-additional-secret
```

Highly experimental / Tech Preview; no guarantee the Deployment works as expected,
and it can confuse the `Auto` rolling-update probe. See [[operator-pod-template]].

## Scheduling

`spec.scheduling` exposes standard Kubernetes `affinity`, `tolerations`,
`topologySpreadConstraints`, and `priorityClassName`. With no custom affinity, Pods
default to **same-zone affinity** and **same-node anti-affinity** to improve
availability and avoid high-latency cross-zone cache traffic. Import/update Jobs
inherit scheduling from the CR (documented from 26.4, see Contradictions/caveats
below on the version discrepancy). See [[operator-scheduling]].

## Resources

`spec.resources` sets compute requests/limits. Defaults: requests memory
**1700MiB**, limits memory **2GiB**. The Realm Import Job falls back to the
Keycloak CR's values (or defaults) unless overridden on the Realm Import CR. See
[[operator-resources]].

## Disabling required options (dev only)

For development you can relax security: `http.httpEnabled: true` plus
`hostname.strict: false` disables strict hostname/TLS. Not for production.

## Admin bootstrapping

`spec.bootstrapAdmin` configures the initial admin user and/or service account; if
omitted the Operator creates `<cr-name>-initial-admin` with user `temp-admin` and a
generated password. Once a master realm exists, `bootstrapAdmin` is ignored. See
[[operator-initial-admin]] and [[kc-bootstrap-admin]].

## Contradictions / caveats

- `unsupported.podTemplate` is Tech Preview across 26.0–26.6.
- Job scheduling inheritance (import/update Jobs honoring `scheduling`) is spelled
  out from **26.6** (ambiguous — the same text is already present in the
  `rhbk-26-4-advanced-configuration` note and absent from 26.0/26.2, so **26.4** is
  the more accurate first version, not 26.6); the default same-zone/anti-node
  affinity applies to server Pods only, not Jobs.
