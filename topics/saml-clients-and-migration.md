# SAML Clients & Migration (SP integration, adapters, air-gap)

**How SAML service-provider apps integrate with RHBK as IdP, which SAML adapters
survive the RH-SSO→RHBK move, and what changes — distinct from the OIDC story.**

## SAML in RHBK — what's supported
RHBK is a full SAML 2.0 IdP. Per the Server Administration Guide (Ch. 13/9):
- **All RHBK client adapters for OIDC *and* SAML are supported**, **plus**
  **`mod_auth_mellon`** (the Apache HTTPD SAML module) **and standard SAML entity
  descriptor files**. See [[mod-auth-mellon]].
- A SAML client is created from a **SAML entity descriptor** (the SP metadata XML)
  or configured manually. RHBK can also generate **SP metadata** for brokering
  (Ch. 9 → SP Descriptor / "SAML 2.0 Service Provider Metadata" link).

## Migration: which SAML SP option to use
This is the key difference from OIDC — the SAML adapter story is **not** "all
adapters removed":
- ✅ **Fully supported SAML adapter = the Keycloak SAML Adapter feature pack (or
  RPM) for JBoss EAP 8.x.** This is the target for EAP-hosted SAML SPs.
- ✅ **`mod_auth_mellon`** for Apache HTTPD-fronted apps — supported, and a clean
  air-gap fit (it's an Apache module, configured from local metadata files).
- ✅ **Generic SAML SP** built into the app's framework (e.g. Spring Security SAML)
  consuming RHBK's SP/IdP metadata.
- 🔴 **RH-SSO 7.6 SAML adapters for other containers** (e.g. older Tomcat/JBoss
  SAML adapters): *not* supported by RHBK — supported **only in combination with
  RH-SSO 7.6**. Those SPs must move to the EAP 8 SAML feature pack, mod_auth_mellon,
  or a framework-native SAML SP.

**Bridge:** as with OIDC, an RH-SSO 7.6 SAML adapter keeps working against an
**RHBK 26.x server** during transition — migrate the server first, re-platform SPs
after. See [[adapter-migration]] and [[rhsso-to-rhbk-migration]].

## SAML-specific gotchas
- **Single Logout in a cluster:** with a non-replicating distributed cache, a SAML
  logout can hit a node lacking the SAML session-index→HTTP-session mapping →
  failed logout (inferred — confirmed against the SAML Galleon feature-pack
  chapter, which isn't in this page's cited `sources:`). See [[oidc-logout]] and
  [[distributed-caches]] (and the SAML Galleon feature pack note).
- **Signing/encryption keys & metadata drift:** SP and IdP exchange entity
  descriptors with embedded certs; rotating realm keys ([[realm-keys-and-rotation]])
  means re-exporting/re-importing metadata on both sides.
- **Bindings:** RHBK defaults to Redirect binding for IdP-initiated responses
  unless POST/Artifact binding is set (identity-broker settings) (inferred —
  confirmed against the identity-broker chapter, not in this page's cited
  `sources:`).

## Air-gap friendliness
SAML is comparatively air-gap-friendly: integration is **metadata-file exchange**,
not a live network dependency. Export RHBK's IdP descriptor and the SP descriptor
as **files** and import each side manually — no internet, no metadata-URL polling.
(If you configure metadata-by-URL, point it at the internal host, not a public
one.) See [[air-gapped-client-integration]].

## Contradictions / caveats
- Adapter support combinations are version-sensitive — confirm the exact
  SP-adapter ↔ RHBK-server combination in `ref:rhbk-platform-support.md`.
- SAML wording is stable across RHBK 26.0–26.6; the "fully supported = EAP 8 SAML
  feature pack/RPM" statement appears in the 26.0/26.2/26.6 Migration Guides.
