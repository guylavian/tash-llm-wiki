- [[bgp-4-ios-xe]] — BGP-4 (Border Gateway Protocol version 4) is the interdomain path-vector routing protocol that exchanges loop-free reachability between autonomous systems over TCP port 179. On IOS XE, it installs one best path per prefix, uses AS_Path for loop prevention, supports 2-byte and 4-byte ASNs (asplain/asdot), and requires the next hop to be reachable (usually via the IGP) for any route to be usable.
- [[c9500-issu-svl-blackhole-nsf-gr]] — On a Catalyst 9500 StackWise Virtual pair, ISSU caused ~90-second traffic blackhole and OSPF/BGP flapping despite the standby reloading and rejoining cleanly. The root cause is missing OSPF NSF and BGP Graceful Restart configuration, not an ISSU procedure error — the routing protocols tore down adjacencies during the control-plane switchover because no grace signal was sent.

- [[etherchannel-load-balancing]] — EtherChannel bonds multiple physical links into one logical port-channel for bandwidth+redundancy; load balancing uses a 16-bucket flow-based hash per port-channel, with per-port-channel override of the global method.
- [[lacp-fast-switchover-prereqs]] — lacp fast-switchover enables EtherChannel flow-based limited 1:1 redundancy — one active + one hot-standby member with fast failover instead of full reconvergence. It must be enabled at BOTH ends, requires lacp max-bundle 1 on a two-port LACP channel; port-priority choice controls whether the channel reverts to the primary link.
- [[mixed-speed-port-channel]] — Mixing a 1G and a 10G link in the same LACP port-channel causes out-of-order packets and throughput degradation because (a) Cisco does not support mixed-speed EtherChannel members, and (b) flow-based load balancing distributes packets across links with ~10× serialization-delay difference, causing reordering at the receiver.
- [[ospfv2-routing-ios-xe]] — OSPFv2 (RFC 2328) on IOS XE is a link-state IGP that floods LSAs within areas, runs SPF to build a loop-free shortest-path tree, uses cost (derived from bandwidth) for path selection, elects DR/BDR on multiaccess networks, and requires consistent hello/dead timers, authentication, and MTU for adjacency formation.
- [[policy-based-routing-when-used]] — Policy-based routing (PBR) forwards packets by a route map applied to an interface instead of by destination-based longest-prefix lookup — used for source-sensitive routing, protocol-sensitive routing, equal-access, or dedicated-link steering.
