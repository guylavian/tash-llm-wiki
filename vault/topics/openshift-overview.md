# OpenShift / Kubernetes — Overview

**OpenShift Container Platform (OCP) 4 is a Kubernetes distribution: an upstream Kubernetes core plus a Red Hat platform layer that is itself run by operators.** Everything Kubernetes does — pods, controllers, Services, PV/PVC, RBAC — works unchanged; OCP adds Routes, in-cluster builds, Operator Lifecycle Manager, stricter security defaults, and an integrated OAuth server.

## The two layers

**1. The Kubernetes core** (identical to upstream, see <https://kubernetes.io/docs/home/>):
- **Workloads** — the [[kubernetes-pod]] is the unit; you manage replicas through controllers (Deployment for stateless, StatefulSet for stateful, DaemonSet for per-node, Job/CronJob for batch). Health via liveness/readiness/startup probes; placement via resource requests/limits. See [[openshift-implementation-review]] for the failure modes.
- **Networking** — a [[kubernetes-service]] is a stable endpoint over churning pod IPs; [[network-policy]] is the allow-list firewall (default allow-all until the first policy selects a pod).
- **Storage** — the PV/PVC split with dynamic provisioning via a StorageClass + CSI driver; an unsatisfiable PVC leaves a pod **Pending**.

**2. The OpenShift platform layer** (over Kubernetes, see the OCP 4 docs):
- **Operator-driven cluster** — the Cluster Version Operator drives per-subsystem **ClusterOperators**; `oc get clusteroperators` is the first health-triage surface (inferred: this is the day-2 entry point a future SRE agent keys off). Node OS config flows through MachineConfig; apps install via **OLM** Subscriptions/CSVs.
- **[[openshift-route]]** — native external HTTP(S) via the HAProxy router (edge/passthrough/re-encrypt TLS); an Ingress is reconciled into a Route on OCP.
- **Builds** — **BuildConfig + Source-to-Image (S2I)** build images in-cluster; ImageStreams trigger redeploys on new tags.
- **[[security-context-constraints]] (SCC)** — the default `restricted-v2` runs containers as a **random non-root UID**; a community image assuming root often fails on OCP but runs on plain Kubernetes (the single most common porting surprise — inferred from the SCC model).

## Versioning
OCP 4 minors track upstream Kubernetes minors; the brain spans **4.8 → 4.22**. Upgrades are operator-driven over channels (`stable-4.x`, EUS). State version-specific behavior by OCP minor.
