# Exchange Server — Overview

**On-premises Microsoft Exchange Server (2016 / 2019 / Subscription Edition) is a
messaging and collaboration platform built around two server roles — Mailbox and
Edge Transport — with mail flow, recipients, high availability, and client access as
its four operational pillars.**

## Body

Since Exchange 2013, Microsoft has collapsed what used to be up to seven server
roles (Mailbox, Client Access, Hub Transport, Unified Messaging, Edge Transport...)
down to **two**: the **Mailbox server role**, which now bundles the old Mailbox and
Client Access components (Client Access services provide auth/proxy for HTTP, POP,
IMAP, SMTP; Mailbox services host the Transport service and the mailbox databases
themselves), and the **Edge Transport server role**, typically deployed in the
perimeter network outside the internal AD forest to minimize attack surface and add
anti-spam/anti-malware layers on Internet-facing mail
(`exchange-exchange-servertoc-p0001-0040.md:242-267`). Exchange Server Subscription
Edition (SE) is RTM-code-equivalent to Exchange 2019 CU15 with in-place upgrade
supported from 2019 CU14/CU15; in-place upgrade from 2016 is not supported — 2016
must first go through a legacy upgrade path (`exchange-exchange-servertoc-p0001-0040.md:100-134`).

**Mail flow** moves through the **[[exchange-transport-pipeline]]** — Front End
Transport, Transport, and Mailbox Transport services on Mailbox servers, plus
Transport on Edge Transport servers — coordinated by **Send/Receive connectors**
and staged in the **[[exchange-mail-queues]]** (submission, delivery, poison,
shadow, unreachable) before landing in a destination mailbox database.

**Recipients** — the people and resources mail is delivered to — come in the
explicit types catalogued on **[[exchange-recipient-types]]** (user mailboxes,
shared/resource/linked mailboxes, mail contacts/users, distribution and mail-enabled
security groups, ...), each with a distinct `RecipientTypeDetails` value.

**High availability** for the Mailbox role is built on the **Database Availability
Group (DAG)** — see **[[exchange-database-availability-groups]]** — which groups up
to 16 Mailbox servers around a Windows failover cluster to provide automatic,
database-level recovery from disk/server/network failure.

**Client access** since 2016/2019 no longer needs session affinity: all native
clients speak HTTP/HTTPS, and a client reconnecting to a different Mailbox server is
transparently proxied to whichever server holds the active mailbox copy — see
**[[exchange-client-access-namespace]]**. This runs over TLS secured by
**[[exchange-certificates]]** (self-signed by default at install, replaceable with
internal-CA or commercial certificates).

Inbound/outbound mail is screened by **[[exchange-antispam-antimalware]]** — the
Content Filter agent (spam confidence level / SCL scoring) and the built-in Malware
Agent — and organizations running alongside Microsoft 365/Exchange Online typically
run the **[[exchange-hybrid-deployment]]** model via the Hybrid Configuration Wizard.
