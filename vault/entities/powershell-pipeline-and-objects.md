# PowerShell Pipeline and Object Binding

**Cmdlets on either side of a `|` exchange whole .NET objects, and PowerShell resolves which
parameter receives the piped object using a two-step ByValue-then-ByPropertyName rule.**

## Body

### Objects, not text

Piping `Get-Service -Name w32time | Get-Member` shows the pipeline carries a typed
`System.ServiceProcess.ServiceController` object with real properties (`Status`, `Name`,
`DisplayName`, …) and methods (`Start`, `Stop`, `Pause`, …) — `Get-Member`'s first output line,
`TypeName`, names the exact .NET type flowing through the pipe
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:17-60`).
Only four properties are shown by default; `Select-Object -Property *` or `Format-List`
reveals the rest.

### How a parameter accepts piped input

When a cmdlet parameter is piped a value, PowerShell tries **ByValue** binding first — it matches
the incoming object's .NET type against the parameter's declared type. If no parameter's type
matches, PowerShell falls back to **ByPropertyName** — it looks for a property on the incoming
object whose *name* matches a parameter name and binds that property's value
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1245-1281`).
For example, piping a `ServiceController` object to `Stop-Service` binds the whole object to
`-InputObject` (ByValue); piping a plain string binds it to `-Name` (ByValue, string type); and an
arbitrary object that merely *has* a `Name` property binds that property to `-Name`
(ByPropertyName). "By value" is a slightly misleading label — it is really **by type**
(inferred — the source itself makes this correction).

### Filter left

Best practice is to filter as early in the pipeline as possible — using a cmdlet's own filtering
parameters (e.g. `Get-Service -Name w32time`) instead of retrieving everything and piping to
`Where-Object` downstream. Retrieving an unfiltered set only to narrow it later wastes work that
gets expensive at scale (the source's own example: thousands of AD user objects)
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1086-1130`).
Command order also matters when chaining `Select-Object` and `Where-Object`: filtering must
happen *before* trimming properties with `Select-Object`, or the property `Where-Object` needs
to filter on may no longer be present in the pipeline
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1128-1150`).

## Contradictions / caveats
None noted — this is uncontested, version-stable PowerShell language behavior.
