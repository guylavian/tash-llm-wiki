# PowerShell Profiles and Providers

**A PowerShell profile is a script that runs automatically at session start to customize the
environment (aliases, functions, variables, modules, PSDrives, preferences); a PSProvider exposes
a hierarchical data store — the registry, certificates, environment variables, even third-party
stores like Active Directory or SQL Server — as a navigable PSDrive alongside the filesystem.**

## Body

### The `$PROFILE` automatic variable

`$PROFILE` holds the paths to up to four possible profile scripts, covering every
combination of user scope (`AllUsers` vs. `CurrentUser`) and host scope (`AllHosts` vs.
`CurrentHost`): `AllUsersAllHosts`, `AllUsersCurrentHost`, `CurrentUserAllHosts`,
`CurrentUserCurrentHost`. Referencing `$PROFILE` bare returns the "Current User, Current Host"
path; the other three are read off its member properties (`$PROFILE | Select-Object *`). On
Windows the default `CurrentUserCurrentHost` path is
`C:\Users\<user>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`; on Linux it's
`/home/<user>/.config/powershell/Microsoft.PowerShell_profile.ps1`. Each PowerShell **host**
(console host, VS Code) has its own uniquely-named profile file — VS Code's is
`Microsoft.VSCode_profile.ps1` instead of `Microsoft.PowerShell_profile.ps1`
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0241-0280.md:361-432`).
Running scripts (including a profile) on Windows requires the execution policy to be at least
`RemoteSigned` — [[powershell-execution-policy]] doesn't apply to macOS/Linux, so this
requirement is Windows-only.

### PSProviders and PSDrives

`Get-PSProvider` lists the providers available in a session — built-ins include `Registry`
(`HKLM`/`HKCU` drives), `Alias`, `Environment` (`Env:`), `FileSystem`, `Function`, `Variable`, and
`WSMan`; `Certificate` (`Cert:`) is also present. Third-party modules like `ActiveDirectory` and
`SqlServer` register their **own** provider and PSDrive (`AD:`, `SQLSERVER:`) on import
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0161-0200.md:11-53`).
`Get-PSDrive` lists the resulting drives, and they're navigable exactly like a filesystem — e.g.
`Get-ChildItem -Path Cert:\LocalMachine\CA` lists certificates the same way `Get-ChildItem` lists
files
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0161-0200.md:56-90`).
