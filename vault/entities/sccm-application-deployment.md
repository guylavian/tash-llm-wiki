# SCCM Application Deployment

**An application is created with one or more deployment types (how to install it on a given
platform), then deployed to a user or device collection; revisions and supersedence manage its
lifecycle as versions change.**

## Body

### Create and deploy

Creating an application (via **Software Library > Application Management > Applications** and
the Create Application Wizard) is the starting point; before deploying, at least one
**deployment type** must exist for the application (the install/detection/requirements logic for
a given platform). Deploying then targets a user or device collection and instructs the client
how and when to install or uninstall the software.

Two related features avoid deployment sprawl:

- **Application groups** bundle several applications so they can be sent to a collection as a
  single deployment, instead of creating one deployment per application.
- **Simulated deployment** tests a deployment type's detection method, requirements, and
  dependencies without actually installing/uninstalling anything, reporting results in
  **Monitoring > Deployments**. Only *required* application deployments can be simulated — not
  packages or software updates.

### Revision and supersedence

Editing an application or a deployment type creates a new **revision**; revision history can be
viewed, and a prior revision restored. **Supersedence** is the mechanism to move a collection of
targets from an old application version to a new one in a controlled way, rather than scripting
ad hoc uninstall/install logic.

### Package Conversion Manager (PCM) error surface

PCM (which converts legacy packages/programs to applications) logs to `PCMTrace.log`; common
failure messages — "Application creation failed with the following exception", "Conversion Error
– APPLIES TO A PACKAGE TRANSFORM STATUS", "Objects were not created successfully" — are all
resolved the same way: raise `PCMTrace.log` to verbosity level 4, check Configuration Manager
permissions and network-share connectivity for the package data source, and also check
`SMSProv.log` for object-creation failures.
