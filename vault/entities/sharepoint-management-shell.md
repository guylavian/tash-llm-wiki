# SharePoint Management Shell & Server PowerShell Cmdlets

**The on-premises SharePoint Server administrative cmdlet surface — distinct from the
SharePoint Online (`Connect-SPOService`) cmdlets — requires Windows PowerShell and
is loaded either automatically (module, Subscription Edition+) or explicitly
(`Add-PSSnapin`, older versions).**

## Body

### Module vs. snap-in

As of SharePoint Server Subscription Edition, SharePoint Server cmdlets install as a
**PowerShell module** rather than a snap-in — they are "automatically available in all
Windows PowerShell consoles," so an admin no longer has to launch the dedicated
SharePoint Management Shell or run `Add-PSSnapin` to reach them; the module also lets
PowerShell fetch updated cmdlet help over the internet. The SharePoint Management
Shell itself is still shipped, as a familiar PowerShell UI wrapper
(`what-s-new-new-and-improved-features-in-sharepoint-server-subscription-edition.md:462-472`).

On older/other versions the cmdlets are a snap-in, loaded with:

```
Add-PSSnapin Microsoft.SharePoint.PowerShell
```

**Hard constraint carried over regardless of packaging:** SharePoint Server cmdlets
require **Windows PowerShell** — "these cmdlets will not be compatible with PowerShell
Core 6.x or PowerShell 7.x"
(`what-s-new-new-and-improved-features-in-sharepoint-server-subscription-edition.md:472`).

### Elevated-administrator warning

Some SharePoint cmdlets require an elevated administrator token; because Windows
User Account Control can silently block that token unless PowerShell was launched
via "Run as Administrator," the SharePoint Management Shell warns on launch if it is
not running elevated
(`what-s-new-new-and-improved-features-in-sharepoint-server-subscription-edition.md:478`).

### Granting cmdlet permissions

Health Analyzer remediation steps across the corpus consistently require the operator
to be a member of `securityadmin` (SQL Server instance), `db_owner` (databases being
updated), local `Administrators`, and the Farm Administrators group before running
PowerShell fixes; `Add-SPShellAdmin` is the cmdlet an administrator uses to grant
another account permission to run SharePoint Server cmdlets without holding those
memberships directly
(`technical-reference-cached-objects-have-been-evicted.md:33-45`).

## Contradictions / caveats

Do not confuse this on-premises **SharePoint Server** cmdlet surface with the separate
**SharePoint Online** (`Connect-SPOService`, `Get-SPOSite`, …) cmdlet surface documented
at [[sharepoint-powershell-cmdlets]] (`domain: powershell`) — different module, different
connection model, different auth (MFA/modern-auth vs. Windows/claims), same product
family.
