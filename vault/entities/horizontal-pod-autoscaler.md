# Horizontal Pod Autoscaler (HPA)

**The HorizontalPodAutoscaler automatically scales the replica count of a Deployment, StatefulSet, or similar scalable workload resource to match observed demand — horizontal scaling (more Pods), not vertical scaling (bigger Pods).**

## How it works
The HPA is a control loop, not continuous: the controller manager queries resource utilization once per sync period (`--horizontal-pod-autoscaler-sync-period`, default 15s), resolves the HPA's `scaleTargetRef` to a Deployment/StatefulSet, selects its Pods via that resource's `.spec.selector`, and pulls metrics from the resource metrics API (per-Pod CPU/memory) or the custom metrics API (everything else). It then adjusts the target's desired replica count toward `minReplicas`/`maxReplicas` bounds. **Horizontal pod autoscaling does not apply to a [[kubernetes-daemonset]]** — a DaemonSet's Pod count is tied to node count, not a scalable target.

## v2 API — configurable behavior
The `autoscaling/v2` HorizontalPodAutoscaler API adds a `.spec.behavior` field with separate `scaleUp` and `scaleDown` policies, letting you tune reaction speed independently per direction:
- **`stabilizationWindowSeconds`** — how far back the controller looks before picking the most recent stable value, smoothing out flapping. The built-in default is `300` for `scaleDown` (favors caution, avoids thrashing on a brief dip) and `0` for `scaleUp` (react immediately to a load spike).
- One or more scaling **policies** can be set per direction (e.g. cap the rate of change); when several apply, the default selection picks the policy allowing the biggest change.

## Practical notes
- Target metrics are typically average CPU or memory utilization (a percentage of the requested value — see [[resource-requests-limits]]) or a custom/external metric.
- Scale-downs happen gradually by design, smoothing the impact of rapid metric fluctuation rather than reacting on a single sample (inferred: this is the same caution motive as the `scaleDown` stabilization window default above).
