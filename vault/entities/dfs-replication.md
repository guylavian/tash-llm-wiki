# DFS Replication

**DFS Replication (DFSR) is a Windows Server role service that keeps folders
synchronized across multiple servers and sites using an active-active
replication engine.**

## Body

You configure **replication groups**; each group contains **members** (servers)
and one or more **replicated folders**. Replicated folders in the same group share
a topology, schedule, and bandwidth-throttling settings, but each folder keeps its
own file/subfolder filters. Replicated folders don't need to be shared or part of a
DFS namespace.

DFSR uses **remote differential compression (RDC)** — it detects changed blocks
within a file and replicates only those blocks, not the whole file. It replaces
the legacy File Replication Service (FRS) as the replication engine for DFS
namespaces, and **Active Directory Domain Services uses DFS Replication to
replicate the `sysvol` folder** in domains at the Windows Server 2008 domain
functional level or later.

It's part of the **File and Storage Services** role; management tools are the DFS
Management snap-in, the DFS Replication PowerShell module, and the `dfsradmin` /
`dfsrdiag` commands (installed separately via RSAT).

**Virtualized DFSR caveats:** don't restore a DFSR server from a hypervisor
snapshot/saved state (breaks replication and needs special database recovery,
except for the `sysvol` case); don't export/clone/copy a DFSR VM; back up from
inside the guest, never from the host; a VPN with RPC Endpoint Mapper (port 135)
plus a dynamic or statically-configured port must connect on-premises members to
Azure VM members.

## Contradictions / caveats

DFS Replication is frequently pressed into service as a low-end disaster-recovery
tool, but [[storage-replica]]'s own overview calls this "often impractical": DFSR
can't replicate open files and is designed to minimize bandwidth at the expense of
latency (often hours/days), so the newest, hottest files are the *least* likely to
be current on the replica. Where zero-data-loss DR is the goal, Storage Replica
(block-level, no file-close requirement) is the documented alternative — not a
DFSR configuration change.
