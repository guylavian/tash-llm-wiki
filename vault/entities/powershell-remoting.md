# PowerShell Remoting — WS-Management (WinRM) and SSH

**`New-PSSession`, `Enter-PSSession`, and `Invoke-Command` run PowerShell on one or more
remote computers over either the WS-Management (WinRM) transport or, since PowerShell 6,
an SSH-based transport for non-Windows and mixed-OS targets.**

## Body

### WS-Management (WinRM) remoting

Windows PowerShell 5.1 and earlier use the **WS-Management (WSMAN)** protocol —
implemented by **Windows Remote Management (WinRM)** — for connection negotiation and
data transport. If WinRM is already enabled, PowerShell 7 reuses the existing Windows
PowerShell 5.1 endpoint (`Microsoft.PowerShell`); running `Enable-PSRemoting` gives
PowerShell 7 its own endpoint instead. The target computer must be configured for remote
management for WS-Management remoting to work at all
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0641-0680.md:1136-1150`).

### SSH-based remoting

SSH-based remoting was added in **PowerShell 6.x** specifically to support operating systems
that can't use Windows-native components like WinRM. It creates a PowerShell host process on
the target as an SSH subsystem. `New-PSSession`, `Enter-PSSession`, and `Invoke-Command` all
gained a parameter set for it:

```powershell
[-HostName <string>] [-UserName <string>] [-KeyFilePath <string>]
```

```powershell
Enter-PSSession -HostName <Computer> -UserName <Username>
# or
Enter-PSSession -HostName <Username>@<Computer>
```

Interactive use prompts for a password; the `-KeyFilePath` parameter sets up SSH key
authentication with a private key file instead
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0641-0680.md:1157-1192`).
The **Microsoft.PowerShell.RemotingTools** module (PowerShell Gallery) plus its `Enable-SSH`
cmdlet automates configuring the SSH side of this.

## Contradictions / caveats
None noted — WinRM vs. SSH-based remoting is a target-OS/transport choice, not a version
contradiction: WinRM remains the Windows PowerShell 5.1 default, SSH is the add-on for
PowerShell 6+ cross-platform and mixed-OS use.
