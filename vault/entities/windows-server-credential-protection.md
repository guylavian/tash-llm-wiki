# Windows Server credential protection (Restricted Admin, LSA protection, Protected Users)

**A set of Windows Server 2012 R2 / Windows 8.1-era features that reduce how much
of a user's or admin's credential material a compromised host can harvest.**

## Body

- **Restricted Admin mode for Remote Desktop Connection** — an interactive RDP
  logon to a host that never transmits reusable/plain-text credentials to that
  host. If the target host is compromised, credentials can't be harvested from
  the initial connection; both the client and the host must support the mode, or
  the connection attempt fails.
- **LSA protection** — the Local Security Authority (running inside the LSASS
  process) validates logons and enforces local security policy; LSA protection
  prevents code injection into LSASS by non-protected processes, hardening the
  process that stores and manages credentials. Configurable on Windows 8.1; on
  and non-configurable on Windows RT 8.1.
- **Protected Users security group** — a domain global group that forces
  additional, non-configurable restrictions on any member: sign-on **only** via
  Kerberos (NTLM, Digest Authentication, and CredSSP are refused, and no password
  is cached — a device using one of those SSPs simply fails to authenticate a
  Protected Users member); Kerberos preauthentication for the account **never**
  uses DES or RC4 (the domain must support at least AES); the account **cannot**
  be Kerberos-delegated (constrained or unconstrained); and its Kerberos TGT
  lifetime is capped at a configurable 4 hours by default (via Authentication
  Policies). **Never add service or computer accounts to Protected Users** — they
  gain no local protection (the password/certificate is always present on the
  host) and instead simply fail to authenticate.
- **Authentication Policies and Authentication Policy Silos** — forest-based AD
  objects (domain functional level 2012 R2+) that constrain *which hosts* an
  account (User, Computer, Managed Service Account, or Group Managed Service
  Account) is allowed to sign in from, enforced during the Kerberos AS/TGS
  exchange; used together with the Protected Users group to isolate related,
  high-value accounts.

## Contradictions / caveats

This page covers **OS/protocol-level** credential-theft mitigations that apply
independent of any specific password-rotation tool. It is deliberately adjacent
to, but distinct from, AD's **Windows LAPS** ([[windows-laps]] /
[[laps-password-encryption]] in the `active-directory` domain), which addresses a
different failure mode — a single shared local-administrator password across a
fleet — by rotating per-machine local admin passwords rather than hardening the
domain-authentication path itself (inferred framing: the source note doesn't
mention LAPS, but both defenses target the same "harvested credential enables
lateral movement" attack chain from complementary angles).
