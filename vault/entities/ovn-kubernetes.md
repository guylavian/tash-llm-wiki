# OVN-Kubernetes

**OVN-Kubernetes is the default network plugin (CNI) for OpenShift Container Platform and single-node OpenShift**, providing a virtualized overlay network for pods and Services by transforming declared network configuration into OpenFlow rules.

## Architecture
- Built on **Open Virtual Network (OVN)**, itself built on **Open vSwitch (OVS)** — every node in the cluster runs OVS, and OVN's per-node controller programs each node's OVS to implement the cluster-wide logical network.
- OVN-Kubernetes runs daemon sets for its distributed databases and for the OVN controller on every node; the controller translates logical flows into `OpenFlow` rules that direct packet routing through the cluster.
- Uses **Geneve** (not VXLAN) as the overlay encapsulation protocol between nodes.

## Capabilities
Beyond plain `OpenFlow`, OVN adds distributed virtual routing, distributed logical switches, DHCP/DNS support, and access control. The OVN controller enables, among others: egress IPs, firewalls (see [[network-policy]]), hardware offloading, hybrid networking, IPsec encryption, IPv6/dual-stack, multicast, and NetworkPolicy enforcement + logging.

## OpenShift specifics vs upstream
- OVN-Kubernetes is an open-source CNCF-adjacent CNI plugin usable on any Kubernetes cluster, but **OpenShift ships it as the default** network provider (replacing the older OpenShift SDN plugin from earlier OCP releases) and documents/operates it as a first-class cluster capability (`{openshift-networking}`).
