# Exchange Database Availability Groups (DAG)

**A DAG is the base building block of Exchange Mailbox-server high availability: a
group of up to 16 Mailbox servers hosting replicated copies of a set of mailbox
databases, with automatic recovery from server/disk/network failure.**

## Body

All servers in a DAG must run the **same Exchange version**
(`exchange-exchange-servertoc-p2601-2640.md:274-282`) — you cannot mix, e.g.,
Exchange 2013 and 2016 in the same DAG. The DAG is a boundary for database
replication and for switchovers/failovers, managed by **Active Manager**, a
component running on every Mailbox server in the DAG. Any DAG member can host a
copy of any other member's database.

Created with `New-DatabaseAvailabilityGroup`, a DAG starts as an empty AD object;
adding the **first** Mailbox server auto-creates a dedicated Windows failover
cluster (used exclusively by the DAG — no other purpose is supported)
(`exchange-exchange-servertoc-p2601-2640.md:300-327`). A DAG can be created **with**
a cluster administrative access point (a name + IP registered in DNS) or, on
Exchange 2013 SP1+ / Windows Server 2012 R2+, **without** one — passing
`([System.Net.IPAddress]::None)` to `-DatabaseAvailabilityGroupIPAddresses` — which
drops the DNS-registered name, the cluster name object (CNO) in AD, and Failover
Cluster Management tool support (PowerShell against individual members only); this
reduces attack surface and is the recommended default absent third-party tooling
that needs the access point
(`exchange-exchange-servertoc-p2601-2640.md:329-410`).

Underneath every DAG is a Windows failover cluster relying on **quorum** — a
majority-consensus mechanism. If the cluster loses quorum, **all DAG operations
terminate and every mounted database in the DAG dismounts**; recovery requires
admin intervention (`exchange-exchange-servertoc-p2601-2640.md:440-454`).

Database copy placement is governed by **activation preference**
(`Add-DatabaseAvailabilityGroupServer`/`Add-MailboxDatabaseCopy` auto-increments it
if unspecified) and mount behavior on failover by
**`AutoDatabaseMountDial`** on `Set-MailboxServer`, e.g.:

```powershell
Set-MailboxServer -Identity EX1 -AutoDatabaseMountDial GoodAvailability
```

`GoodAvailability` (the default) mounts based on the activation preference value
rather than the passive copy's queue length, provided log copying/replay can
reasonably catch up (`exchange-exchange-servertoc-p2681-2720.md:10-34`). Inspect
copy health/status with `Get-MailboxDatabaseCopyStatus`
(`exchange-exchange-servertoc-p2641-2680.md:968`).

## Contradictions / caveats

None observed across the three notes; all describe the same DAG mechanics.
