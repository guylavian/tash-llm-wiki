# Operator Lifecycle Manager (OLM)

**OLM is the OpenShift/Operator-Framework component that installs, upgrades, and grants access to *application* Operators — it runs by default and is a separate control loop from the [[cluster-operators|Cluster Version Operator]] that manages OpenShift's own platform ClusterOperators.**

## Core CRDs
| CRD | Short name | Role |
|---|---|---|
| `ClusterServiceVersion` (CSV) | `csv` | Operator metadata: name/version/icon, required resources, RBAC, install strategy, owned/required CRDs |
| `CatalogSource` | `catsrc` | A repository (backed by an index image) of CSVs/CRDs/packages OLM queries to discover Operators |
| `Subscription` | `sub` | Tracks a channel in a package to keep an installed CSV up to date |
| `InstallPlan` | `ip` | The calculated set of resources to create/update to install or upgrade a CSV |
| `OperatorGroup` | `og` | Multitenant config: which namespace(s) a group of Operators watches |
| `OperatorConditions` | — | Communication channel for an Operator to report complex states back to OLM |

Enabling any of `ClusterServiceVersion`/`CatalogSource`/`Subscription`/`InstallPlan`/`OperatorGroup` APIs requires the `OperatorLifecycleManager` cluster capability; the `marketplace` capability depends on it (can't disable OLM and keep marketplace).

## OperatorGroups and multitenancy
An OperatorGroup selects target namespaces via the `olm.targetNamespaces` annotation projected onto member CSVs. An Operator is a *member* of a group only if its CSV lives in the same namespace **and** its CSV declares an `InstallModeType` (`OwnNamespace` / `SingleNamespace` / `MultiNamespace` / `AllNamespaces`) compatible with that group's target set — the install-mode/target-namespace mismatch is the most common "Operator won't install here" cause.

## Troubleshooting surface
`Subscription` status conditions are the first diagnostic stop: `CatalogSourcesUnhealthy`, `InstallPlanMissing`, `InstallPlanPending`, `InstallPlanFailed`, `ResolutionFailed`. Default OpenShift platform ClusterOperators do **not** have a Subscription object — only OLM-managed application Operators do (see [[cluster-operators]] for the CVO-managed side).

## Upgrades
A Subscription tracks a channel; a new CSV in that channel produces a new `InstallPlan` (automatic or manual approval), which OLM reconciles to upgrade the running Operator — this is the OLM analogue of how the CVO rolls out ClusterOperator upgrades, but scoped to one application Operator instead of the whole control plane.
