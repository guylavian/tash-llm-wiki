# Exchange Recipient Types

**A recipient is any mail-enabled Active Directory object Exchange can deliver or
route messages to; each carries an explicit type surfaced in the EAC and as a
unique `RecipientTypeDetails` value.**

## Body

Per `exchange-exchange-servertoc-p1001-1040.md:988-1069`, explicit typing lets
admins differentiate, search/sort, and bulk-manage recipients, and lets the EAC
render type-appropriate property pages (e.g. resource capacity only shows for room
mailboxes). Notable types:

- **Equipment mailbox** — a resource mailbox for a non-location-specific asset
  (laptop, projector, company car); can be booked as a meeting resource.
- **Linked mailbox** — assigned to a user account in a separate, trusted forest.
- **Mail contact** — an AD contact with an external email address; all mail
  routes externally. No logon credentials.
- **Mail user** — like a mail contact but *does* have AD logon credentials and
  can access resources.
- **Mail forest contact** — represents a recipient from another forest,
  typically MIIS/sync-created and **read-only**: cannot be modified via EAC or
  Exchange Management Shell.
- **Mail-enabled non-universal group** — discontinued since Exchange 2007;
  survives only via migration from Exchange 2003 or earlier. Cannot be created
  in modern Exchange.
- **Mail-enabled public folder** — a public folder configured to receive mail.
- **Distribution group** vs **mail-enabled security group** — the former is
  message-distribution only; the latter is an AD universal security group that
  can *also* be used for both resource access and message distribution.
- **Microsoft Exchange recipient** — a special system sender that replaces the
  old "System Administrator" sender for system-generated messages.

**Delegate permissions** on a mailbox are distinct from recipient type: **Full
Access** lets a delegate open the mailbox; **Send As** lets a delegate send mail
that appears to originate from the mailbox; **Send on Behalf Of** lets a delegate
send *as themselves, on behalf of* the mailbox owner — the recipient sees both
identities (`exchange-exchange-servertoc-p1041-1080.md:529-537`, "Full, Send As
and Send on Behalf" permission trio).

## Contradictions / caveats

None observed; both sources are consistent.
