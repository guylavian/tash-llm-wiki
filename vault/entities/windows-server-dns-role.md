# Windows Server DNS Server role

**DNS is Windows' default name-resolution service and, in an Active Directory
environment, the mechanism clients use to locate domain controllers.**

## Body

DNS is installed as a Windows Server role (Server Manager or PowerShell); when you
create a new AD forest/domain, **DNS is installed automatically alongside it**. AD
DS depends on DNS to store and replicate the zones containing every domain
computer's name and IP address, and domain controllers use DNS to locate each
other. Windows Server DNS can also run **standalone, without Active Directory** —
for example, hosting public lookup zones for an organization.

Every TCP/IP-configured client runs the **DNS Client service**, which on domain
logon queries DNS to (1) locate a domain controller and (2) resolve that
controller's name to an IP address before authentication begins.

**Server features:** Active Directory-integrated zones (secure updates and
replication of DNS data), dynamic updates (automatic client record registration),
**DNSSEC** (data integrity/authenticity, mitigates cache poisoning), forwarding
and conditional forwarding, caching, monitoring/logging, DNS policies
(behavior conditioned on client IP or time of day), and **anycast** (one IP shared
across multiple DNS servers for redundancy/load balancing).

**Deployment scenarios:** AD-integrated (domain-controller location and auth),
public or private lookup zones, hybrid on-premises/cloud DNS, load-balanced/
failover DNS for reliability, and DNSSEC for attack mitigation.

## Contradictions / caveats

This entity covers the **generic Windows Server DNS Server role**; the
AD-DS-specific mechanics of `_msdcs` SRV records, AD-integrated zone replication
scopes, and the DC-locator algorithm are covered in the `active-directory` domain's
own pages ([[dns-infrastructure-design]]) — consult those for AD-specific
troubleshooting rather than duplicating that detail here.
