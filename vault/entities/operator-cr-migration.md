# RH-SSO Operator → RHBK Operator (CR) migration

**The RHBK Operator is a complete rewrite, not backward compatible with the
RH-SSO 7.6 Operator — migration means installing it fresh and authoring new
`Keycloak` CRs.**

## Body
Install the RHBK Operator into the namespace, then hand-author new CRs + Secrets.
The CR uses apiVersion `k8s.keycloak.org/v2alpha1`, kind `Keycloak`. All server
options are **first-class fields** (same naming as `kc.sh`), with `additionalOptions`
for anything missing (e.g. SPI config) and an `unsupported.podTemplate`
(Technology Preview) escape hatch for raw pod-spec fields.

### Key differences from the RH-SSO 7.6 Operator
- **Database:** can reuse the same DB instance (schema auto-migrated on first
  connect — see [[database-auto-migration]]). Configured directly in the CR `db`
  block with `usernameSecret`/`passwordSecret`. Embedded-DB migration unsupported.
  All server-supported DB vendors now work (RH-SSO Operator only did PostgreSQL).
- **TLS:** no assumptions made — you must supply your own `tlsSecret`
  (`kubernetes.io/tls`). Default Route termination changed from **reencrypt** to
  **passthrough**; TLS termination config is not supported (disable the default
  Route via `ingress.enabled: false` and bring your own).
- **Extensions:** specifying extensions in the CR is **removed**; build an
  optimized custom image and reference it via the `image` field (the Operator
  then skips the build-time optimization). See [[custom-provider-migration]].
- **Upgrade strategy:** default is now **recreate** (scales the deployment down
  before rolling new pods, guaranteeing a single server version touches the DB).
  Optional `Auto` and `Explicit` strategies allow rolling updates in some cases —
  still single-version-against-DB only.
- **Health:** health endpoints are enabled by default on the management port
  **9000** (used by OpenShift probes, not exposed as a Route).
- **HPA:** the CR can be scaled directly by a Horizontal Pod Autoscaler; the old
  `disableReplicasSyncing: true` workaround is gone.
- **External instance:** connecting to an external RHBK instance is **no longer
  supported**.

### Realm / Client / User CRs
- `KeycloakRealm` CR → **`KeycloakRealmImport`** CR: bootstraps a full realm
  representation, but offers **no update or delete** (import only).
- **Client and User CRs were removed.** Realm Import can seed (not update/delete)
  most realm resources. Client CR support is planned for a future release; User
  CRs are not planned.

## Contradictions / caveats
- Upstream Keycloak Operator CRs are compatible with the RHBK Operator (only a
  reinstall is needed) — unlike RH-SSO 7.6 CRs, which are not (inferred — not
  stated in the cited migrating-operator chapter, which covers only the RH-SSO
  7.6 → RHBK path). See [[rhsso-to-rhbk-migration]].
- `podTemplate` is Technology Preview — prefer first-class CR fields (e.g.
  `spec.imagePullSecrets` over `spec.unsupported.podTemplate.spec.imagePullSecrets`).
