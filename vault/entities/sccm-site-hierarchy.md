# SCCM Site Hierarchy and Site Systems

**A Configuration Manager deployment is built from one or more sites forming a hierarchy; the
first site installed determines the hierarchy's scope, and each site's functionality is extended
by site system roles hosted on site system servers.**

## Body

The first site you install must be either:

- A **central administration site (CAS)** — suitable for large-scale, geographically distributed
  deployments; provides a central point of administration but does **not** directly manage
  devices. A CAS requires one or more child **primary sites** to actually manage clients.
- A **stand-alone primary site** — suitable for smaller deployments; manages devices directly.
  It can later be expanded: a new CAS can be installed above it, at which point it becomes a
  child-primary site.

A stand-alone primary site and a child-primary site are the same site type (primary); the
difference is only the hierarchy relationship, which also gates which site system roles can be
installed where — some roles are restricted to the top-tier site (a CAS or stand-alone primary).

Below a primary site you can install one or more **secondary sites** to extend management reach
into locations with a slow network link to the primary. The primary site still manages every
client; the secondary site's job is to compress and relay content/state traffic across the WAN.

### Site system roles

Every site installs two roles by default: the **site server** role (the computer you installed
the site on) and the **site database server** role (the SQL Server hosting the site database).
Additional roles (management point, distribution point, software update point, etc.) are
optional and installed only as needed. A site system role always belongs to a single site — a
site system server cannot host roles from two different sites at once.

### Publishing to Active Directory

Extending the AD schema and publishing site data to AD DS is a one-time, per-forest operation
(before or after the first site install) that lets clients securely discover sites, site system
servers, and their services from a trusted source instead of relying only on DNS/WINS discovery
(inferred — framed here as the discovery alternative the source contrasts AD DS publishing
against).
