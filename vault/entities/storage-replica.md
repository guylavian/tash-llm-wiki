# Storage Replica

**Storage Replica replicates volumes between servers or clusters for disaster
recovery, at the block level rather than the file level, with a synchronous mode
that guarantees zero data loss.**

## Body

Two replication modes:
- **Synchronous** — the application's write isn't acknowledged until the remote
  copy also acknowledges it; guarantees zero data loss, but adds network round-trip
  latency to every write (recommend ≤ 5 ms average round-trip).
- **Asynchronous** — the local write is acknowledged immediately and replicated
  in the background; no distance limit, but a failure can lose the still-in-flight
  writes.

Three supported configurations:
- **Stretch cluster replication** — one cluster, nodes split across two sets of
  asymmetric storage, replicating with site awareness; supports automated failover.
- **Cluster-to-cluster replication** — two independent clusters (works with
  [[storage-spaces-direct]]); failover requires manual intervention.
- **Server-to-server replication** — two standalone servers; also manual failover.

Transport is **SMB3** (TCP/IP or RDMA — iWARP, InfiniBand, RoCE v2), over a single
firewall port (TCP 445 or 5445), with **Kerberos AES256** authentication and
AES-128-GCM encryption + preauthentication integrity checking baked in. Management
is via PowerShell, Failover Cluster Manager (stretch clusters), or
[[windows-admin-center]] (server-to-server / cluster-to-cluster).

**Prerequisites:** an AD DS forest; Storage Spaces (SAS JBOD), Storage Spaces
Direct, FC SAN, shared VHDX, iSCSI, or local storage; ≥ 2 GB RAM and 2 cores per
server; log drives faster than data drives, never shared with other workloads.
Windows Server Standard edition limits Storage Replica to a **single volume** of
up to **2 TB**; Datacenter has no such limit.

## Contradictions / caveats

Storage Replica is explicitly **not a backup solution** — a deletion on the source
replicates instantly and irrevocably to the destination — and it is **not**
Hyper-V Replica or SQL Always On (it's a general-purpose, storage-agnostic engine,
so it can't match an application-aware replication technology's tailored
behavior). In Windows Server 2016, the destination volume is fully inaccessible
while replicating (dismounted, not just read-only); `Test-Failover` (from Windows
Server version 1709 onward) can temporarily mount a read-write snapshot for
testing/backup without breaking replication.
