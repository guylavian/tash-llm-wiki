# PowerShell Modules and Manifests

**A script module (`.psm1`) only autoloads if it sits in a folder — on one of the paths listed in
`$env:PSModulePath` — whose name matches the file's base name; every module should also ship
a `.psd1` manifest, or `Get-Module` reports it at version `0.0`.**

## Body

### Loading a module manually vs. autoloading

A function defined in a `.ps1` script file that is merely *run* (`.\Get-MrPSVersion.ps1`) does not
load the function into the session — calling it afterward fails with:

```
Get-MrPSVersion : The term 'Get-MrPSVersion' is not recognized as the name of a cmdlet,
function, script file, or operable program. ...
+ CategoryInfo          : ObjectNotFound: (Get-MrPSVersion:String) [], CommandNotFoundException
+ FullyQualifiedErrorId : CommandNotFoundException
```

(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0201-0240.md:756-791`).
The function must instead live in a `.psm1` script module and be loaded with `Import-Module
C:\MyScriptModule.psm1`
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0201-0240.md:993-1000`).

PowerShell 3+ **module autoloading** removes the need for an explicit `Import-Module` call, but
only if the `.psm1` file is saved inside a folder with the **same base name** as the file, and that
folder is located directly inside one of the paths listed in `$env:PSModulePath` (split on `;` to read
it) — the first three default paths are typically the current-user, AllUsers, and the protected
`C:\Windows\System32` locations
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0201-0240.md:1000-1044`).

### Module manifests

Every module should ship a **module manifest** — a `.psd1` metadata file, created with
`New-ModuleManifest` (the only *required* parameter is `-Path`, but `-RootModule` is also
needed for the module to work correctly; `-Author`/`-Description` are best-practice and required
if publishing to a NuGet/PowerShellGet feed). A module without a manifest reports version `0.0`
from `Get-Module`. Use `Update-ModuleManifest` to add or fix values later — re-running
`New-ModuleManifest` on an existing manifest generates a **new GUID**, which is a mistake to
avoid
(`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0201-0240.md:1054-1096`).

## Contradictions / caveats
None noted — this is uncontested, version-stable PowerShell language behavior.
