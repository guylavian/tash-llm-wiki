# SharePoint Web Applications & Site Collections

**A web application is the IIS-hosted boundary that maps content databases and
authentication zones to a URL space; site collections (and the web sites nested under
them) are provisioned inside it.**

## Body

### Zones

Each web application can have up to **five zones** — logical paths to the same content:
`Default` (created automatically), plus `Intranet`, `Extranet`, `Internet`, and `Custom`,
created by extending the web application
(`install-software-boundaries-limits-2019.md:128`). Zones let the same content be reached
through different authentication methods; when using claims-based authentication
(recommended), multiple authentication providers can be layered on a single zone
instead of needing a separate zone per method
(`security-for-sharepoint-server-plan-user-authentication.md:63-77`).
Only one instance of forms-based authentication is allowed per zone.

Classic-mode web applications can only be created with the `New-SPWebApplication`
PowerShell cmdlet (Central Administration only offers claims-based creation as of
SharePoint 2013); classic mode is deprecated and cannot be migrated back to from
claims (`security-for-sharepoint-server-plan-user-authentication.md:85`) — see [[sharepoint-authentication]].

### Site collections and web sites

Recommended/supported limits per farm (`install-software-boundaries-limits-2019.md:193-209`):

| Object | Supported/recommended limit |
|---|---|
| Site collections per farm | 250,000 (plus up to 500,000 Personal Sites) |
| Web sites per site collection | 250,000 supported; **2,000 recommended** — beyond 2,000, deleting/creating a site can affect availability of siblings, `PSConfig`/upgrade timer jobs slow drastically, and Central Administration's upgrade status page can time out |
| Site collection size | Recommended cap **100 GB** — site collection backup/restore and `Move-SPSite` are only supported up to 100 GB; larger site collections require backing up the whole content database |
| Device channels per publishing site collection | 10 (boundary) |

A farm can reach a large total web-site count safely by spreading it across many
site collections at ≤2,000 web sites each (e.g. 125 site collections × 2,000 = 250,000
web sites) rather than growing one site collection past the recommended limit
(inferred — direct implication of the two limits combined).

## Contradictions / caveats

"Supported" and "recommended" limits are distinct in the source table: e.g. 250,000
web sites per site collection is *supported*, but 2,000 is the *recommended* ceiling
before administrative operations visibly degrade — treat the supported number as a
hard ceiling, not a target.
