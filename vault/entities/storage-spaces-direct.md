# Storage Spaces Direct

**Storage Spaces Direct (S2D) pools the internal drives of 2–16 clustered servers,
over Ethernet, into one software-defined storage pool — no shared SAS or Fibre
Channel fabric required.**

## Body

Under the hood it layers: **Failover Clustering** (connects the servers) → the
**Software Storage Bus** (a software-defined fabric so every server can see every
other server's local drives) → **Storage Bus Layer Cache** (binds fast drives to
slow drives for read/write caching) → the **Storage Pool** → **Storage Spaces**
(mirroring/erasure coding, distributed software RAID) → **ReFS** volumes → **Cluster
Shared Volumes (CSV)** so every volume looks locally mounted on every node.

Two deployment models:
- **Hyperconverged** — one cluster runs both Hyper-V VMs (or SQL Server) and the
  storage that backs them, directly on the local volumes.
- **Converged (disaggregated)** — a separate Scale-Out File Server (SoFS) cluster
  layers on top of S2D and exposes SMB3 shares to a separate compute cluster.

**Hardware minimums:** 2–16 servers, Intel Nehalem-or-later or AMD EPYC-or-later
CPU, 4 GB RAM per TB of cache-drive capacity (plus normal workload RAM),
direct-attached SATA/SAS/NVMe/persistent-memory drives (cache devices ≥ 32 GB), and
a 10+ Gbps NIC minimum (25 Gbps + RDMA — iWARP or RoCE — recommended for 4+ node or
high-performance clusters). Maximum raw capacity is 400 TB per server / 4 PB per
pool on Windows Server 2019+.

**Not supported:** shared SAS enclosures connected to multiple servers, any
multi-path I/O (MPIO) topology, or RAID controllers that don't pass SAS devices
through in simple pass-through mode.

Managed via [[windows-admin-center]], Server Manager + Failover Cluster Manager, or
PowerShell.

## Contradictions / caveats

For disaster recovery, S2D's own guidance steers away from stretching a single
hyperconverged cluster across sites: losing two nodes takes the whole HCI cluster
down, so the supported DR patterns are cluster-to-cluster [[storage-replica]] or
Hyper-V Replica between two independent clusters, not a stretch cluster (extracted
from the disaster-recovery note's summary).
