- [[exchange-online-powershell-cmdlets]] — Connect-ExchangeOnline (mail/admin cmdlets) and Connect-IPPSSession (Security & Compliance / Purview cmdlets) are the two entry points into the Exchange Online PowerShell module; unattended scripts should authenticate with certificate-based (app-only) auth or managed identity rather than a stored credential, and on-premises Exchange gates remote PowerShell per-user via RemotePowerShellEnabled.
- [[grouppolicy-powershell-module]] — The GroupPolicy module scripts GPO creation, linking, and even bulk item-level targeting cleanly — but several everyday GPO tasks (Group Policy Preference printer actions, ADMX multi-value list-boxes, DNS-client Administrative Template values) have no first-class cmdlet, and community answers consistently redirect to the GPMC GUI instead.
- [[powershell-classes]] — The `class` keyword — reserved since PowerShell 5.0 alongside `using` — lets you define real .NET types inline, including static methods that can be converted to a delegate and passed to another method.
- [[powershell-error-handling]] — PowerShell's try/catch/finally only intercepts terminating errors — a cmdlet's default non-terminating error sails past an empty catch block unless the call is run with -ErrorAction Stop.
- [[powershell-execution-policy]] — PowerShell's execution policy controls whether scripts are allowed to run — it is a safety feature against accidental script execution, explicitly not a security boundary, and Microsoft classifies it as a defense-in-depth mitigation that AppLocker/App Control rules take precedence over.
- [[powershell-functions]] — A plain PowerShell function becomes an "advanced function" — gaining common parameters (-Verbose, -Debug, -ErrorAction, …) and optionally -WhatIf/-Confirm — the moment its param block carries [CmdletBinding()]; naming collisions are avoided with a unique Verb-Noun name.
- [[powershell-modules]] — PowerShell modules autoload from folders on $env:PSModulePath whose name matches the .psm1 base name; a missing folder/name match or a missing .psd1 manifest is why a function shows CommandNotFoundException or a module reports version 0.0.
- [[powershell-pipeline-and-objects]] — PowerShell's pipeline passes live .NET objects (not text) between cmdlets; a downstream parameter binds piped input either ByValue (type match, tried first) or ByPropertyName, and "filter left" is the standing performance rule for chaining commands.
- [[powershell-profiles-and-providers]] — $PROFILE exposes four startup-script paths (AllUsersAllHosts/AllUsersCurrentHost/CurrentUserAllHosts/CurrentUserCurrentHost) that customize a session, while PSProviders expose non-filesystem data stores — the registry, certificates, environment variables — as traversable PSDrives.
- [[powershell-remoting]] — PowerShell remoting runs commands on remote computers over two transports — WS-Management (WinRM), the Windows PowerShell 5.1 default, and SSH-based remoting (PowerShell 6+), which uses -HostName/-UserName/-KeyFilePath instead of WinRM to reach non-Windows and mixed-OS targets.
- [[sharepoint-powershell-cmdlets]] — Connect-SPOService (SharePoint Online Management Shell) must run before any other SPO cmdlet, supports one connection per session/geo, and needs -ModernAuth/-AuthenticationUrl (or certificate/managed-identity auth) instead of a bare -Credential for MFA-enabled admin accounts.
