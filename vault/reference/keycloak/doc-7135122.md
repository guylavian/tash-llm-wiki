# Red Hat build of Keycloak fails to start in FIPS mode with "UnsatisfiedLinkError" due to incompatible Bouncy Castle libraries

Red Hat build of Keycloak fails to start in FIPS mode with "UnsatisfiedLinkError" due to incompatible Bouncy Castle libraries
Environment
- Red Hat build of Keycloak
- 26.x
Issue
When attempting to start the Red Hat build of Keycloak (RHBK) in FIPS mode, the server fails to start with a java.lang.UnsatisfiedLinkError.
Error Log Example:
java.lang.RuntimeException: Failed to start quarkus
...
Caused by: java.lang.RuntimeException: Unexpected error when configuring the crypto provider: org.keycloak.crypto.fips.Fips1402StrictCryptoProvider
...
Caused by: java.lang.UnsatisfiedLinkError: /tmp/bc-fips-jni.../libbc-probe.so: failed to map segment from shared object
This issue occurs when the Bouncy Castle (BC) FIPS libraries bundled with the product have been replaced with newer or different versions (e.g., bc-fips 2.1.x) obtained from external sources. The Red Hat build of Keycloak is tested and certified to work only with the specific versions of BC libraries included with the distribution.
Resolution
To resolve this issue, use the Bouncy Castle FIPS libraries that are bundled with the Red Hat build of Keycloak. Do not download or use external versions from the Bouncy Castle website or Maven Central, as they may not be compatible with the product's runtime environment.
Ensure the following versions (which are the default bundled versions for RHBK 26.2.10) are being used:
bc-fips: 2.0.0
bctls-fips: 2.0.19
bcpkix-fips: 2.0.7
bcutil-fips: 2.0.3
If you have manually placed other versions (e.g., 2.1.x) in the library path or classpath, remove them and revert to the versions provided with the product.
