# Is `w32tm /resync /force` a real flag?

**No. `/force` is not a documented parameter of `w32tm /resync`; run `w32tm /config … /update` followed by plain `w32tm /resync` (add `/rediscover` if the peer list or network path changed).**

## Question

> Our runbook says to run `w32tm /resync /force` on the PDC emulator after changing
> the NTP source — is `/force` a real flag, and what should we run instead?

## Answer

**The flag does not exist.** Search evidence, per the query protocol:

- `w32tm` appears **nowhere** in the `reference/active-directory/` corpus (grep over all
  237 notes: 0 hits) — the corpus is MS Learn AD-DS conceptual material and does not
  document the w32tm CLI at all, so the corpus can neither confirm nor deny the flag.
- The web-grounded wiki entity does: the documented `/resync` switches are **only**
  `/computer`, `/nowait`, `/rediscover`, `/soft` — no `/force`
  (`entities/windows-time-service.md:69`, citing web: Microsoft Learn "Windows Time
  Service Tools and Settings", fetched 2026-07-05).

**Why the confusion is plausible** (inferred): a real `/force` switch *does* exist on a
different, commonly-paired AD CLI — `nltest /dsgetdc:<domain> /ws /force`
(`reference/active-directory/ad-ds-advanced-ad-ds-management-using-active-directory-administrative-center-level-200.md:491-492`)
— so runbooks written from memory plausibly graft `/force` onto `w32tm` (inferred).

**What to run instead on the PDC emulator** (the [[fsmo-roles]] PDC emulator is the
domain's authoritative time source — `entities/windows-time-service.md:32,44`):

```
w32tm /config /manualpeerlist:"<your NTP source>" /syncfromflags:manual /reliable:YES /update
w32tm /resync
```

(`entities/windows-time-service.md:65-66`). `/resync` already forces an immediate
resynchronization, discarding accumulated error statistics — the "force" semantics the
runbook wants are the default behavior (`entities/windows-time-service.md:69`). If you
changed the peer list or the network path to it, use `w32tm /resync /rediscover`
(`entities/windows-time-service.md:69`).

**Verify it worked** (`entities/windows-time-service.md:76-81`):

```
w32tm /query /status
w32tm /query /source
w32tm /stripchart /computer:<upstream source>
```
