# How does PowerShell decide which parameter receives piped input?

**PowerShell tries ByValue binding first — matching the piped object's .NET type against a
parameter's declared type — and only falls back to ByPropertyName (matching a property name
on the object to a parameter name) if no parameter's type matches.** (extracted —
`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1270-1273`)

## The two binding modes

`Get-Command -Syntax` (via `Get-Help -Full`) on a cmdlet like `Stop-Service` shows each
parameter's pipeline-input support, e.g. `-InputObject` accepts `True (ByValue)` and `-Name`
accepts `True (ByPropertyName, ByValue)` (extracted —
`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1245-1259`).
When something is piped in:

1. PowerShell first tries **ByValue** binding — it checks whether the piped object's .NET type
   matches a parameter's declared type. A `ServiceController` object piped to `Stop-Service`
   binds to `-InputObject` (declared type `ServiceController[]`); a plain `String` piped in binds
   to `-Name` (declared type `String[]`) instead (extracted —
   `reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1275-1278`).
2. If **no** parameter's type matches the piped object, PowerShell falls back to
   **ByPropertyName** — it looks for a property on the object whose *name* matches a
   parameter's name, and binds that property's *value*. So an arbitrary object that merely has
   a property named `Name` will bind that property to `Stop-Service -Name`, even though the
   object itself isn't a `ServiceController` or a `String` (extracted —
   `reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1278-1281`).

The doc explicitly flags the label as misleading: "the term by value can be misleading. A more
accurate description is by type" (extracted —
`reference/powershell/powershell-powershell-scripting-powershell-7-6-p0121-0160.md:1271-1273`).

## Why this matters for script authors

If a cmdlet you're piping into doesn't behave as expected, checking `Get-Member` on the piped
object's `TypeName` and comparing it against the receiving cmdlet's `-Syntax` output for
`ByValue`/`ByPropertyName` support is the fastest way to see which binding path will actually
fire (inferred — this is the diagnostic workflow implied by combining the `Get-Member` and
`Get-Command -Syntax` techniques the source demonstrates separately, not a single
worked example in the source itself).

## Contradictions / caveats
None — this is a stable, version-independent PowerShell language mechanism, not something
that varies by PowerShell 5.1 vs. 7+.
