# `kubernetes.io/preferred-zone` does not exist

**`kubernetes.io/preferred-zone` is not a real Kubernetes node label** — the corpus contains no reference to it and it appears in no Kubernetes well-known labels specification.

The actual well-known labels for expressing zone/availability-domain topology on nodes are:

- **`topology.kubernetes.io/zone`** — the current, stable label. The kubelet or cloud-controller-manager populates this with the cloud provider's zone information (e.g., `us-east-1c`). Also used on PersistentVolumes by topology-aware provisioners (`reference/openshift/reference-node-labels.md:31`; `reference/openshift/reference-index-3.md:1149-1163`).

- **`failure-domain.beta.kubernetes.io/zone`** — the legacy equivalent, deprecated since Kubernetes v1.17 in favor of `topology.kubernetes.io/zone` (`reference/openshift/reference-index-3.md:1052-1058`).

If you encountered `kubernetes.io/preferred-zone`, it is likely a misspelling or hallucination. The `topology.kubernetes.io/zone` label is the correct key used in node affinity rules, pod topology spread constraints, and topology-aware routing.
