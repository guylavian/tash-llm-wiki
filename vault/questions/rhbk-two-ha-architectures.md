# What are the two documented RHBK HA architectures?

RHBK ships two documented HA shapes (topics/rhbk-ha-architectures.md:26-29):

1. **Single-cluster** — multiple RHBK pods in one OpenShift cluster behind a shared external database, using **embedded Infinispan** for pod-to-pod clustering (topics/rhbk-ha-architectures.md:33-48). Can span up to three availability zones within one region. Survives pod/node loss with < 30 s recovery and no data loss, but does NOT survive a whole-cluster failure or region outage.

2. **Multi-cluster (multi-site)** — two independent RHBK deployments in separate OpenShift clusters/sites in an **Active/Passive** topology, connected via a synchronously replicated database and an **external Red Hat Data Grid** with Cross-DC replication (topics/rhbk-ha-architectures.md:50-64). Fronted by a load balancer (e.g. AWS Global Accelerator) with `/lb-check` health probes. RPO: no data loss; RTO: < 2 min site failover, up to 5 min for some scenarios.

The dividing line between the two architectures is the cache layer (topics/rhbk-ha-architectures.md:66-73): single-cluster uses **embedded Infinispan** inside each RHBK pod, while multi-cluster uses an **external Data Grid** with RHBK connecting via remote-store and the two Data Grid clusters replicating cross-site.

The Red Hat HA guide deliberately **prioritizes consistency over availability** — Active/Active is *not* the documented supported model (topics/rhbk-ha-architectures.md:93-95). Naming shifted from "multi-site" (26.0/26.2) to "multi-cluster" (26.4/26.6) but the underlying model is unchanged.
